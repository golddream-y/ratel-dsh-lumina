# 水滴转场掉帧：定位瓶颈与取舍

日期：2026-10-22。用户在真实客户端确认转场已触发，但帧率严重下降。

## 瓶颈定位

1. **goo 滤镜作用在整组文字上**：`ink` 容器同时装着最多 240 个文字节点和液体 SVG，`ink.style.filter = url(#goo)` 让浏览器每帧把整组文字重新栅格化再跑一次 `feGaussianBlur` + `feColorMatrix`。
2. **滤镜区域铺满视口**：即使滤镜挂在 SVG 元素上，滤镜缓冲按元素包围盒计算，而液体 SVG 是 `width/height: 100%`，等于每帧做一次全屏级滤镜。
3. **每帧重写全部节点样式**：源文字在 250ms 后已经透明，却仍在每帧写 transform / color / opacity；落点文字归位后也没有停止写入。
4. **每帧重建液面路径**：液面采样 25 个点，路径字符串与 `stdDeviation` 每帧重建，滤镜被迫重算。

## 修改

- 滤镜改为挂在**液体形状 `<g>`** 上（`filter` 属性），滤镜区域=水滴包围盒，不再是整屏；文字节点完全不过滤镜；
- 源文字在汇聚完成后一次性置为透明，之后不再写样式；
- 落点文字到达最终位置后逐个停止写样式；
- `stdDeviation` 量化为 0.25 步进，仅在变化时写入；
- 液面采样点 25 → 13；
- 新增**帧预算守卫**：连续 3 帧超过 38ms 自动摘掉滤镜（`data-lumina-transfer-quality="reduced"` + 一次 warn），保留形状动画，优先不卡帧。

## 取舍

文字与液体的"融化"不再依赖滤镜把字形轮廓融进液滴，改为**颜色渐变 + 缩放 + 淡出**与液滴同步过渡；液体自身的液面/细颈/水滴连续性仍由组内滤镜保证。这是为了帧率做的视觉让步，需要用户确认可接受。

## 验证

类型检查、构建、37 项单元测试通过。真实帧率仍需在客户端实测（需求 A10：60fps、无 >50ms 主线程长任务）；受控预览的帧率不能作为验收依据。

## 未做

未引入 `OffscreenCanvas`、CSS 滤镜替代或预渲染方案，也未降低逐字汇聚与还原的可见差异。若组内滤镜仍然超预算，下一步是把液面/细颈改成单条贝塞尔路径并完全移除 SVG 滤镜。
