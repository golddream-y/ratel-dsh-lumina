# 消解不丝滑与气泡先闪

日期：2026-10-22。客户端反馈：消解效果生硬不丝滑；并且和水滴一样，气泡文字先出现、消失之后动画才开始。

## 消解的生硬来自三处叠加

1. **每字淡出 + 整层模糊**同时作用，文字先糊再消失，读起来是"被擦掉"而不是"散开"；
2. 收尾用 `if (t >= 760) 把所有源字 opacity 置 0`，长文本里还没散完的字被**一刀切掉**，是一个硬跳变；
3. 目标端同时做"每字 opacity 0→1"和"整层模糊解析"，模糊一散开，字就"啪"地跳出来。

改法：

- 全部曲线换成 **smootherstep**（首尾一阶、二阶导都为 0），没有起步/收尾的顿挫；
- 源端每个字**各自走完自己的曲线**到 0，全局置零只作为兜底（此时已经是 0，不再跳变）；
- 源端模糊从 7px 降到 5px、漂移 34→30px、缩放 0.72→0.78，幅度收敛但过程更长；
- 目标端**不再逐字淡入**：整层 opacity 0→1 配 10px→0 的模糊解析（Blur Text 的做法），每字只做 8px 的错峰上浮，落位感来自模糊散开而不是逐字弹出。

## 气泡先出现

根因是**时序**：动画在"提交确认"之后才启动，而宿主在提交被接受时就已经把本地回声画出来了 —— 中间那几十到一百多毫秒里，回声是可见的。

改法：在**捕获手势**时就开始观察会话区，一旦出现新的本地回声（`[data-submission-echo]`，排除队列面板里的同属性行），立刻用 `data-lumina-transfer-pending` 把它隐藏；确认之后转场自己接管遮罩，转场结束（或被取消、超时）时统一解除这个临时遮罩。这样气泡在动画开始前就已经不在画面里。

## 验证

类型检查、构建、41 项单元测试通过；新增用例覆盖"提交确认前本地回声即被隐藏"。

实机仍需完整退出重启后确认：气泡不再闪现；消解的散开与解析是否够柔和。
