# 补齐液滴融入边缘并从液面重新剥离

日期：2026-10-22。用户指出上一版水滴既没有融入边缘，也没有从液面剥离，且不应使用红色水滴。

## Decision

原方案把文字汇聚点当作剥离锚点，跳过了输入框液面；品牌红又被直接用于水体。这两处均不符合用户目标。

汇聚点与输入框上边缘锚点分离。首滴抵达上边缘后通过接触桥融入局部液面，450–510ms 独立水滴半径为零；同一液面随后重新鼓起，拉出细颈，颈部变细后在 710ms 前断开，再沿弧线飞行。液面两端收尖，残留在断开后回收。标准时长 1150ms，柔和 1350ms、鲜明 1000ms；活动装饰硬上限 2.1 秒。

用户明确拒绝红色水体，因此本效果采用独立 --lumina-water-* token，来自客户端冷色语义与白色高光，缺失时用已有蓝色预设。这是对通用品牌同步规则的用户授权例外。透明度、渐变、高光近似水感，不声称真实背景折射。

## Alternatives considered

- 仅将旧水滴换为蓝色：不能补齐液面融合和剥离，拒绝。
- 独立水滴直接穿过边框：缺少完全吸收的间隔，拒绝。
- 让输入框背景整体拉伸：影响宿主内容和布局，拒绝。
- 整页截图、背景像素采样或真实折射渲染：增加隐私、性能及兼容负担，采用临时局部 SVG 轮廓、透明度和高光。

## Validation

类型检查、构建、33 项测试通过。新增物理连续性断言：接触时滴体覆盖边缘、完全吸收时半径为零但液面仍在、同一边缘向外鼓起并保持颈部连接、随后断颈。

受控浏览器加载实际 lib/client.js，连续采样得到 edge-approach / edge-merge / edge-rest / emerge / detach，且默认红色品牌下水体蓝通道高于红通道。原异常清理场景继续通过，无残留遮罩或副本。证据在任务可视化目录 send-transfer-edge 中，包括 evidence.json、完整连续帧和局部慢放。

真实客户端视觉与性能仍需完整退出重启后验收。受控动画预览不作为真实客户端录屏。
