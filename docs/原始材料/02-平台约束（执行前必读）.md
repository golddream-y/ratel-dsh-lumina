# 02 · 平台约束（执行前必读）

本文件里的每条结论都经过实测，**不是推测**。实施方不需要重复验证，但必须遵守。

违反其中任何一条，结果通常是"插件静默不工作"而不是报错——所以这份文档要放在手边。

---

## 2.1 Slot 系统是唯一的官方扩展点

客户端有 **89 个已声明 slot**、91 个渲染点。slot 分四种 kind：

| kind | 语义 | 占据方式 |
| --- | --- | --- |
| `single` | 只取一个占据者，`priority` 最小者胜 | `register({name, priority})`，冲突时抛异常 |
| `list` | 多个占据者并存，按 `order` 排序 | 带 `id` 注册 |
| `keyed` | 按 key 认领 | 带 `key` 注册 |
| `chain` | 链式包裹，可接管整块渲染 | `select` + 包装 |

### 注册契约

```js
ctx.slots.inject("sidebar.brand.mark", () => {
  let release;
  try {
    release = ctx.slots.register(
      { name: "sidebar.brand.mark", priority: -20 },
      BrandMark,          // React 组件
    );
  } catch (error) {
    // slot 已被他人占据时会抛异常，必须兜住
    console.warn("[dsh-lumina] cannot occupy slot", error);
  }
  return () => { release?.(); };   // 卸载必须 release，否则 HMR 残留
});
```

- `ctx.slots.inject(slot, fn)` 是**声明感知**的：插件无论先于还是后于 slot 声明方激活都能工作。
- 非 list slot 的排序是 `priority` **升序**，取第一个 = `priority` 最小者胜。
- **同优先级 = 后注册者胜**（实测：同样 `-10` 时后注册的插件顶掉了先注册的）。
- `dsh-brand-studio` 占用品牌 slot 时用 `priority: -10`。Lumina 用 `-20` 以稳定胜出。

### 本方案用到的 slot

| Slot | kind | scope | 用途 |
| --- | --- | --- | --- |
| `sidebar.brand.mark` | single | root | 左上角鲸鱼图标 |
| `sidebar.brand.name` | single | root | 字标 + 徽标 |
| `conversation.hero.brand.mark` | single | root | 新会话首屏图标 |
| `conversation.input.overlay` | list | session | 输入框浮层锚点 |
| `conversation.input.right` / `.left` / `.dock` | list | session | 输入区扩展位 |
| `conversation.composer` | chain | session | 整个输入区（可包裹） |
| `settings.section` | list | root | 我们的控制面板 |
| `shell.overlay` | list | root | 全局浮层 |

## 2.2 有 369 个稳定的 `data-*` 语义钩子

客户端用 `data-*` 而非 class 做语义标记。这是 Tier 2 的落点。

| 钩子 | 指向 |
| --- | --- |
| `[data-composer-card]` | 输入框那个带边框的卡片容器 |
| `[data-composer-input]` | 可编辑正文（contenteditable / Lexical） |
| `[data-composer-overlay]` | 浮层锚点，CSS 为 `height:0; position:absolute; inset:0 0 auto` |
| `[data-composer-seat]` / `[data-composer-dock]` / `[data-composer-chip]` | 座位 / 底座 / 胶囊 |
| `[data-lexical-cursor]` | **打字机光标** |
| `[data-streaming]` | 流式输出状态 |
| `[data-chat-motion]` / `[data-chat-running]` / `[data-chat-turn]` | 消息区动效状态 |
| `[data-ds-theme]` / `[data-ds-dark-theme]` / `[data-ds-theme-source]` | 主题 |
| `[data-dsh-boot]` | 启动态 |

> 这些钩子随版本可能增删。**每次 DSH 升级后跑一次钩子存在性检查**（见 §2.9）。

## 2.3 CSS-Module 类名是 hash 的，禁止依赖

实际类名形如：

```
_3WPZCG_brandName
yhfFVG_overlayAnchor
InputBar_module_css_default.primary
```

**每次构建都会变。** 任何靠这些类名定位的样式都会在升级后失效，且失效方式是"静默不生效"——很难发现。

### 强制规则

- ❌ `._3WPZCG_brandName { ... }`
- ❌ `[class*="brandName"] { ... }`
- ✅ `[data-composer-card] { ... }`
- ✅ `ctx.slots.register(...)` 占 slot

---

## 2.4 主应用无 CSP 限制，样式注入可行

实测主应用响应头**没有** `Content-Security-Policy`，且 `dsh-brand-studio` 已通过 `document.createElement("style")` 注入样式并生效。

→ Tier 2 的 CSS 注入路线成立：

```js
const tag = document.createElement("style");
tag.dataset.plugin = "dsh-lumina";
tag.textContent = css;
document.head.append(tag);
```

注意：`renderer/welcome.html`（独立欢迎页）**有**严格 CSP，但不在本方案范围。

---

## 2.5 `app.asar` 不可改

`Resources/app.asar` 被 `_CodeSignature/CodeResources` 逐字节封印。实测：

```
recorded hash2: b9ec4c2b...b066
actual sha256 : b9ec4c2b...b066   ← 完全一致
```

改一个字节即破签，macOS 拒绝启动。**所有实现必须在插件层完成。**

（也意味着：不能靠替换官方 `welcome-brand.svg` 来做品牌动效。）

---

## 2.6 打字机光标与流式状态都有钩子

正文用 Lexical 编辑器，光标带 `data-lexical-cursor`；流式输出时消息区带 `data-streaming`。

→ 光标动画可以**纯 CSS** 实现，不需要碰 React 组件。

⚠️ 但光标可能是**伪元素**而非独立元素。实施前必须先测量真实 DOM（见 [04c](04c-动效-打字机光标.md) 的探测脚本）。

---

## 2.7 发送按钮没有稳定钩子

它是输入栏 trailing 区的 `button.primary`，其中：

- `.primary` 是 hash 类名，不可用
- `aria-label` 是**本地化文案**（中文"发送消息"，英文另一套），跨语言会变
- **没有 `data-*` 标记**

→ 因此不能精确定位发送按钮。方案改为**给输入区所有按钮统一按压反馈**（范围化），见 [04d](04d-动效-按钮按压与首屏入场.md)。

## 2.8 插件装载：四个静默失败点

这四条任一不满足，插件**不加载且基本无报错**。按顺序检查。

### ① 必须有 `dsh.bundle.patch`

```json
"dsh": {
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": { "platform": "web", "inject": [...] }
}
```

缺失时 CLI 只警告一句，插件被当普通依赖，**不进 profile layer**：

```
dsh: warning: dsh-lumina declares no dsh.bundle — installed as a plain dependency, not a profile layer
```

### ② patch id 必须与 `lib/index.js` 的 `name` 导出一致

`cordis.patch.yml`：

```yaml
- insert:
    - id: ui-lumina
      name: dsh-lumina
```

`lib/index.js`：

```js
const name = "ui-lumina";
function apply(_ctx) {}
export { apply, name };
```

### ③ `lib/client.js` 的工厂必须 `return module.exports`

**最容易踩的坑。** 返回 `module` 会导致模块永不物化、`apply` 静默不执行、**零报错**。

```js
window.__ModuleLoader__.load({
  id: "dsh-lumina",
  factory: (require) => {
    var module = { exports: {} };
    var exports = module.exports;
    Object.defineProperty(exports, Symbol.toStringTag, { value: "Module" });
    // ...
    exports.apply = apply;
    exports.inject = ["slots"];
    return module.exports;   // ← 必须是 module.exports
  }
});
```

### ④ `inject` 只能列真实存在的包名

`@deepseek-ai/dsh-client-ui-slots` **不存在**（slot 服务由核心上下文提供，不是一个包）。

参考官方 `@deepseek-ai/dsh-client-ui-brand-official`：

```json
"inject": ["@deepseek-ai/dsh-client-ui-renderer", "@deepseek-ai/dsh-client-ui-sidebar"]
```

注意 `exports.inject = ["slots"]`（模块内声明的逻辑依赖）与 `package.json` 的 `dsh.client.inject`（包名）是两回事。

## 2.9 安装、重装、重启

```sh
DSH="/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"

# 安装（必须绝对路径）
"$DSH" plugin --profile web add "file:/绝对路径/dsh-lumina"
```

- **必须绝对路径**。相对路径会被拼成 profile 目录下的相对路径而失败：
  `[ERR_PNPM_LINKED_PKG_DIR_NOT_FOUND] Could not install from ".../x/x" as it does not exist.`
- 安装后 CLI 自动把包名追加进 `~/.dsh/profiles/web/package.json` 的 `dsh.profile.bundles`。
- **改源码后必须强制重装**，否则 pnpm 用旧缓存（改了代码却看不到变化，极难排查）：

```sh
"$DSH" plugin --profile web remove dsh-lumina
rm -rf ~/.dsh/profiles/web/node_modules/dsh-lumina
"$DSH" plugin --profile web add "file:/绝对路径/dsh-lumina"
```

- **改完必须重启客户端**：web 重启 `dsh web` 服务；桌面端完全退出重开。客户端只按启动时的 manifest 装载插件，不支持热更新。

## 2.10 验证手段（推荐用 CDP 断言，不靠肉眼）

用 Chrome DevTools Protocol 连上客户端，`Runtime.evaluate` 断言。关键几条：

```js
// 1. 插件是否进了启动清单
JSON.parse(JSON.stringify(window.__DSH_BOOT__.entries.map(e => e.id))).includes('dsh-lumina')

// 2. 品牌槽里是内联 SVG 还是 img
!!document.querySelector('[class*="brandMark"] svg')   // 或按 slot 容器判断

// 3. 动画是否真的在跑（采样两次看 transform 是否变化）
getComputedStyle(document.querySelector('.lumina-shine')).transform

// 4. 减少动态是否生效
matchMedia('(prefers-reduced-motion: reduce)').matches
```

注意：**截图有绘制时序问题**，`Page.captureScreenshot` 可能早于图片绘制完成。断言 DOM 与 `getComputedStyle` 比截图可靠。
