# 04c · 动效规格：打字机光标（P1）

| 项 | 值 |
| --- | --- |
| 效果名 | `lumina.caret` |
| Tier | 2（CSS on data-*） |
| 稳定性 | ★★★☆ |
| 阶段 | P1 |
| 可并行 | 是 |
| 依赖钩子 | `[data-lexical-cursor]`、`[data-streaming]` |

---

## 1. 视觉目标

原来光标是生硬的开/关闪烁。改成：

| 状态 | 表现 |
| --- | --- |
| 空闲 | 1.15s 呼吸（透明度 0.35 ↔ 1），柔和 |
| 流式输出中 | 0.72s，更快；颜色偏品牌红渐变 |

**注意**：光标是辅助定位元素，动效不能降低它的可见性——透明度最低值不低于 0.35，且减少动态时必须完全不闪、保持常亮。

## 1.1 参考组件与许可

准确组件名是 **`TextType`**（不是 `Typewriter`——那个名字不存在）。它是 React 状态机 + GSAP 时间线 + CSS 光标，props 含 `typingSpeed` / `deletingSpeed` / `loop` / `cursorStyle` / `mistakes` / `typeEffect`。
另有 `DecryptedText`（乱码逐位解密）。

**我们只借鉴"光标呼吸"这一视觉意图**，实现是两条 CSS keyframes 挂在 `[data-lexical-cursor]` 上，**没有**引入其状态机、GSAP 或打字逻辑。

许可约束见 [改编与许可政策](../../THIRD_PARTY_NOTICES.md)。

---

## 2. 先做这一步：测量真实 DOM（不可跳过）

光标可能是**独立元素**，也可能是**伪元素**（`::after` / `::before`）。两种情况的 CSS 写法完全不同，写错了就是"毫无效果且无报错"。

### 探测脚本

在客户端 Console 执行：

```js
// 1. 有没有真实元素？
const el = document.querySelector('[data-lexical-cursor]');
console.log('element:', el, el && el.tagName, el && getComputedStyle(el).position);

// 2. 若没有元素，找伪元素
const input = document.querySelector('[data-composer-input]');
if (input) {
  for (const p of ['::after', '::before']) {
    const cs = getComputedStyle(input, p);
    console.log(p, cs.content, cs.backgroundColor, cs.animationName, cs.width);
  }
}

// 3. 检查是否有现成动画（可能官方已经在做）
if (el) {
  const cs = getComputedStyle(el);
  console.log('existing anim:', cs.animationName, cs.animationDuration);
}
```

根据结果走 §3.1 或 §3.2。

## 3. 实现

### 3.1 情况 A：光标是独立元素（预期）

```css
[data-lexical-cursor] {
  animation: lumina-caret-breathe 1.15s ease-in-out infinite;
  border-radius: 1px;
}

@keyframes lumina-caret-breathe {
  0%, 100% { opacity: .35; }
  50%      { opacity: 1; }
}

/* 流式输出中：更快 + 品牌色渐变 */
[data-streaming] [data-lexical-cursor] {
  animation-duration: .72s;
  background-image: linear-gradient(180deg, var(--lumina-brand-soft), var(--lumina-brand));
}

@media (prefers-reduced-motion: reduce) {
  [data-lexical-cursor] {
    animation: none;
    opacity: 1;
    background-image: none;
  }
}
```

### 3.2 情况 B：光标是伪元素

若探测发现是 `[data-composer-input]::after`，则改作用域：

```css
[data-composer-input]:focus::after {
  animation: lumina-caret-breathe 1.15s ease-in-out infinite;
}
```

⚠️ 伪元素通常**不能**安全地改 `background-image` 而不影响官方绘制（它可能就是靠 border/background 画的）。这种情况只做透明度呼吸，不改颜色。

### 3.3 情况 C：官方已有动画

若 `animationName` 非 `none`，说明官方光标自带动画。此时：

- **优先级方案**：用 `animation` 简写覆盖官方（需要更高特异性）
- **保守方案**：不覆盖，只调 `animation-duration`：

```css
[data-lexical-cursor] { animation-duration: 1.15s; }
```

保守方案更安全，**建议优先采用**。是否覆盖官方动画需视觉确认后再定。

## 4. 硬约束

| 约束 | 说明 |
| --- | --- |
| **不改排版** | 不能改 `width` / `height` / `position` / `margin`。光标宽度变化会导致文字跳动。只动 `opacity` 与 `background-image` |
| **z-index 不压选区** | 光标层级高于选区是正常的，但不能挡住选区高亮的可见性 |
| **可见性下限** | 最低透明度 0.35，不能做"闪到消失"的效果 |
| **减少动态** | 完全不闪，保持常亮 `opacity: 1` |
| **闪烁频率** | 1.15s 周期 = 0.87Hz，安全（3–50Hz 才是光敏风险区） |

## 5. 参数化

| 强度 | 空闲周期 | 流式周期 |
| --- | --- | --- |
| subtle | 1.6s | 1.0s |
| normal | 1.15s | 0.72s |
| vivid | 0.85s | 0.55s |

## 6. 验收标准

- [ ] 空闲时能观测到透明度随时间变化（两次采样 `opacity` 不同）
- [ ] 流式输出时（`[data-streaming]` 存在）动画时长变短（`getComputedStyle` 断言）
- [ ] 光标**位置与宽度**与未装插件时完全一致（像素级对比截图）
- [ ] 文字输入时光标不抖动、不遮挡字符
- [ ] 选区高亮仍然清晰可见
- [ ] 减少动态下 `animation-name` 为 `none` 且 `opacity` 为 1
- [ ] 多行输入、粘贴大段文本时光标仍跟随正常

## 7. 未确定项

- `[data-streaming]` 挂在哪个层级？消息区、会话区还是输入区？需实测确认选择器链，否则 `[data-streaming] [data-lexical-cursor]` 可能永远不匹配。
- 流式输出时用户仍可在输入框打字，此时光标应属"输入中"还是"流式中"？需产品定夺（建议：以输入框焦点为准，流式只影响消息区）。
