# 04b · 动效规格：输入框边缘流光（P1）

| 项 | 值 |
| --- | --- |
| 效果名 | `lumina.composer` |
| Tier | 2（CSS on data-*） |
| 稳定性 | ★★★★ |
| 阶段 | P1 |
| 可并行 | 是（与 04a/04c/04d 无依赖） |
| 依赖钩子 | `[data-composer-card]` |

---

## 1. 视觉目标

输入框那圈边框上有一道光在缓慢环绕。三档状态：

| 状态 | 表现 |
| --- | --- |
| 空闲 | 6.0s 转一圈，不透明度 0.75，安静 |
| 聚焦（`:focus-within`） | 2.4s 转一圈，不透明度 1，明显加快 |
| 流式输出中 | 1.6s 转一圈，可再加一点脉动 |

光带颜色沿**当前品牌预设**：`transparent → var(--lumina-brand) → var(--lumina-brand-soft) → transparent`，占周长约 30%，其余透明——这样看起来是"一束光在跑"而不是"整圈都亮"。

⚠️ **不得硬编码色值**。切到 Ratel 预设时这里是蓝的，DeepSeek 预设时是红的（变量定义见 [04 §4.4](04-动效规格总览.md)）。

## 2. 落点与选择器

唯一钩子：`[data-composer-card]`（输入框带边框的卡片容器）。

**不用** hash 类名（如 `_xxx_card`），见 [02 §2.3](02-平台约束（执行前必读）.md)。

## 3. 实现（纯 CSS，无 JS）

```css
/* 用 @property 注册角度，才能平滑插值；不支持时见 §4 降级 */
@property --lumina-angle {
  syntax: '<angle>';
  initial-value: 0deg;
  inherits: false;
}

[data-composer-card] {
  position: relative;   /* 装饰层定位基准 */
}

[data-composer-card]::before {
  content: "";
  position: absolute;
  inset: -1.5px;
  border-radius: inherit;
  padding: 1.5px;

  background: conic-gradient(
    from var(--lumina-angle),
    transparent 0deg,
    var(--lumina-brand) 40deg,
    var(--lumina-brand-soft) 70deg,
    transparent 110deg,
    transparent 360deg
  );

  /* 只保留边框那一圈，中间挖空 */
  -webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0);
  -webkit-mask-composite: xor;
          mask-composite: exclude;

  animation: lumina-border-spin 6s linear infinite;
  opacity: .75;
  pointer-events: none;   /* 硬性要求：不挡交互 */
}

@keyframes lumina-border-spin {
  to { --lumina-angle: 360deg; }
}

/* 聚焦加速 */
[data-composer-card]:focus-within::before {
  animation-duration: 2.4s;
  opacity: 1;
}

/* 流式输出：由插件或状态钩子驱动 */
[data-composer-card][data-lumina-streaming]::before {
  animation-duration: 1.6s;
}

/* 减少动态：完全关闭 */
@media (prefers-reduced-motion: reduce) {
  [data-composer-card]::before { animation: none; opacity: .5; }
}

/* 紧急降级 */
[data-lumina="off"] [data-composer-card]::before { animation: none; }
```

## 3.1 参考组件与许可

reactbits 免费站里最接近的是：

- `BorderGlow` —— CSS mask + 多层渐变，`--edge-proximity` / `--cursor-angle` 由指针驱动
- `StarBorder` —— Canvas 2D，星点沿精确轮廓跑
- `ElectricBorder` —— Canvas 2D 电弧

**我们未使用其源码。** 本效果用 `conic-gradient` + `@property` 角度插值 + `mask-composite` 自行实现，光是**被动环绕**而非指针驱动，机制与 `BorderGlow` 不同；也没有采用 Canvas 路线。

> 注意：组件真名是 `BorderGlow`，不是 `Glowing Border`——早期文档写错过，派活时别搜错名字。

许可约束见 [05 §5.4](05-reactbits对照与许可.md)。

## 4. 兼容性降级

`@property` 在 Chrome 105+ / Safari 16.4+ 可用；不支持时 `--lumina-angle` 无法插值，动画会变成"跳变"或完全不动。

降级方案（检测到不支持时改用旋转包裹层）：

```js
const supportsAtProperty = CSS.supports('at-rule(@property)')
  || (typeof CSS.registerProperty === 'function');
```

不支持时改为注入这套：

```css
[data-composer-card]::before {
  background: conic-gradient(var(--lumina-brand) 0deg, var(--lumina-brand-soft) 30deg, transparent 70deg, transparent 360deg);
  animation: lumina-border-rotate 6s linear infinite;
}
@keyframes lumina-border-rotate { to { rotate: 360deg; } }
```

> 旋转整圈会让光带绕中心公转而非沿边框流动，视觉稍差但可用。**优先保证"有光"，其次才是"光沿边流动"。**

## 5. 必须保护的东西（这是本效果最大的风险）

边框装饰层是叠在真实输入框上的，最容易出事。

| 风险 | 对策 |
| --- | --- |
| 挡住输入框点击 / 聚焦 | `pointer-events: none`（已写）；额外加验收项：点四角任意位置都能聚焦 |
| 遮住光标或选区 | 装饰层只画 1.5px 边框，`mask` 挖空中心；验收时检查选区高亮可见 |
| 破坏原有圆角 | `border-radius: inherit`，不写死像素 |
| 多行增高时错位 | 用 `inset: -1.5px` 跟随容器，不写死高度 |
| 拖拽文件进输入框被拦截 | `pointer-events: none` 已覆盖；需实测拖拽高亮是否正常 |
| 与官方 focus ring 叠加难看 | 保留官方 ring，只在 `::before` 加光；若叠加丑陋，改用 `inset: -2px` 并把官方 ring 一并纳入视觉 |

## 6. 参数化

```js
// 强度映射（见 03 §3.8）
// 6.0s 基准 / K，K = 0.6(subtle) | 1.0(normal) | 1.4(vivid)
```

注入时把时长替换进 CSS 字符串：

```js
var css = TEMPLATE
  .replace(/__SPIN_IDLE__/g, (6.0 / K).toFixed(2) + 's')
  .replace(/__SPIN_FOCUS__/g, (2.4 / K).toFixed(2) + 's')
  .replace(/__SPIN_STREAM__/g, (1.6 / K).toFixed(2) + 's');
```

## 7. 验收标准

- [ ] 输入框出现一圈可见光，且在动（两帧截图边框区域差异非零）
- [ ] **不遮挡**文字、光标、选区高亮、附件预览
- [ ] 鼠标穿透装饰层：点输入框四角与中心都能聚焦
- [ ] 聚焦后 `animation-duration` 变小（用 `getComputedStyle` 断言）
- [ ] 输入框原有圆角、边框粗细视觉未被破坏（对比开关前后截图）
- [ ] 多行文本增高、拖拽文件入框、粘贴长文本时装饰层跟随且无抖动
- [ ] 空输入框 / 有内容 / 禁用态三种情况都不出现视觉异常
- [ ] 减少动态下 `animation-name` 为 `none`
- [ ] Performance 采样：该动画不引起持续 >16ms 长任务

## 8. 未确定项

- 输入框在某些状态下（如审批卡片占位 `conversation.composer` chain 切换）可能没有 `[data-composer-card]`，需实测确认失效时是否静默。
- `:focus-within` 是否会被内部 popup（命令面板）持续满足，导致长期加速。需实测。
