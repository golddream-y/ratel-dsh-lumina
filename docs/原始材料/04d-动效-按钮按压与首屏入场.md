# 04d · 动效规格：按钮按压 + 新会话首屏入场（P2）

| 项 | 值 |
| --- | --- |
| 效果名 | `lumina.press` / `lumina.hero` |
| Tier | 2（按压，CSS） + 1（首屏，slot） |
| 稳定性 | ★★★（按压） / ★★★★★（首屏） |
| 阶段 | P2 |
| 可并行 | 是 |

本文件包含三件事：

1. **按钮按压反馈**（含发送按钮的替代方案）
2. **发送确认闪光**
3. **新会话首屏入场**（用来替代"新会话按钮点击动画"）

---

## 1. 按钮按压反馈

### 1.1 为什么不做"精确定位发送按钮"

发送按钮的真实情况（[02 §2.7](02-平台约束（执行前必读）.md)）：

- 是输入栏 trailing 区的 `button.primary`
- `.primary` 是 hash 类名，**每次构建都变**
- `aria-label` 是**本地化文案**（中文"发送消息"/ 英文另一套），跨语言失效
- **没有 `data-*` 标记**

→ 精确定位必然脆弱。

### 1.2 方案：范围化

给输入区内**所有**按钮统一的按压手感。发送按钮自然被覆盖，同时模型选择、附件、权限等按钮也获得一致反馈——而且完全不依赖"知道哪个是发送按钮"。

```css
[data-composer-card] button:not([disabled]) {
  transition:
    transform 140ms cubic-bezier(.34,1.56,.64,1),
    filter 140ms ease;
}

[data-composer-card] button:not([disabled]):active {
  transform: scale(.92);
  filter: brightness(1.15);
}

@media (prefers-reduced-motion: reduce) {
  [data-composer-card] button:not([disabled]) { transition: none; }
  [data-composer-card] button:not([disabled]):active { transform: none; }
}
```

侧栏按钮同理（新会话、设置等）：

```css
[data-lumina="on"] sidebar button:not([disabled]):active,
[data-lumina="on"] [class*="sidebar"] button:not([disabled]):active {
  transform: scale(.94);
  transition: transform 120ms cubic-bezier(.34,1.56,.64,1);
}
```

> ⚠️ 侧栏这条用了 `[class*="sidebar"]`，属于**弱选择器**。它只是"有则更好"，命中不到不影响任何功能。归入 Tier 2 的尽力而为部分。

### 1.2.1 与 reactbits 的关系

reactbits 里和"按钮点击"相关的是 `ClickSpark`（Canvas 2D 火花迸射，支持 `ring` 扩散环、`layer:'back'` 溢出按钮外、`ref.spark(x,y)` 程序触发）、`Magnet`（磁吸）、`SpecularButton`（WebGL 玻璃）。

**两个重要事实：**

1. **reactbits 没有 Material ripple 按钮** —— ripple 语义只出现在 `RippleDistortion`（图片水波）和 Pro 的 `Minimal Ripple`（背景）。所以"点击涟漪"这个经典效果不能指望现成组件。
2. **我们做的是按压缩放，不是点击特效。** 它对发送按钮这种高频操作更合适：反馈明确、不遮挡内容、不需要 Canvas、也不需要在按钮外新建容器（而 `ClickSpark` 的 `layer:'back'` 恰恰要这么做，在 DSH 的输入区布局里风险很高）。

许可约束见 [改编与许可政策](../../THIRD_PARTY_NOTICES.md)。

### 1.3 注意

- 排除 `[disabled]`：禁用态按压会误导用户。
- 不要动 `background` / `border`：那些是官方状态色的职责。
- `transform` 会创建合成层，但对按钮是常规做法，代价可接受。

## 2. 发送确认闪光

### 2.1 思路

不监听点击，而是观察**状态跃迁**：发送 → 进入流式 → 输入区进入活动态。用 `[data-streaming]` 的出现作为信号。

### 2.2 实现

```js
// 这是本方案唯一允许的 MutationObserver：
// 只观察一个属性、只在根节点范围、防抖、可整体关闭
function watchStreaming(onStart, onEnd) {
  var current = null;
  var timer = null;

  function check() {
    clearTimeout(timer);
    timer = setTimeout(function () {
      var now = !!document.querySelector("[data-streaming]");
      if (now && !current) onStart();
      if (!now && current) onEnd();
      current = now;
    }, 120);   // 防抖
  }

  var mo = new MutationObserver(check);
  mo.observe(document.body, {
    subtree: true,
    attributes: true,
    attributeFilter: ["data-streaming"],
  });
  check();
  return function () { clearTimeout(timer); mo.disconnect(); };
}
```

触发时：

```js
var card = document.querySelector("[data-composer-card]");
if (card) {
  card.setAttribute("data-lumina-sent", "");
  setTimeout(function () { card.removeAttribute("data-lumina-sent"); }, 620);
}
```

```css
[data-composer-card][data-lumina-sent]::after {
  content: "";
  position: absolute;
  inset: -2px;
  border-radius: inherit;
  pointer-events: none;
  animation: lumina-send-flash 520ms ease-out;
}

@keyframes lumina-send-flash {
  0%   { box-shadow: 0 0 0 0 rgba(var(--lumina-brand-rgb), .45); }
  100% { box-shadow: 0 0 0 10px rgba(var(--lumina-brand-rgb), 0); }
}
```

### 2.3 风险与约束

| 项 | 处理 |
| --- | --- |
| MutationObserver 开销 | 只监听 `attributeFilter: ["data-streaming"]`，且 120ms 防抖 |
| 与 04b 的 `::before` 冲突 | 04b 用 `::before`，这里用 `::after`，互不占用 |
| 频繁发送时叠加 | 用 620ms 定时器清理，重复触发会重置 |
| 无法关闭 | 必须在 `lumina.press` 开关下受控 |

## 3. 新会话首屏入场

### 3.1 为什么不做按钮的点击动画

新会话按钮在 sidebar 内部，同样没有稳定钩子。监听它需要 MutationObserver + 本地化文案匹配，又脆又容易误触发。

**更稳的做法：把动效放在"目的地"而不是"按钮"上。** 新会话会进入首屏，而首屏有官方 slot。

### 3.2 方案

占据 `conversation.hero.brand.mark`（single slot），挂入场动画。每次进入空会话都会触发，**效果等价于"点击新会话后的动效呈现"**。

```js
function HeroMark() {
  return jsx("span", {
    className: "lumina-hero-mark",
    children: heroSvg(),
  });
}
```

```css
.lumina-hero-mark {
  display: inline-flex;
  animation:
    lumina-hero-in 320ms cubic-bezier(.22,1,.36,1) both,
    lumina-hero-glow 900ms ease-out 120ms both;
}

@keyframes lumina-hero-in {
  from { opacity: 0; transform: translateY(6px) scale(.92); filter: blur(6px); }
  to   { opacity: 1; transform: none; filter: blur(0); }
}

@keyframes lumina-hero-glow {
  from { filter: drop-shadow(0 0 0 rgba(var(--lumina-brand-rgb), 0)); }
  40%  { filter: drop-shadow(0 0 10px rgba(var(--lumina-brand-rgb), .55)); }
  to   { filter: drop-shadow(0 0 0 rgba(var(--lumina-brand-rgb), 0)); }
}

@media (prefers-reduced-motion: reduce) {
  .lumina-hero-mark { animation: none; }
}
```

设计意图参考 reactbits 的 `BlurText`（模糊→清晰）+ `SplitText`（错落入场）的合成效果，但**未使用其源码**，全部用纯 CSS 实现。

> 组件名是 `BlurText` / `SplitText`（无空格），早期文档写成 `Blur Text` 会搜不到。

### 3.3 可选：字标同步入场

若字标也在首屏出现（`conversation.hero.*` 有相关 slot），可给它加 60ms 延迟的同款入场，形成"图标先、字标后"的层次。

### 3.4 注意

- 动画只在**元素首次挂载**时播放一次（`both` + 一次性 animation）。
- 不要在路由切换/状态刷新时反复播放——若实测发现会重播，改用「首次挂载时加 class，动画结束移除」的方式。

| 强度 | 按压 | 首屏入场 | 发送闪光 |

## 5. 验收标准

### 按压
- [ ] 输入区按钮按下有可见缩放
- [ ] `[disabled]` 按钮按下**无**反馈
- [ ] 连续快速点击 10 次不卡顿、不抖动布局
- [ ] 减少动态下无缩放

### 发送闪光
- [ ] 发送消息后输入框出现一次外扩光环，约 0.5s 消失
- [ ] 光环 `pointer-events: none`，不影响输入
- [ ] 连续发送 3 条，光环不叠加、不错位
- [ ] 关闭 `press` 效果后光环消失

### 首屏入场
- [ ] 新建会话进入首屏时，hero 图标有淡入+缩放+去模糊
- [ ] 连续新建 3 次，动画每次都正常播放（或确定只播一次并记录原因）
- [ ] 在已有会话间切换时**不**误触发
- [ ] 减少动态下无动画

## 6. 未确定项

- `[data-streaming]` 出现时机是否与"用户点了发送"严格一一对应？如果模型快速失败，可能一闪而过或根本不出现，需实测后再决定是否改用其它状态钩子。
- hero slot 在**非空会话**下是否也渲染？若渲染，入场动画会在每次打开会话时播放，需要额外条件判断（建议：只在首屏空态播放）。
