# 06 · 实施路线与验收标准

## 6.1 分期

| 阶段 | 内容 | 稳定性 | 价值 | 前置 |
| --- | --- | --- | --- | --- |
| **P0** | 骨架 + `lumina.brand` + 设置面板骨架 | ★★★★★ | 最高（用户已指定） | 无 |
| **P1** | `lumina.composer`（边框流光）+ `lumina.caret`（光标） | ★★★★ | 高频可见 | P0 骨架 |
| **P2** | `lumina.press`（按压 + 发送确认）+ `lumina.hero`（首屏入场） | ★★★ | 质感补齐 | P1 选择器经实测确认 |
| **P3** | 强度预设、更多入场变体、与 brand-studio 的让位逻辑 | ★★★★ | 可玩性 | P0–P2 |

### 为什么 P0 必须先单独跑通

插件装载链有**四个静默失败点**（见 [02 §2.8](02-平台约束（执行前必读）.md)），任一不满足都是"不加载且基本无报错"。

如果骨架没验证就往里堆五个效果，出问题时你无法区分：

- 是插件压根没加载？
- 还是加载了但某个效果的 CSS 没命中？

**P0 的退出条件就是"确认插件已加载且品牌已替换"**，之后才允许往上加效果。

## 6.2 各阶段交付物与退出条件

### P0

交付：

- `package.json` / `cordis.patch.yml` / `lib/index.js` / `lib/client.js`
- `lumina.brand` 三个 slot 占据
- `settings.section` 面板（可只有总开关 + 品牌开关）
- 配置读写（`dsh-lumina/settings/v1`）
- README（中英）

退出条件（全部满足才进 P1）：

- [ ] `dsh.profile.bundles` 含 `dsh-lumina`
- [ ] `window.__DSH_BOOT__.entries` 中有 `dsh-lumina`
- [ ] 控制台有加载日志、无 slot 冲突告警
- [ ] 侧栏品牌已是鲜红鲸鱼 + 流光字标，且流光在动
- [ ] 卸载后回落到官方视觉

### P1

交付：

- `lumina.composer`（CSS 注入）
- `lumina.caret`（先完成 DOM 探测，再定实现路径）
- 两者各自的开关

退出条件：

- [ ] 边框流光可见且在动，**不遮挡任何交互**
- [ ] 光标动效生效，排版零变化
- [ ] 减少动态下两者都停止

### P2

交付：

- `lumina.press`（按压 + 发送确认）
- `lumina.hero`（首屏入场）

退出条件：

- [ ] 按钮按压反馈可用，禁用态无反馈
- [ ] 发送后有一次闪光
- [ ] 新建会话首屏有入场动画
- [ ] 唯一那个 MutationObserver 有防抖且可关

### P3

交付：

- 强度档位（subtle / normal / vivid）全效果联动
- 与 `dsh-brand-studio` 的让位逻辑
- 面板内实时预览

## 6.3 并行派工建议

P0 完成后，P1 与 P2 的三份效果文档**可以同时派给不同 Agent**：

| Agent | 文档 | 改动范围 | 冲突风险 |
| --- | --- | --- | --- |
| A | [04a](04a-动效-品牌logo.md) | `effects/brand.ts` + SVG 资产 | 无 |
| B | [04b](04b-动效-输入框边框流光.md) | `effects/composer-glow.ts`（`::before`） | 无 |
| C | [04c](04c-动效-打字机光标.md) | `effects/caret.ts` | 无 |
| D | [04d](04d-动效-按钮按压与首屏入场.md) | `effects/press.ts` + `effects/hero.ts`（`::after`） | 与 B 共用 `[data-composer-card]`，但 B 用 `::before`、D 用 `::after`，**不冲突** |

**唯一需要协调的**：`lib/client.js` 的 `apply()` 里各效果的注册顺序、以及 `core/styles.ts` 如果做单文件拼接则需合并。建议每个效果各自注入自己的 `<style>` 标签（`data-plugin="dsh-lumina"` + `data-effect="brand"` 等），避免文件级冲突。

### 派工给 Agent 时必须交代的

1. 先读 [02](02-平台约束（执行前必读）.md)，特别是装载四要点。
2. 只改自己那份文档对应的模块文件，不要碰别人的。
3. 每个效果必须自己 try/catch + 自己实现 `prefers-reduced-motion` 分支。
4. 提交时必须带**实际证据**（见 §6.4）。

## 6.4 证据要求（不可用"代码看起来对"代替）

| 验证类型 | 要求 |
| --- | --- |
| 装载 | `__DSH_BOOT__.entries` 的实际输出（贴 JSON） |
| DOM | 关键断言的实际返回值（贴 Console 输出） |
| 动效 | **两次采样**的 `getComputedStyle` / `getBoundingClientRect` 值，证明在变 |
| 视觉 | 开关前后的对比截图 |
| 无障碍 | `matchMedia` 与 `animation-name` 的实际值 |
| 性能 | DevTools Performance 10s 采样，说明有无 >16ms 长任务 |

⚠️ **截图不可作为动效唯一证据**：`Page.captureScreenshot` 有绘制时序问题，可能早于动画绘制。必须以 DOM/计算样式断言为主、截图为辅。

## 6.5 总验收清单

### 装载
- [ ] `~/.dsh/profiles/<profile>/package.json` 的 `dsh.profile.bundles` 含 `dsh-lumina`
- [ ] `window.__DSH_BOOT__.entries` 有 `id: "dsh-lumina"`
- [ ] 控制台无 `cannot occupy` / `effect failed` 告警

### 品牌（P0）
- [ ] 图标槽容器内是 `<svg>` 而非 `<img>`
- [ ] 展开/收起两态都渲染
- [ ] 流光在动（6 次采样 transform 互不相同）
- [ ] 流光扫过处纯白像素为 0
- [ ] 浅色 `#12100F` / 深色 `#F4F1F0`，对比度均 ≥4.5:1
- [ ] 减少动态下 `animation-name: none`

### 输入框（P1）
- [ ] 边框流光可见且在动
- [ ] 不遮挡文字/光标/选区/附件
- [ ] 点四角与中心都能聚焦（`pointer-events: none` 生效）
- [ ] 聚焦后时长变短
- [ ] 多行增高、拖拽、粘贴时不错位

### 光标（P1）
- [ ] 呼吸动画生效
- [ ] 流式时更快
- [ ] 位置与宽度零变化
- [ ] 选区高亮仍可见
- [ ] 减少动态下常亮

### 按压与首屏（P2）
- [ ] 按钮按下有反馈，禁用态无
- [ ] 发送后有闪光，不叠加
- [ ] 新建会话首屏有入场动画
- [ ] 会话间切换不误触发

### 品牌预设（P0 起）
- [ ] `brand: "ratel"` 时品牌区呈现 Ratel 标识与蓝 `#2563EB`
- [ ] 切到 `brand: "deepseek"` 后，品牌区**与所有效果**同步变红（`#FF3B30`）——不能只有品牌区变
- [ ] 切换不改变 slot 拓扑（`sidebar.brand.mark` 等仍各有一个占据者，不出现重复）
- [ ] 切换后刷新页面，配置保持（localStorage 生效）

### 不回归（全部阶段）
- [ ] 卸载后无 `.lumina-*` / `[data-lumina*]` 残留
- [ ] 卸载后 `dsh.profile.bundles` 已移除
- [ ] 设置面板可开、可存、刷新后保持
- [ ] `document.documentElement.dataset.lumina = 'off'` 后所有 Tier 2 动画停止
- [ ] Performance 10s 采样无本插件引起的持续长任务
- [ ] 与 `dsh-brand-studio` 同时安装时品牌区不出现双重字标
