# 发送反馈设计

日期：2026-10-24。状态：已实现，受控浏览器验证通过；待客户端视觉验收。基准：0.6.0；本轮先做发送按钮反馈，水滴材质另行细化。

## 视觉目标

发送按钮像轻触水面：按下时略微下沉，随即向外扩散两圈薄水纹，局部反光随扩散减弱。反馈在按钮周围清楚可见，与水滴转场同时工作。按钮位置固定，文字与消息的业务交接不等待动画。

## 动作编排

以下为正常强度的设计目标，以发送意图通过本地有效性检查为起点；该反馈不代表服务端请求成功。

| 阶段 | 时间 | 表现 |
| --- | --- | --- |
| 触压 | 0–100 ms | 鼠标按压时按钮缩至约 0.96，松开平滑恢复；键盘发送仅播放后续水纹 |
| 主水纹 | 0–460 ms | 从按钮外沿开始，直径从按钮直径的约 1.05 倍扩散至 2.2 倍；起始清楚，逐渐变薄、淡出 |
| 后续水纹 | 延迟 85 ms，持续 485 ms | 第二圈更淡，扩散范围略小，结束时间约 570 ms；与主纹保持可辨的间距 |

颜色以浅蓝灰和少量白色反光为主，环线约 0.8–1.2 CSS px；透色外缘帮助白底辨认，局部亮弧与柔和衰减表现水感。整体不能呈现等亮霓虹圆环、实心圆盘或过曝光斑。不增加全框爆闪、沿框跑光点、飞散粒子或持续循环。深浅主题均需辨认。

两圈从同一按钮中心扩散，不移动按钮或输入框。装饰允许越过框边，在内容与控件上方透明绘制并保持点击穿透；窗口移动和尺寸变化时不能遗留固定光环。

## 与水滴的关系

水纹负责即时发送反馈，水滴负责文字汇聚到消息的转场。两者可短暂重叠：水纹在按钮周围展开，文字在输入区域左侧汇聚，视觉焦点分开。水纹不等待水滴飞行结束；水滴接管发送手势也不能抑制水纹，转场失败不能补出第二次水纹。水滴关闭时，水纹独立工作。

本轮不新增框边冲击波或牵引丝带，先保证一次发送的反馈清晰、精致。

## 触发与边界

- 鼠标有效发送、键盘真实发送都产生一次水纹，去重覆盖 click、发送转场和生成状态变化的多路通知。
- 禁用按钮、空内容且无有效附件、停止生成、普通换行、组合输入确认不触发。不能仅凭 Enter 或“最右侧按钮被点了”认定发送。
- 优先共用已有发送适配层的有效性与意图判断，不改变宿主请求、输入内容或提交时机；后端请求失败也不重播。
- 保留现有「按钮与菜单反馈」开关，默认开启。其关闭时停止水纹，发送转场设置保持独立。
- 系统减少动态时取消缩放与扩散；使用短暂、静态的按钮轮廓反馈，结束后恢复，不保留循环效果。
- 页面隐藏、关闭效果、切换会话及卸载时清理动画、属性、监听和装饰节点。

## 技术落点与验收

使用 CSS transform / opacity 驱动两圈水纹，不为小面积反馈新增 WebGPU。按压仅影响插件自有 scale；不得覆盖宿主 transform。先读取按钮位置，再启动动画，逐帧不读布局。

发送反馈独立观察公共 session 的 pendingSubmissions，仅在近期本地点击或键盘操作得到 transcript admission 后播放，以 requestId 去重。与转场共用 TransferServices 类型和 sendControl 适配，不再依赖转场接管或失败回调；仅附件发送也可确认。公共 session 服务不可用时跳过装饰，不退回仅凭 Enter 或 streaming 猜测。

客户端分别检查鼠标、键盘、中文输入法、换行、停止、空输入、有附件、转场关闭/开启及失败回退；每次有效发送只有一组两圈水纹。录制或多时刻采样证明扩散与结束清理，白底与深底检查细亮边、透明过渡和局部高光，不以单张截图代替动态验收。

## 本轮验证

实际客户端 bundle 的受控浏览器中，水滴开启/关闭均只有一组两圈水纹；120 ms 与 260 ms 的计算样式分别证明扩散和透明度变化，结束后清除 active 属性。键盘真实提交触发，Shift+Enter 换行不触发；减少动态下无扩散动画，仅短暂静态轮廓。浏览器无 pageerror，原生最终观感待确认。

### 圆形轮廓细化

两圈使用明确的正方形边界、50% 圆角和等比缩放。整圈保留连续蓝灰底线，不以大段白色上边或淡化下边制造高光，以免白底下出现缺口、被误读为椭圆；高光仅用轮廓内侧的轻微反光，不额外画同心亮圈。
