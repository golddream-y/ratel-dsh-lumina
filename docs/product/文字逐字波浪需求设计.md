| 项 | 内容 |
| --- | --- |

| 关系 | 与 [发送转场需求设计](发送转场需求设计.md) 并列的独立效果；共享只读字形快照能力 |

## 1. 目标

用户打字、以及模型文字流式输出时，**新出现的字依次被点亮**，像一道光沿着文字传过去，然后归于平静。

与发送转场无关：发送转场负责"文字从输入框去到消息"，本效果负责"文字出现时的光"。

## 2. 范围

| 表面 | 是否包含 | 说明 |
| --- | --- | --- |
| 输入框（用户草稿） | ✅ | 每次输入，新输入的字依次点亮 |
| 流式输出（助手消息） | ✅ | 每批新到的字依次点亮 |
| 已有文字（历史消息、设置页正文） | ❌ | 不回溯、不重放，只作用于"新出现"的字 |
| 品牌字标 | ❌ | 已有扫光，不叠加 |

## 3. 实现约束（硬性）

1. **绝不修改宿主文本**：不插入 span、不改 textContent、不动 Lexical 状态；
2. **只在字的上方叠光**：每层光是一片定位到该字真实矩形的辉光块，`pointer-events:none`、`aria-hidden`；
3. **不改布局**：辉光是 `position:absolute` 覆盖层，不参与排版；
4. **不干扰输入**：IME 组合期间不产生光；组合结束后再补一次；
5. **有界**：每次触发的光层数量与存活时间都有上限（建议 ≤ 40 层、≤ 700ms）。

## 4. 视觉与实现形态（已在原型上实测）

光 = **该字的高亮副本 + 模糊**，叠在文字上方，快速隐去：

```text
<span class="spark" style="与原字同字体/同字号/同位置；color=品牌色; filter:blur(3px)">
```

- **不是背光**：输入框与消息区都有不透明背景，光放到文字后面会被挡住；
- **不能用 `mix-blend-mode: screen`**：白底上 screen(白, 红) = 白，光等于消失；
- 真实文字一个字都不动，辉光只是叠在上面的副本；
- 错峰：新字按出现顺序依次亮起，间隔约 45ms；
- 收尾：单个光在 ~500ms 内隐去，文字本身颜色不变；
- 与输入框边缘光晕、发送转场不冲突（转场期间暂停）。

只对**新增的字**点亮（记录上一次字符数，只处理增量），不重复点亮已有文字；同时存活的光层上限约 10 个，避免长文本堆积。

## 5. 设置

- 新增独立开关 `effects.typeWave`（布尔，默认开启）；
- 与 `sendTransition` 互不影响：转场选了"关闭"也不影响波浪；
- 强度沿用全局 `intensity` 档位（只调节奏，不调颜色）。

## 6. 验收

| 编号 | 验收点 |
| --- | --- |
| W1 | 输入时**只有新字**依次点亮，光沿文字方向传播，随后隐去；已有字不被重复点亮 |
| W2 | 流式输出同样逐字点亮 |
| W3 | 文字内容、选区、撤销、IME 全程无异常 |
| W4 | 无光层残留（切换会话、卸载、异常后归零） |
| W5 | 长文本不产生布局位移，输入不卡顿 |
| W6 | 减少动态下不播放，只保留即时状态 |

## 7. 未决

- 光的颜色：品牌红 / 官方蓝 / 跟随表面（原型已验证红与蓝两种）；
- 错峰间隔与持续时间的最终值；
- 流式输出是否与"打字柔光"（M3）合并，避免两个效果同时亮。
