# 丝带流光与液态发送

日期：2026-10-24。状态：页面丝带流光已随 0.6.0 发布；发送水波纹与水滴材质细化仍待实现。发送按钮最新动作、触发与验收要求见[发送反馈设计](发送反馈设计.md)，该文优先于下文早期波纹说明。

## 目标与范围

流光呈现半透明丝带的厚度、交叠和柔和流动；发送时按钮水波纹清楚可见，水滴具有通透水感。三者共享蓝白亮边、少量暖色反射的视觉语言，不能靠堆粒子、加强外发光代替水和丝带的形态。

用户确认“就是效果图上的”：本轮目标是新会话页面级丝带流光，从页面左下流向输入框，沿框外缘形成柔和交叠与亮边，延续到另一侧。不是侧栏运行条目，也不是将丝带缩成输入框内的一条细线。侧栏当前星河保持原样。

## 丝带流光

参考 `assets/readme/hero-zh-CN.png` 左下区域：宽窄变化的半透明带面、交叠处的亮度差、细白亮边与蓝白/淡珊瑚色反射。运动像风推动薄绸，连续变形、速度有舒缓变化，轨迹平滑且不机械往返。星点只作极少量点缀，不能成为主体；不出现“一个亮点沿边框跑”的视觉。

先制作独立动态原型，再适配最终落点。不能承诺从静态图推导唯一的运动轨迹或逐像素复刻。

### 确认落点：新会话页面与输入框外围

- 构图以宣传图左下丝带为参考：页面左下有宽度和起伏的带面向输入框汇聚，贴近框外缘后分层绕行，并向另一侧自然淡出。不是一个光点沿矩形边框循环奔跑。
- 带面允许跨出输入框，位于新会话内容区域的装饰层；用户补充确认允许跨过侧栏，必须保持穿透点击；输入文字和控件内部仍裁切保护。桌面小窗口与窄屏按可用空间收敛延伸范围，不产生横向滚动或硬切边。
- 默认只保留混合色细边，未聚焦时不持续发光；输入框聚焦后丝带与亮边平滑显现，失焦后平滑消退。这一规则沿用用户此前确认的默认不发光要求。
- 粒子聚合、标题描边及辅助控件的既有顺序保留。主入场结束后，若仍聚焦才进入丝带流动状态；鲸鱼喷水仍在全部入场结束后播放一次，两者衔接不能突然爆亮。
- 用户点击或输入时立即可用；所有带面仅作背景或外缘装饰，不阻挡操作，不复制输入框或造成重影。
- 先在真实新会话布局尺寸的原型中确认带面厚度、跨度与流速，再落地客户端；宣传图里的立体透视与地面倒影不属于客户端要求。

## 发送按钮水波纹

用户反馈当前实际客户端看不到水波纹。代码中，转场接管发送手势时跳过 `pulse`；这是已发现的触发冲突，尚不能据此断言所有缺失现象均由它造成。

最终目标：一次有效发送产生一次清晰反馈，无论水滴转场是否开启。无效发送、禁用按钮、停止生成及组合输入确认不触发。

- 点击发送后，按钮中心向外扩散一圈主波纹和一圈更淡的后续波纹；两圈有短暂错峰，约 450–650ms 完成。
- 波纹表现为细亮边与柔和透明过渡，不能像厚实圆环、爆闪或整个输入框震动。
- 波纹可超出按钮约一半直径，需有独立可见装饰层，不受按钮圆角或输入框裁切吞掉。
- 键盘真实发送使用同一反馈；由发送确认触发并去重，不把普通 Enter 换行当发送。
- 波纹与水滴允许短暂重叠：波纹确认按下，水滴完成文字到消息的衔接。转场成功不能再抑制波纹，转场失败也不得补出第二次波纹。
- 保留独立设置语义：按压反馈关闭时不强制波纹；水滴关闭时波纹仍可播放。

## 水滴转场材质与形态

参考宣传图中飞向消息的水滴。保持现有文字汇聚、边缘融合、剥离、飞行和消息交接的总体目标；本轮不引入文字消解效果。

### 材质

- 主体通透，以浅蓝灰层次、细亮轮廓和局部白色高光表达体积；珊瑚红仅作为少量环境反射，不能将水滴染成实色红球。
- 具有宽而柔和的亮面、较深的边缘及局部透光变化；深浅主题均能辨认，不依赖大面积外发光。
- 透明与折射为视觉近似；不读取对话截图或整页内容做真实折射，不增加消息内容采集。

### 运动与交接

1. 输入文字作为连续整体汇聚缩小，不能碎成烟尘或逐字消解。
2. 到输入框边缘时先融入局部液面，形成可见的连接与鼓起。
3. 水滴拉长，连接处变细后断开；剥离前后位置和速度连续。
4. 飞行时有圆润腹部与短尖端，形状随速度和方向柔和变化，高光跟随体积变化，不是固定贴图平移。
5. 抵达消息位置后轻微压扁、展开，与真实消息自然交接，不出现消息先显示再遮住的闪烁。

宣传图中的长丝带拖尾不直接作为运行时要求。尾迹若采用，只能短、淡、快速消失，不横贯对话区，不掩盖文字。发送请求不等待动画，不延迟业务执行；目标缺失、中断或渲染失败时恢复真实内容。

## 协调与性能

- 流光、波纹与水滴分别承担环境、按下反馈和发送转场，不同时提高亮度争抢注意力。
- 系统减少动态时关闭循环、波纹及飞行，直接交还真实界面；总开关和逐效果关闭应完整清理。
- 装饰不捕获事件，不改业务状态；无第三方动效运行时。优先使用局部缓存、有限曲线和 transform / opacity，控制透明叠层与滤镜范围。
- 离屏或页面隐藏时暂停环境动效；转场取消时立即清理。性能预算在动态原型阶段实测，不预先承诺固定帧率。

## 验收与实施顺序

按已确认的页面级丝带构图制作共享原型；之后恢复可见的发送波纹，再细化水滴材质与融合/剥离。

验收必须使用实际客户端与真实尺寸：

- 新会话聚焦/失焦时，页面丝带流光显隐连续，具有带面而非星点线条；文字仍清晰。
- 鼠标有效发送、键盘有效发送，且水滴开/关组合下，每次都恰好一次波纹；换行、禁用和停止按钮不误触发。
- 分段慢放检查液面连接、断颈和抵达交接；正常速度能辨认通透水滴，不能出现实色球或文字消解。
- 亮暗主题、减少动态、中断、切换会话及连续发送均不残留遮罩或装饰。
- 原型与客户端使用相同核心绘制；记录多时刻采样及实际对比，不能只凭截图声称动画有效。

## 本轮落地（2026-10-23）

用户提供原生新会话布局截图，确认左下留白可容纳页面级丝带。本轮只实现流光，归属「输入框边缘流光」开关；发送波纹与水滴材质留待后续。采用一张局部 Canvas 绘制宽幅透明带面与亮边，真实客户端和原型共用实现；默认不绘制，聚焦且主入场结束后淡入，失焦淡出。按视口绘制，允许跨侧栏；输入框内部裁切，重排由观察器更新几何，绘制循环不读取布局；关闭、减少动态或离开新会话时清理。

### 实现边界与验证

一张视口 Canvas，像素数上限 250 万，DPR 不超过 1.25；绘制约每 30ms 更新，隐藏、未聚焦及减少动态时停止。只在观察器或布局事件中采集矩形，绘制循环不读取布局。1440×1000、1024×700 受控页面验证聚焦 opacity 0→1、画面采样变化、失焦回到 0，输入框中心透明度为 0，无横向溢出；减少动态与离场均清除 Canvas，控制台无 pageerror。未做原生客户端帧率测量，不承诺固定帧率或宣传图逐像素还原。

### 范围补充（2026-10-24）

用户明确允许丝带越过侧栏，装饰层改为全视口坐标，不再以主内容区边界裁切；全层 pointer-events none，不影响侧栏点击、输入、拖拽和选中。

### 2026-10-24 实机视觉返工

用户截图显示首版呈平行半透明色带，沿输入框上沿形成生硬横线，与宣传图的通透光流差距明显。重新以左下舒展曲线汇入输入框边缘：取消沿卡片轮廓绕行的直角与长直线；薄层宽窄交错，使用白色细高光与低透明彩色晕层形成透亮层次。细光丝随同一连续流场变化，避免平行塑料条。仍允许越过侧栏，装饰不接收点击，输入框内部保持透明。此条为未发布功能的视觉迭代，不单列为 changelog 修复。

### 新会话光带构图调整

按输入框尺寸确定装饰尺度：左侧延伸约 0.6 倍输入框宽，右侧约 0.18 倍；光带沿输入框下方贯穿，采用低矮的连续 S 曲线，避免从窗口边缘爬升的大斜坡。上下起伏与光层厚度随输入框宽度缩放，在窄窗口收敛。主体保持通透，左右端渐隐，不沿矩形轮廓描边。标题与操作区保持视觉留白。此前左下斜向汇入的构图由本条取代。

### 本轮仅调整材质

按用户要求暂不调整位置、路径和延伸比例。将多根细线叠加改为少量连续曲面：横向截面具有透明边缘、红蓝透色、白色反光；随扭转改变投影宽度与反光位置。取消密集平行光丝，以宽面与薄边交替表达体积。先验收质感，再调整贯穿构图。

### 最新技术路线：WebGPU

用户明确指定 WebGPU。已替换页面丝带绘制内核为原生 WebGPU/WGSL，保留现有位置和延伸范围；旧 Canvas 分带方案仅作历史对照。材质样板先静态验收再评估运动，WebGPU 不可用时跳过该装饰，不修改客户端安全设置。此前 WebGL 2 方案已被本条取代。

### WebGPU 材质反馈：锯齿、缺光与生硬

用户反馈样板仍有锯齿、缺乏发光感且运动不够柔顺。本轮冻结位置，增加片元导数控制的边缘覆盖与柔化；以少量柔和透色光晕衬托局部白亮折面；曲面变化使用低频、不同相位的连续弯曲，避免机械同步翻转。不得用全屏泛白掩盖形态问题。局部光晕需要额外绘制，预算按实际提交更新，不能沿用上一版三次 draw 的描述。

### 曲面结构重做

用户否定同向、等距的淡色薄片形态。本轮保持整体定位与横向范围，曲面改为不同路径相位、不同局部宽度的非对称交错结构，出现展开、薄边和再收束；红色与蓝色各有主导面，避免均匀混灰。局部高光沿折转集中，透色面保留足够色彩对比。样板与客户端继续共用内核，视觉验收尚未通过。

### 发光层次修订

用户再次反馈白底样板看不到光。当前反射高光与淡色光晕没有形成足够对比。本轮保留曲面与位置，区分近白亮芯、饱和度更高的近场彩光与低透明远场衰减，降低宽面均匀泛白。亮芯必须在彩光周围可辨，而不是白色画布上单独一根白线。此处为白底视觉近似，不宣称物理 HDR bloom 已实现。


### SVG 与 WebGPU 结合路线

用户要求先改技术设计再实现。光带形态改由包内手绘 SVG 边界驱动，构建时采样为曲面数据；WebGPU 负责有界形变、实时高光和透明合成。先对齐基准帧形态，再看材质与动态。页面定位和延伸范围保持，不使用静态截图代替实时曲面。

### 先验收 SVG 美术样板

用户否定三条波浪状 SVG 源图。暂停 GPU 形态与材质调参，新增独立可编辑 SVG 美术样板，先表现带面翻卷、局部褶皱、锐边与柔光、集中亮部。样板允许使用 SVG 渐变、裁切与局部滤镜探索视觉，不代表这些效果已经映射到实时 GPU 内核。现有客户端实现不随本轮未认可的美术探索变化；静态样板通过后再制定到运行时的映射。

### 已认可方向的静态细化

### 构图、初次流入与持续流动

用户反馈现版过平、像垫在框下，流动几乎不可辨。本轮缩短并收束右侧，左段保留可见抬升曲线，中段只短暂接触下缘，减少通栏桌布感。首次聚焦且入场完成后，约 1.65 秒由左向右逐段流入，不整条同时淡出显现；同一新会话失焦再聚焦不重播，切换新会话重置。展开结束后保留多段柔和明暗随流线向右运行，同时轻微形变；不能只靠整体呼吸或静态贴图小幅上下移动代替流动。保留失焦淡出、减少动态停用、标题栏局部画布保护。

保留已认可的左下进入、框后穿插、右上舒展构图。本节补充现行视觉要求，替代前文仅以“更亮”判断高光质量的表述。

- 曲线：框边收束与右侧展开应连续、舒缓；静止和流动时均不出现可辨的折点、突然变窄或局部尖拱。细丝跟随主曲面，错相微动不能造成抖动。
- 亮部：局部窄亮芯可辨，亮芯周围仍能看见红蓝透色、薄边与褶皱；不得形成大片泛白光斑或冲淡带面层次。
- 精度：在客户端正常缩放及高分屏下检查实际显示尺寸，细线与渐变应连续，避免明显锯齿、像素块、拉伸模糊或色阶断层。截图缩放产生的失真需与客户端原始显示区分。
- 动态与交互：保留逐段流入、持续流动、失焦淡出及新会话重置；不因提高画质引入明显掉帧，点击穿透、窗口拖动和减少动态行为必须正常。

验收分别记录静帧细节、持续流动观感与交互结果。浏览器验证通过不等同于客户端视觉通过；当前精修版本已实现并本地安装，等待客户端实际观感确认。网格、纹理、像素预算等实现参数见[新会话丝带渲染设计](../engineering/新会话丝带渲染设计.md)。

### 独立开关与操作反馈

新会话分组提供“首屏入场”和“丝带流光”两个独立开关；输入框分组的边缘流光只控制框边。设置保存后生效，首屏动画在进入新会话时播放，丝带在新会话聚焦输入框后显示。各项说明应明确触发时机，避免用户切换入场开关却以为它会隐藏丝带。旧存档缺失丝带开关时继承旧输入框开关，保留关闭意图。

### 客户端比例调整

缩小、放大或运行中连续修改客户端比例，光带都必须保持与输入框外缘、遮罩对齐，不得覆盖文字及发送按钮。GPU 裁切与真实画布位置统一在视口坐标下验证，不能只在默认比例检查。发送水纹在当前比例下保持圆心对齐；播放中改变比例则清掉这次短反馈，防止漂移残留。
