# 发送文字水滴转场 · 需求设计

| 项 | 内容 |
| --- | --- |
| 状态 | 实现版已接入；受控浏览器通过，真实客户端视觉与性能验收待完成 |
| 日期 | 2026-10-22 |
| 产品 | Ratel Lumina / `@ratel-works/dsh-lumina` |
| 适用动作 | 当前会话中一次有效的用户文字发送 |
| 关系 | 扩展 [产品需求](产品需求.md) 的发送反馈；实现须遵守 [技术详细设计](../engineering/技术详细设计.md) 与 [官方 API 面](../engineering/官方API面.md) |

点击发送后，输入框中的文字逐字、逐行向汇聚点收拢，连续融合为水滴；水滴先抵达输入框上边缘并完全融入局部液面；同一液面再鼓起、拉出细颈，随后剥离，沿弧线抵达本次用户消息的位置，再展开为对应文字。发送请求与消息创建照常进行，转场只接管短暂的视觉呈现。

本文定义最终交付效果、呈现时序、宿主接入依赖及验收标准。2026-10-22 实现已使用公开只读提交快照与用户节点身份关联；参数仍需真实客户端视觉验收。

## 1. 最终效果与交付范围

### 1.1 七个连续阶段

| 阶段 | 用户应看到的变化 | 完成条件 |
| --- | --- | --- |
| 文字汇聚 | 输入框中各行、各字向同一个位置收拢；距离较远的文字形成舒展的汇聚路径，原来的排版逐渐瓦解 | 能辨认多个文字单元具有不同位移，不能只是整段文本整体缩小 |
| 融合成滴 | 字形逐渐紧缩、接触、融合，文字轮廓与液体轮廓连续变化，形成有体积感的水滴 | 慢放时看不到独立文字层消失后突然换成水滴的断点 |
| 融入边缘液面 | 汇聚成形的水滴抵达输入框上边缘，接触、铺展并完全进入局部液面；随后液面短暂稳定 | 必须有独立水滴完全消失、仅剩液面的时段，不能直接穿过边框 |
| 牵连剥离 | 同一处液面重新鼓起，向外拉出水滴与细颈；细颈被拉长、变细后断开，残留收回 | 连接、拉伸、断开具有先后关系，不能是水滴凭空出现后直接位移 |
| 弧线飞行 | 水滴脱离输入框，沿指向本次用户消息的弧线运动；形状随速度轻微拉长，接近目标时收敛 | 飞行方向明确；不绕框、不随机游走，不形成可见颗粒群 |
| 抵达铺展 | 水滴在目标文字区域内减速、压扁并铺开，液体轮廓逐渐分化为文字轮廓 | 目标位置是本次发送的用户消息，不能是助手消息或猜测坐标 |
| 文字还原 | 文字单元从铺展区域中分离，回到目标消息的真实排版位置，最终交接给宿主文字 | 文本内容、最终换行、位置与真实消息一致；没有水滴淡出后消息突然出现的替换感 |

七个阶段属于同一条转场，不分别作为可交付的简化版本。允许工程实现使用视觉副本、不同渲染层和轮廓混合，但合成画面必须满足连续汇聚、液化和还原的要求。

### 1.2 文本与其他内容

覆盖单行、多行、中文、英文、标点、换行、emoji 与组合字符。文字单元按用户可见字素处理，不能拆开 emoji、组合音标或中文输入法尚未提交的内容。

Markdown 源码按输入时的真实可见文字汇聚；到达后按宿主消息渲染后的真实排版还原。源端和目标端不一定逐字一一对应，不能用强制相同换行来改变宿主排版。对 Markdown 标记被隐藏、文字被格式化等情况，轮廓应在液态阶段完成对应转换，不允许在最终交接时跳变。

附件、文件引用与命令标签的业务行为保持原样，本需求不要求把非文字卡片液化。含这些元素时，只对可确认属于本次文字内容的部分执行转场；不能连同附件状态、工具按钮或整张输入框一起吸走。

长文本只对源端视口内原本可见的文字进行可见汇聚，对目标视口内应可见的文字进行还原；不可见部分照常由宿主承载。不得为覆盖全文强制滚动输入框或会话，也不得因为文字长就改成整段缩小的另一种正常效果。

### 1.3 不满足交付目标的表现

以下表现不能以「近似实现」通过正常场景验收：

- 整段文字作为一张矩形图片统一缩放，随后换成水滴。
- 文字仅淡出，水滴独立淡入，二者没有连续的形态融合。
- 用圆点、发光胶囊或带尾巴的图标代替液体剥离。
- 水滴到达后直接消失，整条消息统一淡入，缺少液体铺展与文字展开。
- 目标还未找到，就飞向预设的屏幕角落或「大概是消息」的位置。
- 延迟真正的发送、改变消息内容或改变会话滚动，以配合动画。

## 2. 触发与交互规则

鼠标、触摸及宿主支持的键盘发送都应进入同一条视觉流程。点击禁用按钮、空内容被拒绝、普通回车换行、IME 组合确认、停止生成和重试助手输出均不触发本效果。

「有效发送」指宿主已经接受本次用户提交并开始创建对应的本地用户消息，不等于服务端已经成功接收。输入快照可以在有效发送前准备，但不得仅因 pointerdown 或任意按钮 click 就让文字消失。动画结束也不表达发送成功，失败、排队和重试状态仍由宿主原有界面说明。

同一次提交只能有一条转场。点击与后续流式开始不能各播一次；连续发送相同文字也必须作为不同提交识别。动画不阻挡输入、选择、拖拽和下一次发送。

用户开始输入下一条内容时，已有转场可以在独立装饰层继续飞行，但不能读取、隐藏或带走新草稿。真实输入框是否清空、何时恢复占位文案，完全沿用宿主行为。

## 3. 视觉编排

### 3.1 汇聚点、路径与形状

汇聚点位于输入框可编辑文字区域内，靠近指向目标消息的一侧。由源文字布局和目标方向决定，不能固定吸向发送按钮，也不能要求用户改变输入框尺寸。文字位移应表现为共同汇聚，同时保留行间与字间的细微错峰；不能让所有字以完全相同的路径重叠飞行。

汇聚成滴后先抵达输入框上边缘，完全融入局部液面。液面再向外鼓起并保留短暂连接，连接锚点必须位于同一条边缘，不能整块拉伸输入框背景。断开后的水滴是一个连贯主体，可有很短的形变余韵，不增加绕行的小光点、散射粒子或持续拖尾。

飞行路径优先采用一条简单、平滑的弧线，避开明显穿出应用视口的路线。水滴的体积感通过轮廓、高光和轻微明暗层次表现，颜色使用独立冷色水体与高光 token，不能继承品牌红；文字还原后立即恢复宿主原有文字颜色和样式。

### 3.2 时长初值

以下为实现调校初值，需通过真实画面评审确定；不影响完整阶段的必达要求。

| 阶段 | 建议时间窗口（normal） | 节奏 |
| --- | --- | --- |
| 汇聚 | 0–160ms | 迅速建立汇聚方向，文字仍可辨认 |
| 融合 | 160–240ms | 字形轮廓连续收拢为液体 |
| 抵达边缘 | 220–360ms | 水滴与输入框上边缘建立接触 |
| 融入与稳定 | 340–510ms | 水滴完全融入液面，450–510ms 不存在独立水滴 |
| 鼓起与剥离 | 510–710ms | 同一液面隆起，细颈拉长、变细、断开 |
| 飞行 | 710–950ms | 中段较快，接近目标减速 |
| 铺展与还原 | 950–1150ms | 液体扩展，字形分离并归位 |

相邻阶段允许少量重叠，不能机械地停在每个阶段末尾。目标总时长以约 1150ms 为当前初值，不能为了等待网络或目标挂载而无限延长。强度档位只调整节奏与形变幅度，不减少必要阶段，也不开放任意毫秒参数。

### 3.3 与现有动效的主次

水滴转场接管本次发送的主视觉反馈。触发时保留按钮轻按压，暂停同次发送的独立扩散光环，避免多个焦点争抢。输入框既有混色细边不消失；聚焦流光在汇聚与剥离期间暂停，转场脱离输入框后按当前焦点状态恢复。品牌扫光沿用输入或输出期间暂停的规则。

本效果独立开关，暂定配置标识 `sendTransfer`；最终设置文案为「发送文字水滴转场」。该配置已在实现版接入，默认开启。现有 `press` 开关继续控制普通按钮反馈与菜单淡入；水滴转场关闭、减少动态或接入不可用时，发送保留现有轻量确认。

正式交付时拟默认启用 `sendTransfer`，旧设置缺少该字段时按默认值迁移；总开关关闭时不运行。`sendTransfer` 与 `press` 独立：前者开启且可正常运行时，替代同次发送光环；前者关闭或因异常退出时，仅在 `press` 开启的情况下恢复基础发送确认。两者均关闭时不增加发送装饰。最终迁移与能力探测策略应在工程设计中落实，不能在当前代码中假定新字段已存在。

## 4. 真实内容与视觉副本的交接

### 4.1 源端交接

宿主清空编辑器前，适配层取得本次提交的只读文字与可见排版快照。效果层根据快照生成临时视觉副本；逐字分解、变形和液化都发生在副本中，不向 Lexical 内插入 span，不修改真实输入内容、选区、撤销记录或组合输入状态。

副本必须在真实文字的相同位置开始呈现。快照保存字体、字素、换行、裁剪、滚动偏移和可见几何信息，不能只保存 textContent 后用另一种字体重排。宿主文字消失与副本显现的交接不得出现空白帧或双重文字；这需要可验证的发送呈现时序，普通异步观察不能代替此保证。

### 4.2 目标端交接

目标是同一提交对应的用户消息文字区域。消息应按宿主正常流程创建，不能等待动画结束才写入消息列表。若真实文字提前出现，只能在完成转场的条件已满足且目标已准确关联时，短暂接管该文字区域的视觉呈现；动作栏、失败提示、排队状态与容器布局保持可用。

临时接管不得修改目标文字、可访问名称、焦点或业务属性，不使用 display:none/移除 DOM 改变布局。落地阶段依据目标真实渲染布局展开副本文字，展开完毕在同一呈现时机交还真实文字并移除副本。不能留下重影、字体跳变或最后一帧的位置突变。

任何视觉隐藏必须绑定清理句柄，取消、异常、开关关闭和插件卸载时立即恢复。用户尝试操作目标消息时，中止转场并恢复真实文字优先于继续播放。

### 4.3 业务时间线与动画时间线

业务侧正常提交、创建用户消息、更新发送状态，并行执行。动画侧从本次快照开始汇聚和剥离，在飞行前取得对应目标的稳定几何信息，最后完成视觉交接。目标允许在汇聚阶段出现；不允许在剥离后猜测落点。

目标未及时就绪属于异常或接入能力不足，不能将等待时间藏进无限拉伸的细颈，也不能把「中途淡出」作为普通发送的默认实现。

## 5. 宿主接入契约与当前缺口

以下是本效果需要的能力契约，不是已存在的 DSH API 名称。它们应由 L1 适配层统一提供，效果层不得自行读取私有业务 store 或拼接 hash 选择器。

| 所需能力 | 最少需要的信息 | 当前事实与要求 |
| --- | --- | --- |
| 发送前快照 | 本次文本、可见字形布局、源几何、会话标识 | composer 输入钩子存在；原子快照与真实发送的时序尚未验证 |
| 有效提交确认 | 独立提交标识、会话标识、文字快照关联 | 当前 click 与 streaming 信号不足以确认每一次用户发送；需要核实公开只读事件或扩展点 |
| 本次用户消息关联 | 提交标识到用户消息身份的确定映射 | 当前适配层没有已验证的映射；不能用文字相同或最后一个 DOM 节点判断 |
| 目标布局就绪 | 真实文字区域、渲染后可见布局、滚动容器及挂载状态 | 待核实稳定消息钩子和布局时机；包括 Markdown 的源/目标差异 |
| 可逆视觉接管 | 源端/目标端呈现控制及无条件恢复句柄 | 待验证 React 重建、虚拟列表与卸载下是否可可靠恢复 |

浏览器能绘制这些形态，不代表现有插件已能可靠接入。实现前必须把上述缺口逐项核实；如客户端没有公开入口，应提出正式的宿主扩展需求，不能改 app.asar、拦截请求、依赖私有 store 或以不可靠选择器强行绕过。

缺少确定的提交关联或目标交接能力时，完整效果不能通过交付验收。正常发送仍须工作，但不允许将低配动画标成最终目标已完成。

### 5.1 对现行只读范围的提议扩展

现行产品需求 C5 将读取范围限制为 `data-*` 与主题 token。本效果需要新增一项明确、局部的例外：仅为本次有效用户提交读取文字及可见排版，生成短生命周期视觉副本。它不授权读取助手输出正文、私有请求状态或其他会话草稿，也不授权记录文字。现行产品需求 C5 与工程契约已同步此局部例外。公开快照接入已实现，真实客户端验收仍须单独记录。

## 6. 建议的渲染职责

采用「只读快照 → 临时字形层 → 液体形态层 → 目标字形层 → 宿主文字」的视觉流水线。字形层保留字素级或能体现独立文字运动的几何信息，液体层负责字形融合、细颈拉伸和落地铺展，转场协调器只组织阶段与取消。

渲染层切换本身不是问题，用户看到轮廓断裂才是问题。可以采用 DOM/CSS、内联 SVG、浏览器原生动画及必要的临时遮罩；具体轮廓融合方法由后续实现验证选择。不能在本文尚无验证的情况下宣称已解决任意字体的字形提取或任意 Markdown 的逐字几何映射。

保留零第三方运行时依赖。液化所需的临时 SVG 滤镜、遮罩或轮廓动画超出现行 transform/opacity 默认约束，须在工程设计中明确作用范围、生命周期和性能证据；不能把「水滴」当作无限制使用全屏滤镜、Canvas/WebGL 或逐帧整页截图的理由。

## 7. 状态、取消与异常

主流程为：准备快照 → 有效提交 → 汇聚 → 融合 → 剥离 → 飞行 → 铺展 → 交接 → 清理。准备快照不改变任何显示；所有阶段均可进入取消与清理，取消后真实内容由宿主完整呈现。

| 情况 | 处理要求 |
| --- | --- |
| 空发送、校验拒绝或组合输入确认 | 不开始转场，不影响宿主提示 |
| 目标挂载迟于预期 | 在飞行前限时等待；超时取消装饰、恢复已接管文字，标记为目标就绪失败 |
| 网络发送失败 | 不删除、不恢复或重发草稿来配合动画；保留宿主失败与重试提示，必要时终止转场 |
| 相同文字连续发送 | 按提交身份分别关联，不能按内容去重；不得合并成一滴 |
| 快速连续发送 | 每条提交独立，建议最多同时呈现两条转场；超出预算时优先恢复真实消息，不排队延迟发送。并发上限为待验证设计值 |
| 滚动、缩放、窗口变化 | 小幅目标移动可在剩余路径中平滑重定向；大幅移动、目标出视口或源被销毁时取消并恢复，不能瞬移追逐 |
| 切换会话、关闭面板或卸载 | 立即取消相关转场、恢复呈现并释放全部快照与节点，不飞向另一会话 |
| 用户继续输入 | 不接管新草稿，旧快照与新内容隔离 |
| 用户操作目标消息 | 立即交回真实内容，不让装饰层拦截操作 |
| 效果开关关闭或系统改为减少动态 | 停止形变与位移，直接交还真实消息，保留基础反馈 |

异常取消是保护真实交互的兜底，不是可替代完整阶段的正常交付路径。普通支持场景应稳定走完完整转场；异常命中率应在验收中单独记录，不能混入成功率。

## 8. 内容、性能与可访问性边界

视觉副本设置 aria-hidden，装饰层 pointer-events:none，不重复朗读用户文字；真实消息语义、键盘焦点和屏幕阅读器通知由宿主保持。减少动态下不播放汇聚、液化或飞行，直接使用宿主呈现与基础发送确认。

文字与排版快照仅在本次转场内存中存在，不写 localStorage、日志或诊断输出，不上传渲染服务。清理时释放文本、字形、几何信息与动画对象；诊断仅记录阶段、取消原因、耗时和节点数量。

不引入常驻动画循环，不为准备转场持续扫描全文。几何读取集中在快照、目标就绪和必要的位置变化时机；动画期间不逐帧重排编辑器或消息列表。可见字素过多时应采用分组渲染和裁剪策略，但保留逐字/逐行汇聚与还原的可见差异，不能偷换成整段缩小。

性能初始验收预算为：转场不引入可归因的超过 50ms 主线程长任务，在约定基准设备正常负载下以 60fps 为目标；滤镜区域限定在转场当前包围区域，不创建全屏持续滤镜。预算需在真实客户端测量并写明设备与文本规模，不能用独立空白页的帧率代替。若预算与最终效果冲突，应记录具体瓶颈并调整渲染实现，不能静默删掉必要阶段。

## 9. 验收方式与通过条件

正常场景至少覆盖中文短句、多行中英文、emoji/组合字符、长文本滚动视口、Markdown 文本和重复内容连续发送；同时覆盖鼠标与宿主支持的键盘发送、深浅主题、强度档位和减少动态。

| 编号 | 验收点 | 必须提供的证据 |
| --- | --- | --- |
| A1 | 源端原位接管 | 输入框原画面与转场首帧对齐；慢放无空白帧、无重复文字 |
| A2 | 文字独立汇聚 | 连续采样显示多个字素/行具有不同位移；整段矩形缩放不通过 |
| A3 | 字形连续液化 | 高帧率录屏及关键阶段帧，融合过程中不存在文字层消失后换滴的断点 |
| A4 | 细颈剥离 | 可见连接、拉长、断开、残留回收的顺序；不得只录飞行部分 |
| A5 | 精确关联目标 | 提交身份到用户消息身份的验证结果，包含相同内容连续发送；证据中不保存正文 |
| A6 | 水滴铺展为文字 | 慢放可见轮廓分化、文字展开并归位，不能以整条消息淡入替代 |
| A7 | 最终无缝交接 | 末帧副本与真实消息位置、排版一致；无重影、跳字、残留遮罩 |
| A8 | 业务与交互不受影响 | 开关前后发送次数、文本、顺序一致；选区/IME/继续输入与失败重试保持原行为 |
| A9 | 异常可恢复 | 每一种取消路径均验证真实文字恢复、装饰不残留、快照和动画释放 |
| A10 | 性能与无障碍 | 真实客户端性能记录、布局稳定证据、减少动态与辅助语义检查 |

静态截图、动画对象存在、CSS 参数变化均不能单独证明这条转场达标。必须在真实 DSH 客户端录制完整发送过程，并对汇聚、融合、剥离、落地展开分别慢放检查。独立渲染验证可用于定位工程问题，但不是正常场景的替代交付。

## 10. 接下来的工程工作

本需求不拆成低配产品版本。实现可以按依赖组织：先核实提交关联和源/目标交接能力，再完成文字几何与液体连续变形，最后把完整链路接入真实客户端。各环节在同一目标下验证，交付时统一按 A1–A10 判断。

需要在工程设计中补齐的证据包括：公开宿主入口、准确的本次消息映射、Markdown 源/目标几何策略、可逆接管方式、临时滤镜/轮廓渲染方案与基准性能。当前文档没有将这些事项标为已实现。

水体颜色按 2026-10-22 用户修正，使用冷色透明水感与白色高光，不随品牌红变红。水感通过透明度、渐变与高光近似，不宣称具有真实背景折射。

## 11. 候选模式（2026-10-22 追加）

用户提出把"回车发送"的转场做成**可在设置中选择的多版本**。骨架不变：只读快照 → 落点关联 → 接管真实气泡 → 飞行 → 还原交接；差异只在**渲染层**与**形态**。

| 模式 | 形态 | 复杂度 | 运行开销 | 状态 |
| --- | --- | --- | --- | --- |
| `liquid` | 现有水滴：汇聚 → 液化 → 融入边缘 → 剥离 → 弧线 → 铺展 | 已实现 | 需要局部 SVG 滤镜，当前最贵 | 已实现 |
| `dissolve` | 文字消解/文字合成：源端逐字上浮淡出，目标端整层从 blur 解析成形（参考 React Bits Blur Text） | 低（约水滴 1/5） | 仅逐字 transform/opacity + 一层 blur，无 SVG | 已实现（默认模式） |
| `ghost` | 小幽灵：红色半透明圆润幽灵从输入框升起，摇摆飞向消息位置，抵达后化成文字 | 低到中（约水滴 1/3） | 单个精灵 + 关键帧，无滤镜 | 已实现（原型见 `docs/demo/ghost.html`） |

设置形态：发送转场改为**枚举**（`off` / `liquid` / `dissolve` / `ghost`），保留"关闭"以满足 C6 的可关掉约束；旧设置 `sendTransfer: true/false` 分别迁移为 `liquid` / `off`。

七阶段的要求只约束 `liquid`。`dissolve` 与 `ghost` 仍须满足：不改写宿主内容、可逆接管、落点必须是本次提交对应的消息、无双影与背景残留、异常可恢复、减少动态下不播放并交还真实文字。
