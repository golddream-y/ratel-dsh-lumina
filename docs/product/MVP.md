## 2. 动效改编清单

改编依据是**依赖**：零依赖的可改编代码，带 `motion` / `gsap` 的只取思路、用平台原语重写。

| 我们的效果 | 上游组件 | 上游依赖 | 取什么 | 丢什么 | 改编量 | 需登记 |
| --- | --- | --- | --- | --- | --- | --- |
| M1 品牌字标流光 | **ShinyText** | 无 | 光带渐变停靠点的生成（带宽 × 柔度 → 多 stop）、多光带、`glow` 模糊副层 | `background-clip: text`（SVG 无此属性）、rAF 逐帧驱动 DOM、React 组件壳 | 中 | ✅ |
| M2 边框流光 | **BorderGlow** | 无 | `mask-composite` 挖空、多层渐变堆叠、光晕柔化 | 指针驱动（`--edge-proximity` / `--cursor-angle`）——我们是被动环绕 | 小～中 | ✅ |
| M3 打字机光标 | TextType | `gsap` | 光标呼吸的 CSS 曲线 | GSAP 状态机、打字逻辑 | 极小 | ❌ 只需抄几行 CSS |
| M4 按压 + 闪光 | Magnet | 无 | 弹簧刚度/阻尼比，用作 `cubic-bezier` 调参依据 | 指针磁吸、物理循环 | 小 | ❌ 只调参 |
| M5 首屏入场 | BlurText | `motion` | 模糊→清晰的 keyframe 结构与错落延迟 | `motion/react` | 中 | ❌ 纯 CSS 重写 |
| M8 会话进行中 | **Orbit**（仅视觉参考） | 无 | 环绕光点、呼吸节奏 | 组件壳、多元素堆叠 | 小 | ❌ 原创 CSS，不复制 |

**明确不采用**：`ClickSpark`、`ElectricBorder`、`StarBorder`、`SpecularButton`、`SwarmCursor` ——
Canvas / WebGL 路线，与"只动 transform/opacity、零运行时依赖"冲突。

### 2.1 参数基线（实施用）

旧稿删除前把仍需要的参数迁移至此；与 PRD 冲突的项已按 PRD 修正
（`deepseek` 为默认预设、变量只发布在 `[data-lumina]` 作用域、不写主题选择器）。

| 用途 | 基准 | subtle | vivid |
| --- | --- | --- | --- |
| 品牌流光周期（70% 静止） | 9s | 14s | 6s |
| 边缘呼吸 | 3.6s | 4.8s | 2.8s |
| 发送时旋转一周 | 2.4s | 3.6s | 1.68s |
| 光标呼吸（块光标） | 1.15s | 1.6s | 0.85s |
| 流式光标 | 0.72s | 1.0s | 0.55s |
| 按钮按压 | 140ms | 180ms | 110ms |
| 首屏入场 | 320ms | 420ms | 240ms |
| 发送光环 | 360ms | 420ms | 280ms |
| 会话环绕一周 | 2.4s | 3.2s | 1.8s |

完整 token（含 focus / stream / glow 派生值）见
[技术详细设计 §6.2](../engineering/技术详细设计.md)。

缓动：入场 `cubic-bezier(.22,1,.36,1)`；回弹 `cubic-bezier(.34,1.56,.64,1)`；
边框/流光/环绕 `linear`；光标/呼吸 `ease-in-out`；闪光 `ease-out`。

品牌变量（`deepseek` 预设，只在 `[data-lumina]` 作用域发布）：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--lumina-brand` | `#FF3B30` | 图标、字标、发送闪光 |
| `--dsw-alias-brand-primary-new-colorprimary-new-color` | `#4176e6` | 输入框边缘、光标（官方蓝） |
| `--lumina-brand-soft` | `#FFB3A8` | 流光渐变浅端 |
| `--lumina-brand-deep` | `#8C1D12` | 字标肩部 |
| `--lumina-brand-rgb` | `255, 59, 48` | `rgba(var(...), α)` |

### 2.2 实现注记（旧稿踩坑项）

- **品牌**：必须内联 SVG，不能用 `<img>`；流光用 `<mask>` 重新填字，不能用 `clip-path` + 白块；
  `<use>` 在 `<mask>` / `<clipPath>` 内不生效，必须展开 path；渐变用 `objectBoundingBox`；
  同一资产挂多处时用 `useId()` 给 id 去重。
- **边框**：以 README 宣传图的左暖右冷、细亮边和柔光为视觉目标；闲置时边缘呼吸，聚焦后高光环绕，流式时加速。宣传图中延伸到框外的大幅光带不在实现范围。装饰层 `pointer-events: none`；`@property` 不支持时降级为静态双色环
  （不旋转整块，避免圆角错位）；只用 `[data-composer-card]`，禁止 `[class*="…"]`。
- **光标**：两段，共用一个 `caret` 开关（M9 不新增开关）：
  1. 流式末尾：`[data-streaming]` 最后一个文本块上挂 2px 品牌竖线，随流式结束消失；
  2. 输入框：自定义 overlay 跟随折叠选区，overlay 可见时 native caret 透明；
     失焦、选区非折叠、IME 组合输入时立即摘掉 overlay 并恢复 native caret；
  3. 两段都只动 opacity/transform、不改宽高与位置；最低透明度 0.35；末尾不得换行或遮字。
- **按压 / 首屏**：禁用态无反馈；连续发送闪光不叠加；首屏只在空会话播放。

### 2.3 M8 · 会话进行中指示（替换原生 spinner）

**现状**：侧栏 session 行在运行中渲染一个 14×14 的 SVG spinner
（`data-state="ongoing"`，淡轨道 + 短弧，1.5s 旋转 + dash 呼吸）。通用、灰色、与 Lumina 无关。

**替换为「品牌轨道光点」**：

- 保留原生 SVG 与语义（`aria-hidden` 与屏幕阅读器标签不动），只改视觉；
- 淡轨道改为品牌色 16% 透明圆环；
- 短弧改为约 3px 的圆点（`stroke-dasharray`），绕环 2.4s 匀速；
- 整枚图标 2.4s 呼吸（`opacity .82 → 1`）；圆点用品牌色，不加持续 `filter` 光晕；
- 定位：`[data-row-key^="session:"] svg[data-state="ongoing"]`，只命中 session 行；
- 不新增 DOM、不改 14×14 尺寸、不拦截点击；
- 减少动态：停止环绕与呼吸，保留静态品牌环 + 顶部光点。

**强度**：环绕 2.4s（normal）/ 3.2s（subtle）/ 1.8s（vivid）。

**为什么不是别的**：

- 脉冲圆点（sonar）在 14px 下与 idle / done 状态点混淆；
- 彩色 shimmer 文本会改变行布局，且与官方的 `ShimmerText` 重复；
- 直接去掉 spinner 会让「进行中」失去可见信号。

**性能**：替换而非新增动画。每条运行中的 session 仍只有 2 个动画
（官方为 `rotate` + `dash` 两条，替换后为 `rotate` + `opacity` 两条），多行并行时与官方持平。

## 3. 改编期同样适用的硬约束

改编**不豁免**任何产品边界与工程约束：

1. **零运行时依赖**——不得引入 `motion` / `gsap` / `three`；上游组件依赖它们时，只取思路重写
2. **只 `require` 模块表内的 specifier**——其余必须打进 bundle；引入大库会让包体从 12KB 涨到数百 KB
3. **保留原始版权头与许可声明**，不删不改
4. **每完成一个改编就立刻登记** `THIRD_PARTY_NOTICES.md`，不留到最后
5. 改编后的实现仍须满足：只改时间维度、封闭集合、可完全关闭、不承载信息

## 4. 实施顺序

实现落位、接口契约与测试门禁见 [技术详细设计](../engineering/技术详细设计.md)。

顺序由依赖决定，不按效果编号：

1. **适配层 L1** —— 架构设计 §13 指出的缺失项。六个效果都要靠它，先做能省五次返工
2. **品牌动效** —— 资产已完备（`assets/deepseek-harness-logo-v2.svg`），零依赖，最稳的起点
3. **边框流光** ← BorderGlow 的遮罩叠层
4. **打字机光标** ← TextType 的 CSS 曲线
5. **按压 + 闪光** ← Magnet 的弹簧参数
6. **首屏入场** ← BlurText 的 keyframe 结构
7. **会话进行中** ← Orbit 的环绕光点思路（只改原生 SVG，CSS 即可）
8. **设置页 + 诊断** —— 收口

每一步都必须留下可执行证据（见 §6），不允许"代码看起来对"。

### 2026-10-22 · 统一交互节奏

选型确认采用轻按压与单次发送光环、短淡入与首屏小位移。菜单过渡并入现有 press 开关，不新增设置字段；仅匹配已验证的 MenuSurface 数据钩子。菜单只淡入，保持宿主定位与固定子层的坐标关系，不添加关闭延迟。原生折叠、侧栏与详情面板不在本轮叠加动画。

发送点击即时确认，随后流式开始不再重复播放；编辑器键盘发送由流式开始补一次反馈。普通按钮轻按压，不产生光环。取消整张输入卡片的发送闪光。输入时光标常亮，停顿后恢复呼吸；移除逐键与流式文本变化光环，不再观察模型文本。品牌扫光增加静止间隔，输入聚焦或流式输出期间暂停。首屏仅品牌槽淡入与 4px 小位移，不包装正文。


2026-10-22 用户确认：M2 默认不发光、不呼吸，聚焦输入框后才出现柔光与真实沿边光带，失焦恢复。M2 从页面常驻改为聚焦条件动效；采用 offset-path:border-box，不再依赖角度渐变呈现流动。


2026-10-22 最终视觉修订：默认保留静态红蓝混色细边，不发光、不呼吸。聚焦后宽幅流光融在连续边缘内，取消独立轨道小光点；失焦保留混色细边并去掉光晕。采用 background-position 迁移，与 README 图中的舒展边缘光感对齐。


## 后续需求：发送文字水滴转场

发送转场已从单一水滴扩展为四态（关闭 / 水滴 / 文字消解 / 小幽灵），见 [发送转场需求设计](发送转场需求设计.md)。三种模式共用接管、落点与交接规则，默认水滴；水滴保留完整七阶段。

## 发送水滴实现版（2026-10-22）

设置项为 `sendTransition` 枚举（默认 `liquid`），旧 `sendTransfer` 布尔值迁移为 `liquid` / `off`。三种模式共用只读快照、气泡接管、回声优先的落点关联与可逆交接；只有渲染层不同。发送转场不延迟真实发送。

只使用公开 `sessions` 与 `uiConversation` 只读快照，以 pending 的 `requestId` 和用户节点的 `source.rpcId` 对应落点。缺少服务或不能唯一关联时不接管文字。客户端实测完整录屏前，不将受控页面证据标记为真实客户端验收。

### 水滴与输入框液面修正（2026-10-22）

上一版只从文字中心拉出液滴，没有经过输入框边缘的液面，且直接沿用品牌红。按用户修正，完整过程调整为：文字汇聚成滴 → 抵达输入框上边缘 → 水滴完全融入局部液面 → 液面重新鼓起 → 拉出连着液面的细颈 → 断开后飞向对应消息 → 铺展还原。必须存在肉眼可见的“已吸收、尚未重新突出”时段，不能让同一个独立水滴直接穿过边框。

水体改用客户端冷色语义 token 与白色高光，独立于品牌红；这是用户明确要求的颜色例外。只在发送期间出现局部液面和折射感轮廓，不改变默认不发光、聚焦才发光的输入框规则。
