# 流光发送需求

更新日期：2026-10-26。流光发送、首次发送布局归位与目标消息整行接棒已随 0.7.0 发布，并设为新安装默认模式。现行发送交接链路已完成；早期更细的源端形变、变速和距离适配设想保留为历史探索，不作为当前待办或 1.0 发布缺口。以下动作表包含早期目标，实际交付见文末实现状态及[功能实现状态](功能实现状态.md)。

本文记录流光发送模式的目标、交接规则与迭代过程，不将历史探索自动转为新增需求。与[发送转场需求设计](发送转场需求设计.md)共用有效提交、消息身份关联和可逆交接规则；按钮水纹继续遵循[发送反馈设计](发送反馈设计.md)。

## 1. 目标与范围

一次发送像把一缕流光从输入框送入消息：文字轻微收束，局部光绸从输入框边缘牵出，沿柔和曲线流向对应消息，尾部持续收进目标，真实消息随之落定。需要明确感到流光在传递内容，同时保持日常发送的利落。

本轮新增「流光」选项，与水滴、文字消解、小幽灵并列。默认发送动效改为流光；已有有效模式选择保持不变，不自动迁移用户设置；关闭发送转场仍按宿主原样显示。内部枚举为 `flow`，设置显示「流光 / Light flow」。

只覆盖一次有效的用户文字发送，不扩展到助手回复、侧栏运行状态或新会话入场。附件只发送暂不播放文字转场，按钮水纹仍按有效提交独立反馈。

## 2. 流光的形态

当前采用的共享丝带美术源已获用户认可，作为本轮视觉基准：保留冷暖透色、宽面翻卷、薄边与局部聚光。接下来优化源端、沿途与消息的衔接，不重新设计材质，不增加亮度、光球或装饰粒子。光绸的前端亮面、带身与尾部应保持连续，不出现单独的飞行物。

| 部位 | 视觉要求 |
| --- | --- |
| 前端 | 短而集中的柔软亮面，融入带身；没有圆球、水滴、箭头或星形轮廓 |
| 带身 | 两三缕主带面宽窄交替、轻微翻卷，局部互相遮叠；细光丝只补充层次 |
| 尾部 | 从输入框逐渐牵出，变细、变淡；前端抵达后，尾部继续沿路径收进消息 |
| 材质 | 半透明冷色带面、清晰的局部白色薄边、少量暖色反射；交叠处有层次，中心不过曝 |

参考 README 顶图中的透明丝带材质，转化为适合短距离发送的局部光绸。页面环境光带的长跨度、背景泛光和地面倒影不属于发送效果。

明确排除星星、星芒、星点喷射和到达爆闪；也不使用笔直激光、均匀霓虹线、实心彩条、密集平行线或大面积模糊拖尾。短光绸不能退化成一颗亮点带着尾巴。

## 3. 动作编排

本轮目标是将「文字交给光绸，光绸交给消息」连成一个连续动作。总时长仍以正常档约 600 ms 为调试基准，不因增加衔接细节整体加长。下表保留早期讨论的初始时间安排，已交付版本的实际时序见文末记录；到达与交接必须由同一进度驱动，不能由互不相关的计时器凑合。

| 阶段 | 时间初值 | 动作与衔接 |
| --- | --- | --- |
| 源端交棒 | 0–120 ms | 文字作为整段轻微收拢并向临近框边靠近；光绸根部约从 40 ms 开始形成，与文字退去重叠。文字完全退去前，起始亮面已清楚可辨 |
| 牵出与输送 | 80–420 ms | 光绸从同一根部牵出；离框稍缓、中段加速、接近目标柔和减速。前端、带身与尾部连续传递，不停顿或机械匀速滑行 |
| 到达与收尽 | 约 420–560 ms | 前端先进入消息靠近源端的一侧，随后尾部继续收进同一落点。源端先收尽，路径逐段缩短，不整条同时淡掉，也不在目标旁悬停 |
| 消息接棒 | 到达时开始，约 420–600 ms | 前端进入后，整条消息逐渐显现，与尾部收尽重叠；背景和文字一起落定，只轻微舒展，不弹跳。光绸消退后不再补出背景或重播文字 |

### 源端必须连得上

起始亮面与本次实际文字区域、框边根部构成连续交接。不能先让文字消失，再从无关位置发射特效；不能先出现一根独立光带，再让文字突然消失。长段落仍整段收束，不把每个字变成光点，也不将整段压缩成小球。已有发送按钮水纹继续独立反馈。

### 沿途必须有轻重

出框稍缓，中段顺势提速，接近消息减速，但前端不能减速到悬停。带内反光沿传递方向流动，带面翻卷保持克制；不得大幅左右摆动、折返或以加长尾巴掩盖速度断点。尾部回收有自己的连续进度，前端到达后仍有一小段光绸自然流入。

### 目标端必须接得住

落点位于对应消息靠近源端的一侧，通常是气泡的左下侧，具体取决于实际布局；落点应避开文字主体，不固定落在消息文字中心。光绸与消息相接时开始显现整条消息，不等光完全消失后再显示。边缘反光随收尽减弱，不增加星芒、爆闪或额外光环。

气泡背景、边缘与文字必须一起考虑。禁止文字先出现、背景最后一帧突然补上；禁止副本与真实消息叠出双重背景、重影或文字跳位。无气泡背景的宿主布局按真实整条消息交接，不凭空添加气泡。

### 时间不等于业务等待

600 ms 只约束视觉编排，消息请求与宿主业务状态照常推进。目标未就绪、无法可靠关联或空间不足时恢复普通显示，不悬停等待、不循环、不排队补播。一次发送只经历一次源端交棒和一次消息接棒。

## 4. 路径与尺寸适配

源端以本次实际文字位置为依据，向临近输入框上边缘收束，不统一从发送按钮发射。终点取本次提交关联消息的可见边缘，按源端方向选取进入侧；不得再默认使用字形中心。目标身份仍按提交关联，不靠最后一条消息或相同文本猜测。

常见构图从输入区域左侧向对应消息右上方流动，但方向服从实际源点与目标点。采用连续柔和的单弧或浅 S 曲线，避免尖角和突然转弯。光绸在框边短暂贴合、牵出，不增加水滴模式的融入液面、拉颈和断裂阶段。

- 短距离降低弯曲幅度、带宽与尾长，并压缩中段输送时间；保留源端和消息接棒所需的可辨时间，避免所有阶段同时挤成闪光。不能绕远路展示效果。
- 长距离让路径适度舒展，避免拉成细线；总时长保持约 600 ms 的基准，不随距离线性增长，也不按距离放大亮度。具体距离分档在真实尺寸原型中确定。
- 长文字、多行和中英文混排均按整段排版交接，不随字数增加粒子、路径或动画时长。
- 窗口缩放和尺寸变化不能造成源端或终点偏移、带面拉扁、裁切露白；播放中几何失效时取消转场并恢复真实内容。
- 带面宽度、尾长、曲率与强度档的具体数值在真实尺寸原型中确定，不以放大近景代替客户端效果。

## 5. 与现有效果协调

按钮水纹负责即时确认，流光负责源文字到消息的衔接，两者独立去重，每次有效发送各最多播放一次。水纹不能因流光接管而消失，也不能在转场回退时再次播放。

新会话环境丝带继续遵循聚焦显隐规则。发送光绸是独立的局部转场，不将整条环境丝带搬向消息；离开发送后，不留下循环尾迹。需要避让时仅临时收敛输入框附近的亮度，不让整页闪烁或改变用户开关。

水滴维持当前定版形态与七阶段；本轮不修改其时长、材质、默认状态或设置迁移。流光的视觉验收独立进行。

## 6. 触发、交接与中断

- 只在本次有效提交确认后播放一次；Enter、点击和本地回声的多路通知不能重复触发。换行、IME 确认、禁用按钮、停止生成不触发。
- 沿用提交身份关联的目标定位；气泡不能先闪现，再隐藏并重播。副本按真实排版与消息交接，不复制另一条可交互消息。
- 目标缺失、身份歧义、渲染失败、用户滚动导致落点变化、切换会话、页面隐藏、关闭效果或卸载时，立即恢复真实内容并清理装饰。
- 连续发送分别关联各自消息，不跨消息连接；资源不足时跳过装饰，不能排队补播、延迟发送或隐藏真实消息。
- 装饰保持点击穿透，不影响输入、选中、滚动、设置操作或窗口拖动，不修改业务请求和内容。
- 系统启用减少动态时不播放收束、飞行和形变，直接显示真实消息；按钮可保留既有静态反馈。

## 7. 验收顺序与标准

先制作与正式实现共用核心绘制的独立动态原型，确认后再安装客户端。原型必须同时提供真实发送尺寸与近景，支持正常速度、慢放、暂停、重播和时间拖动，并展示源端、目标与输入框的空间关系。

1. **静止形态**：浅底和深底均能辨认透明带面、薄边和交叠；前端没有星星、球体或水滴，亮处不糊成一团。
2. **源端连续性**：文字退去与根部形成有明确重叠，无「文字已经消失、流光还没出现」的空档；出发位置和本次文字有关。
3. **沿途连续性**：正常速度能辨认缓出、加速、柔和减速，前端到达后尾部继续收进目标；慢放无停顿、整图平移或同时淡出。
4. **目标交接**：前端进入目标边缘时，整条消息开始显现；尾部收尽与消息显现重叠。背景、边缘、文字一起落定，不补闪、不重影、不二次跳动；短句、长段、多行和相同文字连续发送均正确关联。
5. **真实布局**：新会话首次发送、已有会话发送、不同窗口比例、客户端缩放和深浅主题分别核对；不能只验收宽屏近景。
6. **中断与性能**：减少动态、切换会话、滚动、关闭开关和异常恢复无残留；无常驻绘制循环，不增加随字符数增长的粒子或滤镜。记录真实客户端的帧间隔与长任务，再判断流畅度，不提前承诺固定帧率。

默认模式改为流光，水滴仍作为可选模式保留。实现状态、受控验证与原生视觉验收分别记录，不将原型通过等同于客户端验收或正式发布。

## 8. 方案取舍

采用柔软亮面带动短光绸，保持 Lumina 已有的透明丝带语言。星星会引入独立角色感，笔直光束缺少带面与柔顺变化，单点拖尾容易变成弹道；以上方案均不采用。绘制后端、缓存方式与性能预算由下一步技术设计确定，本需求不预先锁定 WebGPU 或 SVG。

## 首次发送的布局交接

新会话首次发送会从居中输入框切换为底部输入框，必须作为独立场景纳入源端交棒。发送前文字快照、迁移后的输入框与目标消息不能混用不同布局时刻的坐标；既不能让流光留在旧位置，也不能将起点直接改到底部造成凭空出现。已有会话中输入框持续置底的路径保持独立。布局迁移期间采用下述同步归位方式交棒；不操纵宿主布局、不延迟业务提交。输入框移动、重新挂载及已有会话不迁移均须单独验收。


## 首次发送布局交棒方案

首次发送保留提交前的文字与输入框矩形快照。宿主提交最终置底布局后，插件仅用可撤销的translate将当前真实输入框从原位置平滑归位，文字副本同步移动；随后从底部真实框边播放原600 ms流光。不复制输入框、不改宿主布局或请求，输入框迁移动作约180 ms；检测提交布局使用不超过96 ms的短窗口，已有会话不增加等待。

兼容同一输入框迁移和输入框重新挂载：只在首次发送、同一提交上下文中关联唯一可见输入框，歧义、尺寸差异过大或接管失败时直接恢复普通消息。迁移结束后冻结新的源端坐标，飞行时不追逐输入框。中断必须恢复translate、真实文字和消息。减少动态不播放迁移或飞行。先覆盖启动前迁移、启动后迁移、重新挂载、普通发送及取消恢复，再本地安装。


### 首次发送实现状态

首次发送（包含预分配ID但尚无消息的会话）已接入同步归位：只保存文字和输入框提交前几何，不改业务提交；关联唯一可见的新输入框，以可撤销translate与文字副本同步移动，归位后冻结底部锚点并开始flow。已有消息的会话保持原600 ms节奏。97项测试通过，实际bundle验证启动前/后移动、启动前/后重新挂载及中途取消六组场景；普通flow和liquid回归通过。证据放本地忽略目录，原生客户端最终表现待用户重启确认。该现行交付链路已完成；更细的形变与变速设想不再列为待完成项，目标端状态见下方实现记录。

迁移开始时清理仍停留在旧按钮位置的短水纹，防止反馈悬空；不重复补播水纹。


### 目标端接棒实现状态

flow现从对应消息靠近输入框的可见边缘进入；按背景实际边界选择进入侧，无背景时使用文字区域边缘。前端约420 ms到达，真实消息整行从此时逐渐显现，尾部约560 ms收尽，600 ms恢复常态。目标端不再绘制字形副本，背景、边缘与文字共同显现，保留宿主原有排版和transform。

99项测试通过；实际bundle的14帧验证确认中间帧真实消息透明度介于0和1、无目标文字副本，并覆盖半显现时的缩放、窗口变化、减少动态及节点替换后完整清理。首次发送六组归位场景回归通过。该目标端接棒已随 0.7.0 发布；受控验证不替代原生客户端视觉确认。


## 默认模式（2026-10-25）

按用户要求，首次安装、恢复默认以及缺失或无效模式值均选择flow。已有有效选择（包含liquid和off）不被覆盖；旧布尔sendTransfer的兼容行为保留，不擅自改变旧用户的明确设置。
