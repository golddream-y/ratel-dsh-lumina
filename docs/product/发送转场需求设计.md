发送转场是**一个效果、五种状态**：`off` / `liquid`（水滴）/ `flow`（流光）/ `dissolve`（文字消解）/ `ghost`（小幽灵）。四种模式共用同一套接管、落点与交接规则，只有视觉呈现不同；设置里五选一，默认 `flow`。

本文定义**最终想要的画面**、共通行为、三种模式的差异、参数初值与验收标准。实现细节见 [发送转场实现与验证](../engineering/发送转场实现与验证.md)。

## 1. 共通规则（三种模式都必须满足）

### 1.1 触发

- 鼠标点击发送、触摸、宿主支持的键盘发送（Enter）都进入同一条转场；
- 空内容、校验拒绝、普通回车换行、IME 组合确认、停止生成、重试助手输出**不触发**；
- 一次提交只播一次；相同文字连续发送按提交身份区分，不按内容去重；
- 动画不延迟真实发送，不改变消息内容、会话滚动与发送状态。

### 1.2 接管顺序：气泡必须先消失

真实消息（或本地回声）由宿主在提交时创建。转场必须在这个窗口内接管：

1. 捕获到发送手势的那一刻，开始观察会话区；
2. 新的**本地回声**（`[data-submission-echo]`，排除队列面板里的同属性行）一出现就立刻隐藏；
3. 提交确认后，隐藏**整条消息行**（`[data-submission-echo]` / `[data-chat-node-key]` / `[data-chat-flow-key]`），背景与文字一起消失；
4. 然后才开始汇聚/消散/起飞。

**不允许**：气泡先亮出来、再被遮罩、再开始动画。用户读到的顺序必须是「气泡消失 → 文字开始动 → 转场」。

### 1.3 落点身份

- 优先用本地回声（提交当帧存在，且属于刚确认的 requestId）；
- 回声被 durable 节点替换后，用 `rpcId` 关联真实用户消息；
- 落点不能靠"文字相同"或"最后一条消息"猜测；歧义时**不播**，回退到普通反馈；
- 首次命中时冻结落点坐标与副本字形，后续元素替换只补遮罩、不改落点。

### 1.4 交接与清理

- 副本 `aria-hidden`、`pointer-events:none`，不重复朗读；
- 视觉隐藏（遮罩、临时属性）必须绑定清理句柄：取消、异常、开关关闭、卸载、减少动态都立即恢复真实内容；
- 结束时副本与真实文字在同一呈现时机交换，无重影、无跳字、无残留遮罩；
- 用户操作目标消息或切换会话时，立即交还真实内容。

### 1.5 减少动态与性能

- `prefers-reduced-motion: reduce` 时不播放位移、形变与飞行，直接交还真实内容，只保留即时状态；
- 不引入常驻动画循环；滤镜只在必要的小区域使用（水滴的 alpha 融合是唯一例外），并带帧预算守卫；
- 目标性能：60fps、无 >50ms 主线程长任务；真实客户端测量，不用空白页代替。

## 2. 模式一：水滴 `liquid`

保持既有七阶段，不拆低配版：

```text
文字汇聚 → 融合成滴 → 融入输入框上边缘液面 → 液面重新鼓起拉出细颈
→ 细颈断开 → 弧线飞行 → 抵达压扁铺展 → 逐字还原
```

- 水体使用独立冷色 token + 白色高光，**不继承品牌红**；
- 必须存在"水滴完全消失、只剩液面"的间隔，不能直接穿过边框；
- 细颈连接 → 拉长 → 断开 → 残回收，顺序可见；
- 落地按目标真实排版逐字展开，不能整条消息淡入；
- 与发送光环互斥；聚焦流光在汇聚/剥离期间暂停，脱离输入框后恢复。

当前实现：局部 SVG alpha 融合，滤镜只作用于液体形状组；帧预算守卫会在连续掉帧时摘掉滤镜。

## 3. 模式二：文字消解 `dissolve`

参考 React Bits **Blur Text** 的"模糊 → 清晰"，但拆成两幕、有重叠：

### 3.1 两幕

| 阶段 | 时长（normal） | 画面 |
| --- | --- | --- |
| 第一幕：源端散开 | 0–720ms | 输入框里的每个字**各自**上浮、缩小、淡出；整层叠加一层由 0 到 5px 的模糊，越散越糊 |
| 第二幕：目标端解析 | 从落点就绪起 140–700ms | 消息层的文字**整层**从 10px 模糊解析到清晰，同时整层淡入；每个字只做 8px 的错峰上浮，不单独淡入 |

两幕有交叠：源端还在散的时候，目标端已经开始解析，中间没有空档。

### 3.2 硬性要求

- **不许硬切**：每个字必须各自走完自己的曲线到 0；不允许在某个时间点"一次性把剩下的字隐藏"；
- **不许双重视觉衰减**：目标端不能同时做"逐字淡入"和"整层模糊"，否则模糊一散字就"啪"地出现；
- 曲线用 smootherstep（首尾一阶、二阶导为 0），起步和收尾没有顿挫；
- 错峰必须摊在**固定窗口**内（按字数比例分配），长文本也要在转场内散完；
- 模糊只加在**整层**，不逐字加滤镜（性能）。

### 3.3 反例

- 整段文字一起缩小淡出；
- 源端到一个时间点被整体隐藏；
- 目标端文字"弹出"而不是从模糊里长出来。

## 4. 模式三：小幽灵 `ghost`

**核心：凌乱的是披风，不是幽灵本体。** 幽灵要稳稳地飘过去，只有身上那件破披风被风吹得翻卷。

### 4.1 形象

- 半透明红色兜帽幽灵，侧脸朝右上方；两只圆眼、淡腮红和小笑脸，肩部圆润，领口宽松；
- 填充透明度约 `.8 / .62 / .4`（内到外），描边约 `.32`，整体入场再乘 0.9 —— **能透出背景**，不是实心贴纸；
- 主体尺寸约 56px，前侧可带一把不遮脸的小弯镰刀；
- **披风下摆是破的**：约 12 个长度不一的锯齿尖端（有的长、有的短、有的翻卷），不能是规则的四个齿。

### 4.2 本体运动（稳）

- 从输入框边缘升起，沿一条**平滑直线**飘向消息位置；
- 固定轻微前倾约 6°，不来回旋转、不挤压拉伸、不做路径游走；
- 只允许极小的上下浮（约 1.6px），用来避免机械感；
- 全程朝向稳定。

### 4.3 披风（乱）

- 每个尖端用**两组不同频率的正弦**独立抖动，且**逐尖振幅不同**；
- 相邻尖端不同步，形成被风撕扯、翻卷的裙摆；
- 风相位随时间行进 —— 是"一路被吹"，不是原地抖；
- 水平摆动限制在约 ±0.8px，垂直翻卷幅度约 2.2px；破边缩短，以柔软曲线代替细长尖刺。

### 4.4 取字、拖尾与落地

- **取字**：源端文字被幽灵**吸进去**——向释放点收缩、缩小、淡出，不加模糊（避免和消解混淆）；
- **拖尾**：一层淡雾跟在幽灵身后，沿同一条路线滞后约 0.12–0.15 跟随，透明度约 0.22；**雾必须在幽灵身后，不能盖住幽灵**（雾画在前面会让幽灵变成"一团红雾"）；
- **落地**：幽灵淡出，目标文字**整块淡入**（240ms 左右），无模糊、无逐字渐入 —— 与消解明确区分。

### 4.5 反例

- 整只幽灵左右乱晃 / 走波浪线；
- 旋转、挤压、弹跳；
- 拖尾盖在幽灵身上；
- 落地复用消解的"模糊解析 + 逐字浮现"；
- 实心、完全不透明的红色贴纸。

## 5. 设置与默认

发送转场是一个**枚举**设置，四选一：

```text
关闭 | 水滴 | 文字消解 | 小幽灵
```

- 默认 **流光**；
- `off` 时不安装转场桥接，只保留 press 的轻量发送确认；
- 旧设置 `sendTransfer: true/false` 迁移为 `liquid` / `off`；
- 短暂出现过的独立 `mist` 模式并入 `ghost`；
- 切换模式**立即生效**（设置保存会重装效果），不需要重启。

## 6. 验收

### 6.1 共通（A1–A8）

| 编号 | 验收点 |
| --- | --- |
| A1 | 气泡在动画开始前消失；慢放无"气泡先亮再消失" |
| A2 | 源端与目标端无空白帧、无重影、无跳字 |
| A3 | 落点是本次提交对应的用户消息；相同文字连续发送不串 |
| A4 | 取消、切换会话、减少动态、卸载都能恢复真实内容 |
| A5 | 开关前后发送次数、内容、顺序一致；选区 / IME / 继续输入不受影响 |
| A6 | 深色 / 浅色主题下都成立 |
| A7 | 三种模式都能在真实客户端完整播放 |
| A8 | 真实客户端 60fps、无 >50ms 长任务（记录设备与文本规模） |

### 6.2 分模式专项

| 模式 | 专项 |
| --- | --- |
| `liquid` | 七阶段可见；液面吸收与再剥离的间隔；细颈连接→断开；水体冷色 |
| `dissolve` | 逐字散开无硬切；目标从模糊解析而非弹出；长文本 240 字内也能散完 |
| `ghost` | 本体平稳不晃；披风尖端长短不一且独立翻卷；拖尾在身后；落地是淡入不是模糊解析 |

## 7. 未决 / 待调

- 幽灵披风的"凌乱程度"（锯齿数量、抖动幅度、尖端长短差）仍需真实客户端目检后定值；
- 三种模式的真实帧率与长任务需在客户端测量；
- `liquid` 的滤镜区域是否还能再压小；
- `off` 与 `press` 的关系是否需要在设置页文案里说明。

## 8. 历史

- 2026-10-22：从单一水滴需求扩展为四态发送转场；新增 `dissolve`、`ghost`；明确接管顺序（气泡先消失）与披风凌乱的分层要求。

### 4.6 最新形象修订：披着斗篷的侧面幽灵

用户进一步明确：发送方向通常是输入框左侧文字 → 右上方 Chat 气泡，距离较短；形象应是披着披风的幽灵，可以有轻微侧面或斜度。此修订覆盖 §4.1 的正面圆顶和 §4.2 的完全不倾斜要求：

- 改为朝右上方的三分之二侧面；兜帽、内凹脸部、肩部与披风分层，不能仍是圆团上贴两只眼睛。
- 允许稳定的小角度前倾（约 6°），全程不来回摇摆；保持朝向，不随裙摆变形挤压头脸。
- 披风从肩部向左下方拖出，破边使用约 12 个真正的尖端及曲线翻卷，长短不一；风感集中在下半部。
- 从源文字附近取字，文字逐字收向幽灵，统一在固定窗口内完成，长文本不允许硬切或消失后重现。
- 消息必须等幽灵抵达后才整块淡入，所有字已经位于最终排版位置；不做逐字移动、缩放或模糊解析。

后续形象补充：侧身角度认可，保留；整体仅轻微前倾（约 6°）。脖子下方放松为宽松领口与圆肩，不收成紧颈或细腰。表情更柔和可爱，披风破边缩短、以柔软翻卷代替细长尖刺。可加一把轻巧的小弯镰刀在前侧，不能遮脸或压过主体。

### 4.7 已确认形象：头身一体的圆润幽灵

用户确认最新效果图，并授权实现飘行动效。此版覆盖 §4.1、§4.3、§4.6 中独立兜帽、领口和 12 个破边尖端的旧要求：

- 头身用一个连续轮廓绘制；脸嵌在上半部，头到前襟不收颈，背部不出现肩线或折角。
- 前襟完整垂到下摆，后侧向左下轻飘；底边改成约 4 个柔软波瓣，保留完整、饱满的布面。
- 保留认可的侧脸、圆眼、小笑脸、半透明珊瑚红及前侧小镰刀；整体固定前倾 6°。
- 飘行沿原有平滑路线，身体不摇摆；下摆和下半部褶皱以小幅连续曲线翻卷，头脸及完整前襟保持稳定。
- 沿用固定窗口取字与抵达后整块文字淡入。减少动态时不启动装饰转场。

转绘修订：布面补宽以恢复已确认效果图的饱满轮廓，起飞至落地始终保持相同比例，落地只淡出，不横向压缩。

### 水滴与文字消解的表现隔离

用户反馈水滴仍像混入文字消解，要求水滴成为默认效果。水滴取字与落地改成整段文字的连续几何收拢、展开：字形之间保持排版关系，不逐字错峰、不旋转、不各自上浮或变色，也不使用文字层模糊解析。液体形状自身的融合滤镜保留。文字消解仍保留独立的逐字散开与模糊解析。默认配置及缺失、无效模式回退为 liquid；已保存的有效模式不自动覆盖。
