# 面板与会话列表动效设计

更新日期：2026-10-27。运行星河、分组折叠与左右整体面板过渡已随 0.4.0 发布；调度与预算优化已随 1.0.0 发布。居中弹框、已验证原生菜单及提示浮层的进退场及 session 选中底板交接已随 1.0.0 发布；空闲柔光尚未定案。会话运行光团及外围柔光已于 2026-10-27 视觉定稿，需求和实现前设计已保存，尚未实现或发布。下文保留原设计与迭代记录，早期“当前待实现”不代表今日状态；汇总见[功能实现状态](功能实现状态.md)。

## 一、全局面板

统一面板收起、展开、弹框和菜单的方向、时长与中断规则。设计适用于整个客户端，接入需逐个核对宿主钩子，不用无差别全局选择器覆盖所有弹层。

| 交互 | 建议表现 | 正常档初始时长 |
| --- | --- | --- |
| 左右面板开关 | 沿所在侧边展开、退回，内部文字随内容淡入淡出，主区域尺寸交接连续 | 展开 260ms，收起 220ms |
| 分组、树节点折叠 | 内容从标题下展开、折回，后续条目顺势让位，箭头同步转向 | 展开 240ms，收起 200ms |
| 居中弹框 | 遮罩淡入，内容从 0.98 倍与下方 6px 归位，关闭轻退 | 打开 220ms，关闭 160ms |
| 下拉菜单、浮层 | 从触发器方向短距离展开，变换原点与触发位置一致 | 打开 160ms，关闭 120ms |

快速反向操作从当前画面接续，不排队。焦点、点击、键盘导航及业务操作不延迟。宿主已有动画时只保留一套，避免双重位移。退出动画需验证卸载生命周期；即时卸载时不能承诺完整退场。

### 左右面板与中间区域协同（已实现，原设计目标）

用户反馈左侧整体收起、展开看不到动画，右侧面板已有局部动画，但右侧收起时中间区域向右扩展缺少连续过渡。此处是整体布局开合，与工作区内部的 session 分组折叠分开验收。以上为用户观察，具体触发原因仍待核对宿主布局和生命周期，不将右侧现有动画视为 Lumina 已实现能力。

**目标**：一次开合呈现为面板与中间区域共同完成的空间交接。面板边缘、中间区域边界、正文与输入框的最终位置应连续衔接，避免面板在动而内容瞬间跳位，或内容先跳位、面板再退场。

| 场景 | 面板表现 | 中间区域表现 |
| --- | --- | --- |
| 左侧展开 | 从左边缘舒展进入，内部内容轻淡入；文字和图标保持原比例 | 左边界随面板推进，正文与输入框按真实布局平滑到达最终位置 |
| 左侧收起 | 向左边缘退回，内部内容同步淡出 | 左边界连续回收，释放的空间平滑交给中间区域 |
| 右侧展开 | 从右边缘舒展进入，沿用并协调现有面板动画 | 右边界随面板推进，正文与输入框的位置和宽度同步调整 |
| 右侧收起 | 向右边缘退回，内容同步淡出 | 右边界连续向右扩展；用户观察到的中间区域右移过程必须有动画，不能瞬间到达终点 |

左右侧采用同一套节奏。建议正常档展开 280ms、收起 240ms，面板边界与中间区域使用相同的起止时刻和缓动 `cubic-bezier(.22,.75,.25,1)`。内部内容可在展开初段后淡入、收起初段先淡出，但不得拖延空间交接。以上参数为本轮设计初值，替代上表整体面板的旧建议，待联合预览确认。

- 中间区域允许依据宿主布局自然改变宽度与位置；长文本重排不能整块骤闪。不得缩放文字或截取截图假装内容缩放，不再叠加一套独立方向相反的位移。
- 正文、输入框、顶部工具栏与分隔线共同验收，保持宿主滚动位置和焦点，不为展示动效滚动到其他位置。
- 快速反向点击从当前可见宽度、位置与透明度接续，不重播起点、不排队；左右接连操作或同时变化时仍维持连续布局。
- 面板中的按钮与业务状态及时响应，不等动画结束才切换。避免退出内容继续接受误点击。
- 首次启动、恢复保存的开合状态、窗口尺寸变化和拖动分隔线不自动播放点击开合动画；拖动时跟手，不能套用延迟缓动。
- 核对宿主已存在的面板、布局和内容动画后再接入；同一视觉变化只保留一套有效动画。即时卸载的退出阶段需验证可用生命周期，不拦截业务操作凑退场。
- 系统减少动态时直接进入最终布局，关闭效果及卸载后恢复宿主样式与动画参数。

**验收**：分别观察左开、左关、右开、右关，面板边缘与中间区域边界在同一段时间内连续变化；在动画中途及结束处无跳位、重影、拉伸或额外第二次移动。覆盖长对话、空白新会话、窄窗口、两侧连续切换及快速反向点击。仅面板淡入淡出或仅列表条目变化不算整体开合完成；需要在真实客户端对布局边界与内容位置做多次采样并录制完整过程。

需求阶段已完成；随后按用户授权接入整体三列布局过渡。已核对 AppFrame 结构和开合钩子，正文与输入框沿原布局改变可用空间。展开 280ms、收起 240ms，中途反向读取当前列宽。受控 bundle 已验证左右边界连续变化、减少动态与拖动免动画；独立右侧 occupant 的视觉节奏和真实 DSH 最终观感仍待重启验收。

## 二、左侧面板内部

### Session 的状态表达

当前选中与正在运行是独立状态：选中的 session 可能空闲，后台 session 也可能在生成。

| 状态 | 建议表现 |
| --- | --- |
| 未选中、空闲 | 原有底色，悬停短暂淡入反馈 |
| 选中、空闲 | 清晰的选中底板，两片浅淡的宽幅混色光慢速交错；约 8 秒一轮，不绕边、不用小亮点追逐 |
| 未选中、运行 | 行背景内半透明的柔软光带连续飘动，弧线缓慢起伏，内部亮纹沿带流动；运行期间持续可见、无停顿 |
| 选中、运行 | 选中底板承载同一种风感光带，适当增强层次；暂停空闲漂移，不叠加两套循环 |
| 运行结束 | 流光自然淡出，回到对应空闲状态，不新增未读判断 |
| 授权、错误、暂停等 | 保留宿主文字、图标与语义，本轮不自定义新的状态映射 |

文字本身保持清晰。背景使用主题与品牌变量，限定在行内。状态只读公开状态或语义 DOM，不分析消息内容，不擅自定义业务状态。

### 背景方向（最新修订）

- **运行中：风感连续流光（用户指定）**。直接参考本仓库 [README 中文宣传图](../../assets/readme/hero-zh-CN.webp) 左下方的半透明蓝白、暖珊瑚光带。两至三层曲面般的宽光带交错、舒展，内部细亮纹持续向前流动，弧度和宽度缓慢变化；整体循环必须首尾连续。上一版单向扫光和静止间隔已取消。
- **选中空闲：静态选中底板或极慢柔光（待选）**。保持选中识别，不沿用运行中的连续流速。用户无法访问 Aurora Text 示例，该链接不再作为验收依据，后续提供本地实际行高预览。
- **实现初案**：原生 SVG 曲线与局部渐变叠层，区分光带的整体起伏和内部亮纹流动；不把整张宣传图平移当作实现，不采用高开销的逐帧全屏模糊或 WebGL。先核对多行并发预算与小尺寸观感。

Session 行空间有限，建议两条主光带与少量细亮纹，主体放在行的下半部，边缘柔和透明，标题保持清晰；具体密度、速度与强度通过本地预览确定。运行状态连续运动，在目标离屏、面板收起、页面隐藏和减少动态时暂停或降级。不增加第三方运行时。

### 星河流光（最新补充需求）

用户反馈：第二版细丝比第一版更灵动，但光不够亮，希望呈现星河的模样。保留既有风感连续流动，以星河的亮度与层次继续设计。本次先维护需求，不调整预览或客户端；以下细节为拟定表现，待原型确认。

- **整体形态**：星河沿 session 行横向舒展，有弯曲、疏密和宽窄变化。星点依附于流光路径，形成连贯的河流轮廓，不均匀撒满整行。
- **光芯**：主光带内部有可辨认的蓝白亮芯，局部高光更集中；浅色背景中也应能看出明亮层次，不能仅靠降低透明度形成一条灰淡的线。
- **星云**：亮芯外围铺薄而透明的蓝色、少量暖珊瑚雾层，边缘逐渐消散。保留细丝和留白，避免糊成厚重色块。
- **星点**：少量清楚的细小亮点随流光沿曲线前行，速度与相位存在差异；少数星点轻微闪烁，主次分明，避免频繁强闪和大颗粒爆散。
- **运动**：主光带缓慢起伏，内部细丝和星点连续前行，星云较慢漂移。各层有速度差，整体无停顿、无突兀重置，运行期间保持流动。
- **可读性**：主要亮度集中在行的下半部与标题留白处，文字、状态标记和操作按钮保持清晰。以真实 session 行高和长标题验收，不能只展示放大的装饰画面。
- **状态区分**：星河流动用于正在运行的 session；选中仍由底板表达，空闲时不维持同强度星河。运行结束后亮芯、星点与星云共同平缓退去。
- **性能与降级**：星点数量有界，只为可见运行行绘制；多行并发需设总预算。离屏、侧栏收起和页面隐藏时暂停；减少动态时取消流动和闪烁，保留静态状态识别。禁止用逐帧大面积模糊堆出发光。

验收重点：浅色中亮度明显提高、深色中不刺眼；能同时辨认亮芯、星云和星点；连续观察时有星河流动感，标题可读；多行运行不显杂乱。具体亮度、星点密度和速度通过下一版原型确认。

### 左侧运行光团（2026-10-27 定稿）

用户确认采用有体积、柔和变形的蓝青光团，内部少量珊瑚粉与紫色交融，外围有随轮廓散开的彩色柔光，替换原有圆环旋转。光团占用原状态图标槽位，底部星河保持现有方向，两者统一明暗节奏；不增加连接线、光柱或拖尾。

视觉稿与完整要求见[会话运行光团需求](会话运行光团需求.md)，接管规则、共用画布、质量预算和验证顺序见[实现设计](../engineering/会话运行光团实现设计.md)。此前的小光点、扁透镜和“只隐藏圆环”的候选不再作为本轮方向。该效果尚未实现，1.0.0 的原有圆环仍是当前发布行为。

### 点击展开与收起

- 面板整体开关遵守全局侧栏规范；内部工作区、session 分组折叠遵守树节点规范。
- 箭头、内容区域、后续行让位同步，收起不能先清空再播放空壳。
- 点击 session 的选中切换另行处理：底板约 220ms 交接，跨度大或跨滚动区域时局部淡出淡入。
- 滚动、虚拟列表重挂载及后台刷新不触发整列入场，默认不做长错峰。

## 接入与验收

已知钩子为 session 行 `data-row-key="session:<id>"` 和运行图标 `svg[data-state="ongoing"]`。选中、折叠、面板边界及弹框生命周期仍需核对，不宣称全局已可用。高度动画涉及布局，须限定局部容器并核准预算；不改宿主包、不拦截操作、不复制交互节点。

循环只作用于可见目标，面板收起、离屏和页面隐藏时暂停；多条运行需统一性能预算。减少动态时静态显示，选中和运行语义仍完整；卸载清除所有装饰、监听及计时器。

原型覆盖：全局开关、弹框、菜单、分组折叠、各 session 状态、长标题、多条运行、快速反向操作、滚动、深浅主题及减少动态。先确定视觉和 loading 方案，再进入客户端实现。

### 星河原型记录

2026-10-23 已更新 `docs/demo/sidebar-motion.html`：使用局部 Canvas 绘制蓝白光芯、渐变薄雾、多层曲线和每行 65 个星点，形状起伏与内部前行分层。深浅色为原型自身配色，不使用客户端主题逻辑。受控浏览器确认连续两次 Canvas 采样不同、运行状态可停止、侧栏可收起，无页面错误。当前仅供观感确认，未接入客户端；多行性能和完整降级仍需后续验收。

用户反馈星河原型掉帧后，优化为预渲染星云与星点光晕贴图，避免逐帧创建径向渐变；行尺寸由 ResizeObserver 更新，移除逐帧布局测量，细丝从 16 层收敛为 10 层。面板和分组收起时跳过绘制。受控采样只代表当前浏览器回调预算，不替代用户设备上的实际帧率验收。

### 连续随机变化（最新要求）

用户要求增强流动曲线与随机性，并同步需求。光带的弯曲幅度、曲率和整体偏移应缓慢、不规则地变化；星点流速与横向疏密也应有连续变化。随机目标以平滑插值连接，不逐帧抽取随机位置，避免抖动、突然跳变和频繁闪烁。

原型使用有种子的连续噪声改变曲线与局部宽度，星点用连续速度函数积分得到位置，避免修改速度时位置跳变；疏密通过缓慢变化的亮度分布表现。不同 session 保留相位差，同一行各层共享主曲线，确保星点沿河流运动。随机性仍是有界的程序变化，不宣称物理流体模拟。缓存贴图、有限星点与可见目标预算保持不变，接入客户端前仍需多行性能验收。

### 客户端接入范围

本轮接入运行中 session 的连续曲线与星点流光，保留宿主 loading 和选中呈现。使用语义行和 ongoing 标记，只读状态；Canvas 绝对定位，减少动态时移除，离屏不绘制，同时最多绘制 8 行、挂载最多 24 行。全局开合与弹框尚未接入。客户端重启后的视觉与多会话性能仍需验收。

### 亮度与状态过渡补充

用户要求继续提亮并增加出现、消失过程。提高共享绘制的星云、光芯与星点亮度；运行开始时约 500ms 淡入，结束时约 500ms 淡出后移除。消退期间重新运行应从当前透明度接续，不闪灭重建。节点卸载、关闭效果和减少动态立即清理。原生业务状态及时更新，不等待装饰。

### 星河厚度补充

依据客户端截图增加星河纵向厚度：星云贴图纵向铺展、细丝间距及星点分布范围一并加宽，光芯保持清晰，避免只加粗单根线。共享绘制同步影响 demo 与客户端，不改变条目行高。真实客户端标题可读性需重启核对。

### 下沿亮芯与层次修订

用户确认提高辨识度，同时避免光线穿过标题。星河亮芯下移至行高约 80% 处，上半部仅保留淡雾；下沿使用有明暗间隔的蓝白曲线与少量高亮星点。星点从 65 个收敛至 44 个，提高较大星点的可见度，避免均匀铺满。保留连续随机流动、厚度与状态淡入淡出，不改变宿主文字、行高及状态图标。Demo 与客户端继续共用绘制，实际观感需客户端重启验收。

### 下沿流动变化增强
