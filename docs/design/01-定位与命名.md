# 01 · 定位与命名

## 1. 一句话定位

**Lumina 是 DSH 客户端的动效增强层。** 它不改变任何业务逻辑，只在官方 UI Slot 和稳定的语义属性上挂载视觉动效。

它解决的问题：DSH 客户端功能强但视觉反馈偏克制——品牌是静态的、输入框没有状态感、流式输出只有一个闪烁光标、按钮点击缺少确认感。Lumina 补齐这一层"手感"，且完全可关。

## 2. 命名

| 项 | 值 |
| --- | --- |
| 项目名 | **Lumina** |
| 包名 | `dsh-lumina` |
| 中文名 | 流光 |
| 命名理由 | Lumina = 光。契合"鲸鱼流光"的视觉母题；短、可读、可做前缀命名；不占用 DSH 官方命名空间（官方是 `@deepseek-ai/dsh-*`） |
| 备选名 | `dsh-biolum`（生物发光鲸鱼，最有记忆点但语义偏窄）、`dsh-motionkit`（直白但平庸）、`dsh-glow`（太泛） |

### 效果命名约定

前缀 `lumina.`，后接界面域：

```
lumina.brand       左上角品牌（含流光字标）
lumina.composer    输入框边缘流光
lumina.caret       流式输出光标
lumina.press       按钮按压反馈
lumina.hero        新会话首屏入场
lumina.panel       设置面板
```

好处：用户在设置面板里看到的名字、控制台日志、`data-lumina-*` 属性、代码模块名，四者一致，排查时不必来回对照。

## 3. 设计原则

按优先级排序，冲突时上面压下面：

1. **升级安全优先于效果丰富。** 宁可少一个效果，也不写一个下个版本就会碎的补丁。
2. **降级必须静默。** 任何 Tier 2 规则命中则生效、未命中则完全无副作用——不报错、不留空壳、不占位。
3. **不争夺交互。** 装饰层一律 `pointer-events: none`，永不阻挡点击、输入、拖拽、选中。
4. **默认尊重无障碍。** 跟随系统"减少动态效果"，且不提供关闭该跟随的选项。
5. **零运行时依赖。** 不引入 gsap / three / framer-motion，避免侧栏里的重库与掉帧风险。
6. **可整体关闭。** 一个开关、一个 data 属性、一次卸载，三条路径都能让客户端回到官方样子。

## 4. 非目标

明确不做，避免范围蔓延：

| 非目标 | 原因 |
| --- | --- |
| 修改 `app.asar` | 破代码签名，macOS 拒绝启动 |
| WebGL / three.js 背景粒子 | 高频交互区引入 WebGL 上下文，启动成本与掉帧风险不值得 |
| 重做角色皮肤 / 主题系统 | 那是主题管道的职责，Lumina 只做动效 |
| 改变信息密度、布局、间距 | 动效层不调布局，避免与官方改版冲突 |
| 监听模型输出内容做动效 | 越界，且会碰到业务逻辑 |
| 引入 Tailwind | DSH 客户端不提供 Tailwind 运行时 |
| 替换业务组件 | 只用 slot 追加/占用，不改官方组件内部 |

## 5. 命名与打包决策（已定）

### 5.1 一个包，不拆

**`dsh-lumina` 是唯一的包。** 不拆"引擎 + 品牌包"，不做跨产品复用设计。

理由（技术判断，不是偏好）：Lumina 的动效**焊死在 DSH 上**——

```
[data-composer-card]     只有 DSH 客户端有
[data-lexical-cursor]    只有 DSH 的 Lexical 编辑器有
sidebar.brand.mark       只有 DSH 的 Cordis slot 有
```

把这些挪到任何别的界面，选择器全部不匹配，一行都跑不起来。所以"复用给别的产品"是伪需求：真要给别的界面做动效，那是另写一套，与本项目无关。

**本项目范围：只服务 DSH 客户端。不考虑其它产品、其它宿主、其它代码库。**

### 5.2 包名不带品牌：包名是能力，品牌是配置

Ratel 是**插件的一个配置值**，不是它的身份。

```
dsh-lumina                        ← 包名：这是 DSH 的视觉/光效层
  └─ brand: "ratel" | "deepseek"  ← 品牌预设：默认 ratel
```

三条理由：

1. **名称说能力，配置说归属。** 同类做法见 `dsh-brand-studio`：它能配成任意品牌，但不叫 `dsh-<某公司>-studio`。
2. **`dsh-ratel-lumina` 读起来像"给 Ratel 用的 Lumina"**，反而暗示了跨项目复用——而 5.1 已确认不成立。
3. **换回 DeepSeek 品牌只改一个配置值**，不改包名、不重装。名字一旦带 Ratel，这件事就变别扭。

### 5.3 标识符对照（实现时勿混）

| # | 标识符 | 值 | 出现位置 | 约束 |
| --- | --- | --- | --- | --- |
| 1 | npm 包名 | `dsh-lumina` | `package.json` 的 `name`、安装命令 | 用户装的就是它 |
| 2 | Cordis 插件 id | `ui-lumina` | `cordis.patch.yml` 的 `id` + `lib/index.js` 导出的 `name` | **两者必须完全一致** |
| 3 | 浏览器模块 id | `dsh-lumina` | `lib/client.js` 的 `__ModuleLoader__.load({ id })` | **必须等于包名** |

第 2 与第 3 值不同是正常的：`ui-lumina` 是 Cordis 侧的插件身份，`dsh-lumina` 是浏览器模块系统的解析键。三个都对上，插件才会加载（详见 [02 §2.8](02-平台约束（执行前必读）.md)）。

### 5.4 其余前缀统一

```
效果名        lumina.brand / lumina.composer / lumina.caret / lumina.press / lumina.hero
CSS 类        .lumina-shine / .lumina-mark / .lumina-name
data 属性     [data-lumina="off"] / [data-lumina-sent] / [data-lumina-streaming]
CSS 变量      --lumina-brand / --lumina-edge / --lumina-angle
存储 key      dsh-lumina/settings/v1
样式标签       <style data-plugin="dsh-lumina">
```

统一前缀的目的：排查时不必来回对照包名、模块名、类名是否一一对应。

### 5.5 显示名

| 场合 | 显示 |
| --- | --- |
| 设置面板标题、README 标题 | **Lumina 流光** |
| 插件清单里的包名 | `dsh-lumina` |
| 品牌区实际呈现 | 由 `brand` 预设决定（默认 Ratel） |

技术包名与用户看到的标题分开：包名稳定，标题可读。
