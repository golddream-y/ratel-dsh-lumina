# 新会话丝带渲染设计

状态：细化 SVG 外观保真接入 WebGPU 已实现，受控浏览器验证通过；原生客户端视觉与性能待确认。旧曲面实验资产与代码已清理，历史记录保留，以下最新交付说明优先于历史记录。用户指定 WebGPU，旧 WebGL 2 讨论仅为历史调研。

## 当前交付：细化 SVG 外观保真接入 WebGPU

用户要求将已认可方向的静态美术做成一个客户端版本。首版采用 SVG 视觉资产纹理与 WebGPU 细分网格结合：构建时将 `silk-study.svg` 嵌入包内；首次初始化时按固定上限栅格化为透明纹理，一次上传，所有褶皱、反面、高光与局部光晕随同一网格形变。避免重新用不成熟的解析材质丢失已认可的美术质感。

本版本的主要高光来自原 SVG，不再宣称主要高光由实时法线产生；这是保真优先的首版取舍。变化由受限的纵横位移与局部伸缩构成，不能宣称真实三维翻面或液体模拟。旧参数曲面方案仅保留本文历史说明，实验代码和资产已清理。

位置、横向范围、焦点显隐、入场等待、减少动态与清理契约不变。256×16 网格为 8192 三角形，一次 draw / submit，4× MSAA；SVG 纹理为 3072×912，透明纹理只在初始化时上传，绘制循环仅更新 uniform。纹理、图像 URL、MSAA、buffer 与 device 在失败或卸载路径清理；运行时不请求网络图片，不采集宿主内容。GPU 不可用时跳过丝带。技术实现只可称为 SVG 外观的 WebGPU 网格形变，原生视觉与性能仍待验证。

## 当前阶段：独立 SVG 美术重画，尚未接入

用户否定原有三条波浪状 SVG，当前暂停将未认可的形态继续同步进 GPU。新增 `assets/motion/silk-study.svg`，在 `docs/demo/silk-art.html` 单独对照 README：手绘宽带面、反面、窄褶皱、锐边与局部聚光，允许使用局部 SVG 滤镜探索静态美术。该样板尚未接入构建采样或客户端，不替代下述运行时几何源；视觉认可后再设计可映射的几何、材质与局部光晕数据。不能将 SVG 滤镜支持暗示为 WebGPU 已实现同等效果。

## 最新架构：SVG 轮廓驱动 WebGPU

本节替代此前由解析正弦函数独立生成曲面形态的方案，先更新设计再实施。WebGPU 后端、现有定位范围及生命周期保持。

美术形态唯一来源为 `assets/motion/silk-ribbon.svg`：每张带面由两条可编辑的三次 Bézier 边界定义，明确局部开幅、交错与收束。不是截图转纹理，也不是在 WebGPU 上叠一层独立运动的 SVG。SVG 中的渐变和静态高光用于美术对照；实时主要高光仍由曲面法线计算，不能称为完整自动转换 SVG 材质。

构建工具 `tools/gen-silk-surface.mjs` 仅支持本资产规定的 M/C 路径语法，验证三张带面的六条边界、端点收束、横向单调与公共采样坐标后，将每张带面的上下边界采样为 129 对坐标，写入包内生成的 TypeScript 数据。路径以横向 x 为公共参数，用有界二分反求 Bézier 参数，不能按两条路径各自弧长采样导致对位错乱。生成数据作为 WebGPU 只读 storage buffer 一次上传；运行时不加载或解析 SVG，不读取页面截图。

顶点着色器按 u 插值边界位置，再按 v 插值得到基础带面；通过同一数据的局部差分获取曲面方向。SVG 给定的宽窄与交错为主，时间仅驱动有界低频位移和横截面深度，不能在动画中推翻原轮廓。固定基准时间必须复现 SVG 边界。实时高光跟随曲面法线，纹理贴图暂不加入。

验收先看 SVG 与 WebGPU 基准帧的等比例轮廓对齐，随后确认透色、高光与运动；编译成功不等于美术通过。美术资产和运行时数据必须同时更新，生成脚本接入 build / build:client，检查生成结果确定性与坏路径拒绝；异步初始化失败、GPU 缺失和 device lost 继续按原契约清理，新增 storage buffer 也须释放。顶点数量与 draw 预算保持不变。

## 目标与实施顺序

读者为 Lumina 渲染实现与验收人员。目标是将 README 中半透明丝绸的宽面、薄边、扭转、红蓝透色和局部白色高光转换成可实时绘制的装饰。宣传图含艺术化光照，不能预先承诺逐像素复刻。

遵从用户最新顺序：先优化材质效果，再调整位置。本阶段冻结现有输入框定位、路径范围与延伸比例。先完成固定时间的静态材质样板，经视觉确认后加入运动，最后单独讨论贯穿构图。不得以构建通过或画面变化代替视觉验收。

## 现状与根因

`composer-ribbon.ts` 管理语义目标、焦点、观察器、显隐和清理；`composer-ribbon-painter.ts` 通过 Canvas 2D 分带着色模拟曲面。当前仍存在条纹、色彩均匀、缺少明确翻面和高光与形态脱节的问题。继续增加细线或半透明叠层不能稳定解决这些问题。

保留生命周期与宿主适配边界，替换绘制内核。Canvas 2D 旧实现仅用于对照，不作为 GPU 失败时的自动视觉回退。

## 技术选择

首版采用原生 WebGPU 与 WGSL，不引入 Three.js、GSAP 等运行时依赖。WebGPU 不可用、shader 编译失败或资源创建失败时跳过页面丝带，保留现有输入框边缘效果和全部业务功能。不给用户增加渲染后端设置。

WebGPU 支持现代 GPU 的渲染与计算，但本效果只有少量曲面、少量提交，没有必须使用 compute shader 的工作负载。性能取决于绘制像素、透明覆盖、材质复杂度和宿主合成，不能推断更换 API 必然提速。用户已选择 WebGPU；首版只维护 WebGPU 实现，不提供 WebGL 后端。API 性能收益仍需同画质实测。

DSH 内嵌运行环境的 WebGPU 可用性目前未验证。验证必须覆盖 `isSecureContext`、`navigator.gpu`、`requestAdapter()`、`requestDevice()` 及真实 canvas 出图；仅有属性存在不算可用。不得修改 Electron 启动 flags、关闭安全机制或要求用户开启实验功能。

## 曲面与光照

最多三张丝带，各自共享路径范围但使用不同相位与小幅层间偏移。静态参数网格由长度参数 u 与横截面参数 v 组成；顶点着色器按路径切线构建局部坐标框架，围绕切线旋转横截面，再正交投影。真实朝向变化应自然产生宽面、薄边、翻面，不能仅缩放二维带宽冒充翻转。

法线由同一曲面的参数导数求得，避免顶点变形与高光使用两套独立运动函数。首版使用有界解析正弦变形，不做流体模拟，不逐帧上传全部顶点。改变时间 uniform 即可驱动形态；静态样板固定时间。

片元着色器连续计算材质，不再使用 Canvas 分带填充：

- 蓝色主体与局部珊瑚红透色沿面内变化，不均匀铺满三张曲面；颜色取自集中管理的装饰调色板。
- 横截面边缘透明度、厚度近似和朝向共同决定透色，保留能辨认的轮廓与清透内面。
- 主高光由法线、固定视向与柔和面光方向计算，加入有界 Fresnel 边缘反光；高光依附曲面，不能画独立扫光线。
- 主体明暗保留少量较深的冷色折面，突出局部白亮；避免整面泛白或全表面同等锐利。
- 通过解析柔边、预乘 alpha 和一致的混合规则控制边缘；不读取真实页面作为折射纹理，不采集对话内容。

透明层按稳定层序绘制，保持有限交叠，首版不实现通用顺序无关透明。若自交使前后关系破坏，优先约束曲面形态，再决定是否分段排序。高光不能掩盖文字；片元阶段按输入框圆角矩形的解析遮罩排除卡片内部，不使用 DOM 截图。

首版不启用 bloom。材质成立后仍需柔光时，只允许局部低分辨率光晕缓冲及有限采样，不使用全屏多轮模糊。白底下不能依靠加法混合把全部色层洗白。

当前模块边界（早期规划中的独立 surface 模块未创建，曲面公式与着色器同文件）：

| 模块 | 职责 |

## 生命周期与资源

沿用当前新会话语义识别与设置归属。聚焦且入场完成后显现，失焦淡出；淡出结束停止绘制。系统减少动态、隐藏页面、离开新会话和卸载时停止循环，按对应语义移除装饰。保留 pointer-events:none、aria-hidden 与真实输入框内部透明。

device lost 或 uncapturederror 时停止提交并停用本次挂载的装饰，正常业务继续；下次效果重新挂载才重新初始化。dispose 解绑 context、销毁 uniform buffer 与 device 并清理事件监听；pipeline 与 shader 随 device 释放，中途失败也释放部分资源。调试信息不得读取消息内容。

## 初始性能预算与验证

以下为设计上限和验收目标，尚非实测结果：

- 一张装饰 canvas、最多三张曲面，总三角形不超过 6000；默认最多三次主体 draw call。
- 绘制范围裁到光带包围矩形并留有限余量，沿用页面坐标映射，避免全窗口透明片元开销。
- DPR 上限 1.25，绘制缓冲上限 150 万物理像素；超出时降低分辨率，不能放大覆盖范围。
- 每帧复用程序、网格、uniform 缓存与临时对象；不编译 shader、不创建缓冲、不读回 GPU、不查询宿主布局。
- 首轮以 60Hz 显示下稳定帧节奏为目标，记录渲染 CPU 时间、整页帧间隔与长帧分布。CPU 提交短不等于 GPU 快；GPU timer 可用时异步读取，跳过 disjoint 样本，不能同步等待结果。
- 性能不足先降低像素预算、透明覆盖和可选柔光，再降低网格密度；仍不足则停用装饰，不拖慢输入。

验证场景包含真实 DSH 的高低窗口尺寸、侧栏开合、连续输入、设置开关、焦点切换、窗口后台、减少动态、context loss 与反复挂载。受控浏览器只验证实现，不能代替原生客户端性能结论。

## 视觉验收门槛

1. 固定时间，裁出 README 参考与当前曲面等比例并排展示；至少包含一个宽面、一段薄边和一次翻面。
2. 在正常缩放下看不到平行色带、网格接缝和密集细线；红蓝色相分工明确，存在局部白色亮面与可辨冷色暗面。
3. 动态至少取三个时刻验证曲面变化；亮面随法线变化，循环不出现跳变。静态截图不能证明流动自然。
4. 材质经用户认可后再调整贯穿位置；整页合成验收独立进行。

## 备选与不采用原因

Canvas 2D：保留为历史对照，当前分带材质与翻面表达已多次未达目标。静态透明贴图：可作质感参考，但不能承担所需的连续翻面与运动。WebGPU：保留评估入口，首版收益未经证明，同时增加宿主兼容与维护成本。外部 3D 引擎：与零运行时依赖边界不符。

## 官方资料调研补充（2026-10-24）

对比对象为 WebGL 2 与 WebGPU，不是 CPU 绘制与 GPU 绘制：两者都能使用 GPU 顶点和片元着色器，因此曲面、高光与半透明材质均可实现。WebGPU 增加一等 compute shader 支持，以不可变 pipeline、命令编码及异步错误模型替代 WebGL 的全局状态与部分同步交互。优势主要对应大量对象提交和并行计算；不能将某个机器学习或粒子基准的倍数套用于三张丝带。

Chrome 官方排障资料明确包含「WebGPU is slower than WebGL」场景，要求检查硬件加速及是否真正利用 WebGPU 的优化方式。故本项目不预设哪套 API 的帧率更高。WebGL 同样需要规避阻塞查询、复用资源、合批并控制 back buffer 大小，不能将旧 Canvas 2D 的 CPU 路径等同于 WebGL。

WebGPU 的手动 MSAA、资源绑定、异步初始化与 device loss 管理增加本项目首版实现量，但不可变 pipeline 与对象标签也能改善状态隔离和诊断；不将其笼统描述为更难或更容易。DSH 的 Chromium/Electron 版本、GPU 加速状态、页面 origin 与实际 adapter 共同决定可用性；浏览器版本号不足以证明 DSH 中可运行。

历史调研曾建议 WebGL 2；现按用户决策采用 WebGPU。若将来引入大规模粒子、GPU 流体求解或大量独立动效提交，应重新评估 WebGPU，而不是永久排除。届时比较必须固定形态、shader 复杂度、像素数、透明层数和硬件，分别记录冷启动、稳定帧间隔、CPU 提交、可用 GPU 时间与资源占用；禁止在同一 canvas 上先获取一种 context 再尝试另一种。

补充来源：

- [Chrome：From WebGL to WebGPU](https://developer.chrome.com/docs/web-platform/webgpu/from-webgl-to-webgpu)：pipeline、异步模型、compute 与 MSAA 管理。
- [Chrome：WebGPU troubleshooting](https://developer.chrome.com/docs/web-platform/webgpu/troubleshooting-tips)：adapter 失败、硬件加速及 WebGPU 比 WebGL 慢的排查。
- [MDN：WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)：避免阻塞调用、合批、缓冲尺寸与资源释放。


## 用户确定的技术路线

用户明确指定直接使用 WebGPU。首版采用原生 WebGPU 与 WGSL，不再实现 WebGL 后端；保留静态材质样板、运动、构图的验收顺序。API 不可用、adapter/device 获取失败或设备丢失时跳过丝带，保留真实界面；不修改宿主安全设置。资源异步初始化必须处理卸载竞态，设备、uniform buffer 和 canvas context 在停止或卸载路径正确释放。静态参数网格通过 vertex_index 程序化生成，时间与尺寸由 uniform 传入，片元连续着色。预算仍为最多三张曲面、6000 三角形、三次主体提交、150 万物理像素。


## 本轮实现记录

三张 128×6 网格曲面，共 4608 三角形；三个 uniform 槽按 256 字节对齐，共用 768 字节 buffer。每帧更新同一 Float32Array，三次主体 draw 在一个 render pass 中提交。片元采用曲面参数导数计算连续法线，避免按三角面求导造成明暗分段。内部圆角输入框以解析距离函数遮罩。缓冲上限 150 万物理像素、DPR 上限 1.25，纵向 scissor 控制片元工作范围；仍使用全视口透明 canvas 以保持当前坐标与位置。尚未实现 canvas 按包围盒缩小的内存优化，不将 scissor 等同于缩小缓冲。默认首聚焦异步初始化，初始化后重查当前场景；卸载后迟到的 renderer 立即释放。

材质样板 `docs/demo/silk-material.html` 与客户端共用 renderer / WGSL，默认定格，支持时间滑块与播放，系统减少动态时禁止播放。此页不注入业务 UI，可直接查看曲面材质；实际 slot 集成仍以 `silk-ribbon.html` 验证。

本轮补充 4× MSAA，抗锯齿纹理仅在尺寸变更时重建，停用或卸载时销毁。150 万物理像素对应 RGBA8 多采样颜色缓冲理论约 24 MB，另有呈现缓冲及实现相关开销；该数值为资源规模估算，不是原生客户端显存实测。首版只使用一个主体 pass，无 bloom。

受控 Chrome 默认配置验证 secure=true、gpu=true、adapter=true，canvas 实际 WebGPU context 可用。连续时间 uniform 采样递增；模拟设备丢失后 canvas 清除，延迟 adapter 初始化期间卸载后 device 销毁一次且未发生提交；GPU API 缺失时输入框继续聚焦。该验证未更改 GPU flags，不等同于原生 DSH 可用性或硬件帧率验证。


## 锯齿与柔顺反馈后的预算修订

最新实现：三张主体曲面为 128×7 网格，三层低密度解析光晕为 64×2 网格，共 6144 三角形、六次 draw，在同一个 MSAA pass 中提交。uniform buffer 改为六个对齐槽，共 1536 字节；此条替代早期的三次 draw / 4608 三角形预算。光晕使用曲面扩展与连续透明衰减，不是 bloom，不增加纹理采样或全屏模糊。边缘依据 fwidth 做解析覆盖，局部折面亮芯也按导数拓宽以减少细线闪烁。曲面弯曲与扭转采用不同低频相位，宽度缓慢变化，位置基准与延伸比例未改。静态材质观感改善不能代替动态帧率与用户验收。

## 交错曲面迭代

三张曲面采用不同局部开幅中心、非对称路径偏移与非匀速扭转，红色主面与蓝色主面分工，降低全部混成灰紫的倾向。高光集中在局部折转与一侧边缘，宽面通过低强度连续褶皱明暗打破等色块。定位基准与横向范围保持，纵向局部展开属于形态变化。预算仍为 6144 三角形与六次 draw，不增加贴图、pass 或全屏后处理。当前版本仍待用户视觉认可。

## 白底光感修订

反射白色在白底上不足以表现发光。本轮保持几何，增加高对比的近白亮芯、局部近场彩光与柔和远场衰减；调色仍从集中 palette 派生，以连续曲线提高透色对比，不写入独立品牌色。RGB 与 alpha 一致预乘，减少全带均匀泛白。没有增加 draw、pass 或纹理，仍是解析光晕近似，未实现 HDR bloom 或真实光照页面。受控截图确认近白亮芯与周围红蓝区域的差异增加，不代表用户已认可光感，也不代表 README 视觉还原完成。


## SVG 驱动本轮实现

六条 M/C 边界及静态渐变源位于 assets/motion/silk-ribbon.svg。生成工具在 build / build:client 前运行，--check 检查 SVG 填面与生成数据是否过期；两个管线测试覆盖源数据同步与不支持命令拒绝。按公共 x 采样 3×129 对边界，6192 字节 storage buffer 在初始化时上传一次，绑定为只读，销毁路径释放。默认材质时间改为 0，并列展示 SVG 源图；主高光仍来自 WGSL，不把 SVG 的渐变声明为已自动搬入 shader。

实际浏览器验证出图、两个时间点形态变化、device lost、延迟初始化卸载及无 GPU 编辑器保留均通过，无页面错误。延迟初始化卸载可能有一次静态 storage 上传，但没有开始绘制，迟到的 device 被释放；不能沿用旧验证中“零 writeBuffer”的说法。形态能否达到 README 仍须用户认可。

### SVG 美术细化与对照

用户认可独立美术稿的方向后，保留原稿 `assets/motion/archive/silk-study-v1.svg`。当前 `silk-study.svg` 在构图不变的前提下增加翻卷冷色反面、局部透光窄褶皱、长短不同的清晰折边及外侧柔光，不整体加亮。美术样板支持上一版切换。当前仍仅是静态 SVG，尚未将新增局部路径、渐变或滤镜映射到 GPU，不能据此声明客户端效果完成。


### 首版保真实现细节

SVG 构建为内联模块，初始化通过已明确尺寸的 2048×608 SVG 图像一次栅格化，使用 copyExternalImageToTexture 上传预乘透明 rgba8unorm 纹理；Blob URL 在成功或失败路径均撤销。纹理约 4.98 MB（不含 GPU 实现开销），不重复上传；一次 draw、2048 三角形、32 字节 uniform，网格上同一形变同时作用于褶皱和光晕。离开新会话、页面隐藏及减少动态时释放 renderer，失焦淡出结束仅停绘；卸载、初始化失败和设备丢失销毁 texture、MSAA、buffer 与 device。旧解析曲面 renderer 文件保留为实验对照，不被客户端调用。

主要反光随纹理运动，不是本轮实时计算的三维高光；这是保留用户认可美术稿的明确取舍。运行时没有访问文件或远程图像，装饰仍不截获事件、圆角输入框内部遮罩透明。实际 native 客户端的 CSP 与 GPU 可用性仍需重启后确认，失败则跳过装饰。

## 新会话窗口拖拽兼容改造

用户澄清为新会话无法拖动原生窗口，已有会话可拖，按钮与设置均正常。旧浏览器“点击穿透”验证不足以覆盖此问题。Electron 的原生拖拽区域由 app-region 控制，不能把 pointer-events:none 等同于原生拖拽安全，见 [Electron 官方说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。当前仍未在原生 DSH 中复现并定位所有因素，不宣称浏览器验证即根因已证实。

改造画布实际布局与绘制缓冲，仅覆盖光带的有界包围范围，顶部 64 CSS px 保留区内不出现此 canvas；光带仍使用全局场景坐标，新增 crop uniform 将世界坐标投影到局部画布，避免视觉位置偏移。只对画布自身设置 no-drag、draggable=false 与强制 pointer-events:none，不改宿主拖拽属性、窗口 API 或业务事件。保留失焦淡出。

新增纯函数范围测试覆盖标题栏留白、正常光带范围及过小窗口跳过；32 字节 uniform 变为 48 字节，像素预算按局部矩形计算，减少透明缓冲。原生窗口拖拽最终验收仍需重启本机客户端。

## 下缘交织布局

原生窗口拖拽恢复已获用户确认，本轮不回退局部 canvas。将 SVG 原稿主脊线按 x 离线采样，作为纹理局部纵坐标基准，WebGPU 将该基准重定位到输入框下缘的浅弧路径，保留相对脊线的褶皱宽度、聚光与细节。首个聚光对齐左下圆角外侧，短右尾离开边缘；主体仍在真实输入框后方，解析遮罩禁止覆盖卡片内部。独立材质页不应用场景重定位，保持可对照。新旧效果不得同时叠加，局部包围盒随新路径更新，顶部保留区不变。


### 下缘交织实现记录

美术 SVG 中新增仅作定位基准的 flow-spine 路径，构建工具按公共 x 采样 129 个 y 值，初始化时一次上传 516 字节只读缓冲。客户端依据输入框边界定位主脊线，再加回原稿相对主脊线的细节，避免简单整体平移导致宽带被卡片大面积遮断。左侧延伸上限约 0.6 倍框宽、440px，右侧网格余量约 0.3 倍框宽、220px（SVG 原有透明淡出使可见尾部更短）。首处聚光靠左下角，中段浅弧，尾部越过右下角淡出。保持输入框内部遮罩与顶部 64px 画布排除区。增加的脊线缓冲在 dispose 路径释放，纹理仍一次上传，draw 数量不变。

## 分段流入与沿线能量传输

局部场景构图调整为左侧抬升、中段短暂藏入下缘、右端收短，带宽随接近框体而收束，避免同宽平铺。用片元 u 参数控制首段软前沿，从左至右展开，时长集中于 token；新会话场景或 session key 变化重置，失焦仅暂停与淡出，不重新播放。展开后沿 u 运行两组不同宽度的连续明暗包络，改变既有纹理局部亮芯与透色对比，像能量沿带面传递；不是再添加一个孤立光点来回跑。保留一次 draw，片元不增加纹理读取；布局仍局部化，不覆盖标题栏。静态材质页 t=0 保留完整源稿用于比较，实际客户端才显示首播展开。


### 流入与传输验证

首次流入时间由 RIBBON_FLOW.reveal=1.65s 控制，软前沿推进到末端；持续传输速度为每秒约 0.17 个归一化带长，两个不同宽度的连续明暗包络同向前进。原稿纹理仍不重复滚动，以免首尾和褶皱脱节。场景重定位左端约 0.65 框宽（上限460px）、右端余量约0.18框宽（上限150px），中段带宽收至原稿约65%，避免铺成通栏色带。

实际 GPU 固定时刻采样：0.4s、1.0s、1.8s 的下缘区域可见最右 x 依次为381、846、1127，证明由左向右展开；3.2s 与5.6s 对照有14635个像素变化超过5/255（限定同一带面区域），作为持续变化证据，不等同于原生流动观感或帧率结论。失焦续播时钟1.583→2.133s，新会话标识变化后回到0.067s，pageerrors=[]。真实按钮点击、离场、重入、减少动态与窄屏范围验证通过，顶部仍排除装饰。


### 右上舒展构图

用户要求进一步放开纵向空间并允许右上舒展。场景路径左段下沉量增大，保留较宽的带面；框体附近高斯收束区缩短，右段越过框右侧后上扬至框顶以上，再向窗口边缘淡出。右侧网格余量放宽至约0.65框宽、上限480px，左侧与首播编排不变。新增窗口侧缘软衰减，避免光带在视口边缘硬切；画布上界调整为框顶上方约180倍缩放系数像素，并保持顶部64px排除区。

当前宽度系数在左侧约1.5、收束处约0.6、右段约1.35之间连续变化，不再把整条固定压窄。材质未重画，局部 canvas 仍强制点击穿透与 no-drag。实机观感待用户确认；受控场景验证左下与右上曲线均可辨、失焦续播及新会话重置正常，pageerrors=[]。

## 2026-10-24：框边穿插与分层舒展

保留左下进入、右上离开的范围。路径以输入框左右边缘为锚点：左下潜入背后，中段被卡片遮住，右下重新露出。仅外沿可见，不覆盖文字和按钮。右侧展开横截面，红色薄片与蓝色主面采用不等长尾部；局部高光集中在潜入和离开处，避免整体增白。

## 2026-10-24：曲率与高光精度

用户反馈框边线条转折生硬、亮部泛白且有低分辨率感。本轮保留构图，将局部收束改为更宽、更浅的曲率过渡；微动幅度收小。网格改为 256×16，SVG 一次栅格化至 3072×912；局部画布 DPR 上限 2、总像素预算 240 万，继续 4×MSAA。该预算较上一版增加，需要关注客户端帧率，不能据此宣称性能不变。

提亮从宽幅白色覆盖改成窄亮芯，降低白色混合量与光晕强度，保留两侧的透色与褶皱。纹理仅初始化上传，单 draw call、不增加渲染通道。
