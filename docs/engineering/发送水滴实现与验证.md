# 发送水滴实现与验证

2026-10-22 已完成一版实现，真实客户端验收仍待重启后进行。此页记录实现边界与可重跑证据，不替代[需求设计](../product/发送文字水滴转场需求设计.md)的 A1–A10 验收。

## 实现

当前编辑器的可见文字按字素取样，保留字体、位置与行高。多个字形分别沿曲线汇聚，局部 SVG alpha 融合使字形与液体轮廓连接；液滴形成细颈后断开，沿弧线移动，在目标压扁铺展，再按真实消息排版展开字形。当前常规总时长约 1150ms，柔和 1350ms，鲜明 1000ms。目标暂未挂载时允许短暂停留，整体硬上限 2.1 秒。

输入框保留静态混色边，默认无额外发光；聚焦流光保留，汇聚与剥离时暂时暂停。设置新增默认开启的“发送文字水滴转场”，旧设置缺少该键时补默认值。与发送光环互斥；无法运行时回到原有反馈，不阻止真实提交。

公开 `sessions.binding(id).session` 的新增 pending requestId 确认提交；`uiConversation.binding(id).target('chat')` 的用户节点 `source.rpcId` 确认落点。两个相同文本同时进入 pending 时，按公开 pending 的接纳顺序消费对应手势快照。落点不能仅靠文字或最后一条消息决定。pending echo 缺少 requestId 钩子，仅在单个 transcript pending、单个 echo 且排版文字符合时使用。

所有文字只在内存保留，候选最长 1.5 秒、活动转场最长 2.1 秒。只修改临时装饰层与可逆遮罩属性；不更改 Lexical 内容、请求、焦点或业务状态。最多两条转场；每个快照最多 240 个可见字素，文字遍历上限 4000 个字素。附件不移动。

## 自动验证

类型检查、构建、36 项单元测试通过。测试覆盖相同消息的 requestId 对应、批量相同文字、未确认手势、IME、过期、切换会话、设置迁移与卸载。

`tools/verify-send-transfer.mjs` 加载实际 `lib/client.js`，用公开服务形状的受控夹具采样动画。执行前构建；环境需要可用的 Playwright 与 Chrome，Playwright 不属于产品运行时依赖。可通过 `LUMINA_PLAYWRIGHT_PATH` 指定验证工具模块位置，通过 `LUMINA_EVIDENCE_DIR` 指定输出目录。

采样得到 gather → fuse → edge-approach → edge-merge → edge-rest → emerge → detach → fly → unfold。字形 transform、液滴 path、颈部 path 与模糊半径都有变化，结束后遮罩和副本均为 0。额外验证卸载、减少动态、切会话、用户滚动、落点消失、节点替换、目标超时，以及下一份草稿不被隐藏。减少动态切换同时检查下一帧清理；受控时钟不能代替真实帧率测量。

## 尚待真实客户端验证

受控夹具不证明已安装客户端已加载新构建，也不证明其滚动、布局和公开服务通知时序完全一致。插件清单只在启动时读取，须完整退出并重开客户端。需继续核对启动条目、设置开关、真实发送录屏、多行/emoji/引用文本、自动滚动与性能预算。

当前缺少公开提交前原子钩子，手势快照须等待公开 pending 确认；若会话绑定尚未就绪、提交直接进入排队或 steering、文本转换不能匹配、落点不可见、可见文字超预算，就保留原有显示。不能将这些回退记为完整转场成功。

## 边缘液面修正

修正后的液体锚点位于输入框上边缘，和文字汇聚中心分开。SVG 局部液面与液滴共用连续形状：靠近时形成接触桥，吸收后独立液滴半径归零；液面短暂稳定，再形成向外的隆起，颈部拉长变细后才断开。液面残留随后回收。常规周期调整为 1150ms，以留出可见的融合和重新剥离时间；柔和 1350ms、鲜明 1000ms，活动装饰硬上限 2.1 秒。

透明水体使用独立 `--lumina-water-*` token，冷色来自客户端语义色（缺失时用已有蓝色预设），高光来自 `--lumina-hi`。不再消费品牌红作为水体或融化文字的颜色。液化阶段降低装饰组不透明度，恢复文字前回到原透明度；不使用背景截图或真实光学折射。

验证增加三个必要条件：融合中水滴与边缘连续连接；吸收完成后独立水滴半径为零；重新鼓起时颈部锚点位于同一条输入框边缘。颜色须在默认红色品牌预设下仍保持冷色水体。

## 客户端未触发的时序修复与诊断

用户报告真实客户端重启后完全没有水滴，不能用受控预览证明已修复。代码审计发现：安装时绑定尚未就绪会被外层 catch 永久静默停用；未选择会话时，首条发送的手势又因 face/chat 缺失被忽略。修复为先捕获有效手势的可见字形，允许无会话到新会话的首次绑定保留候选；已知会话之间切换仍立即清理。绑定失败保持列表订阅，仅在有候选时短时重试，最长不超过 1.5 秒；不得持续轮询正文或伪造提交。

设置新增发送转场状态与启动次数，仅包含枚举与计数，不含草稿、消息、会话或请求身份。区分未启用、绑定未就绪、等待提交确认、文字快照不可用、已启动、目标超时、中断与完成。只有真实客户端显示已启动并有实际发送画面，才可将客户端触发问题记为解决。

## 当前会话取错导致客户端不触发

真实客户端完全没有水滴，根因不是动画参数，而是适配层把当前会话 id 读成了 `sessions.list.getSnapshot().current`。客户端 `sessions.list` 的快照是 `{ ids, byId, phase, projectionsBySession }`，没有 `current` 字段，该值恒为 `undefined`，桥接层因此永远停在 `waiting`，手势快照无法与 pending 提交配对，转场不会启动。

当前会话的唯一公开身份是 `uiSession.current.getSnapshot().key`（官方客户端服务）。修复后改为订阅 `uiSession.current`，会话本体仍用 `sessions.binding(id).session`，对话视图仍用 `uiConversation.binding(id).target('chat')`；`pendingSubmissions` 的 `requestId`、`placement` 与 `time` 字段与客户端 `beginSubmission` 一致，用户消息落点仍以 `nodes.get(key).data.source.rpcId` 关联。

修复后类型检查、构建与 37 项单元测试通过；实机效果仍需完整退出重启后验收。

## 掉帧修复（真实客户端反馈）

转场触发后帧率严重下降，瓶颈有三处：goo 滤镜原本作用在**整组文字**上（每帧重新栅格化最多 240 个文字节点）；滤镜挂在铺满视口的液体 SVG 上，滤镜缓冲等于全屏；源文字与落点文字在不可见/已归位后仍每帧写样式。

修复后：滤镜只挂在**液体形状组**（滤镜区域=水滴包围盒），文字不过滤镜；源文字汇聚完成后一次性隐藏；落点文字归位后逐个停止写样式；模糊半径量化为 0.25 步进；液面采样点 25 → 13；并新增**帧预算守卫**——连续 3 帧超过 38ms 自动摘掉滤镜并标记 `data-lumina-transfer-quality="reduced"`，优先保证不卡帧。

视觉取舍：文字与液体的融化改为颜色渐变 + 缩放 + 淡出与液滴同步，不再依赖滤镜把字形轮廓融进液滴；液面、细颈与水滴自身的连续性仍由组内滤镜保证。真实帧率仍需客户端实测（60fps、无 >50ms 主线程长任务），受控预览的帧率不作验收依据。
