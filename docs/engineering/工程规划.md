## 1. 两条注册路径的语义差异（**最容易踩错的一点**）

官方 slot 目录（`packages/extensions/cordis-client-runner/src/client/slot-catalog.ts`）在 `CLIENT_NOTES` 第 3 条写着：

> Do NOT pass `priority`: the browser-half facade assigns one automatically...

**这条只对「动态插件」路径成立，对我们不成立。** 两条路径必须分清：

| | **Bundle 路径（我们）** | 动态插件路径（`cordis_define`） |
| --- | --- | --- |
| 入口 | `dsh plugin add` → profile bundle | 模型运行时写 JS |
| `ctx.slots` | 真实 `SlotRegistry` | `guard.ts` 的 `guardedSlots` 代理 |
| `priority` | **按传入值生效**（升序，最小者渲染） | 被 `env.allocatePriority()` **覆盖** |
| 同优先级同 cell | **抛异常** | 不会出现（优先级唯一） |

权威实现：`packages/client/ui-slots/src/index.ts:787-868`

```
single: 有同 priority 的占用者 → throw（不同 priority 才能遮蔽）
list:   必须给 id；同 id + 同 priority → throw；排序 priority → order
chain:  必须给 select
```

> 📌 因此本项目的 `-20` 优先级**必须保留**（`dsh-brand-studio` 用 `-10`）。
> 若误信 slot 目录那条 Note 而删掉 priority，我们会与 brand-studio 同为 `0`，**直接抛异常导致品牌区回落官方外观**。

### 3.1 命名决策

| 标识符 | 值 | 位置 | 约束 |
| --- | --- | --- | --- |
| npm 包名 | `@ratel-works/dsh-lumina` | `package.json.name` | 与安装命令一致 |
| Cordis 插件 id | `ui-lumina` | `cordis.patch.yml` + `src/index.ts` 的 `name` 导出 | patch `id` 是 loader entry key；插件 `name` 在 context 内唯一 |
| 浏览器模块 id | `@ratel-works/dsh-lumina` | `lib/client.js` 的 `__ModuleLoader__.load({ id })` | 必须等于包名 |
| 样式标签 | `<style data-plugin="ratel-lumina" data-effect="…">` | 运行时 | 每个效果一个标签，便于单独摘除 |

> 包名不带品牌（Ratel / DeepSeek 是配置项，见 [产品需求](../product/产品需求.md) §1）。
> 仓库目录名暂沿用 `rate-dsh-lumina`；对外包名是 `@ratel-works/dsh-lumina`。仓库名可在发布前改为 `ratel-dsh-lumina`，不影响包 id。

### 4.1 客户端产物契约（自实现预设的验收标准）

```js
window.__ModuleLoader__.load({
  id: "ratel-lumina",
  factory: (require) => {
    var module = { exports: {} };
    var exports = module.exports;
    Object.defineProperty(exports, Symbol.toStringTag, { value: "Module" });
    // … bundle …
    exports.apply = apply;
    exports.inject = inject;
    return module.exports;   // ← 必须是 module.exports
  }
});
```

`require` 只允许请求**模块表**里的 specifier（`react` / `react/jsx-runtime` / `react-dom` /
`@deepseek-ai/cordis` / `@deepseek-ai/dsh-client-ui-slots` /
`@deepseek-ai/dsh-client-runtime/client`）。其余依赖一律打进产物。

> 违反「只请求模块表」的后果是**运行时 throw**（require 是同步的，不能等）。

## 5. 规范体系（不引入 OpenSpec）

**形态**：
1. `.agents/notes/` 复刻官方 Agent Note 树（`proposed/implemented/rejected` × 6 class）。
2. `.agents/skills/dsh-lumina-dev/SKILL.md` 把本项目的开发规范做成 **DSH Skill**，模型可按需调用。
3. 现行真相源是 `docs/product/`（PRD + MVP）与 `docs/engineering/`；
   Agent Note 记录**决策与变更**；历史设计稿已删除，需要时从 git 历史取回。
4. 临时诊断报告、试跑记录、截图、日志和复现证据放 `.local/diagnostics/<日期-主题>/`，由 Git 忽略，不进入 `docs/` 或 `.agents/notes/`。排查完成后只将确认的约束和修复设计提炼进现行文档；有独立价值的长期决策才进入 Agent Note。正式文档不链接本地临时报告，交付用户明确要求的报告除外。

**为什么不引入 OpenSpec**（决策记录见 `.agents/notes/`）：

- OpenSpec 的 34 个 adapter **没有 DSH**，命令文件落在 `.claude/commands/opsx/` 等 DSH 不读的目录；
- `Requirement/Scenario` + `ADDED/MODIFIED/REMOVED` delta 体裁与中文设计散文正面冲突；
- `openspec/specs/` 与现有 `docs/` 构成双轨真相源；
- 为几个动效引入全局 Node CLI 与四级目录，边际收益为负。

**重新评估的触发条件**：扩成多包/多仓、团队 ≥3 人、需要 delta 规格历史或跨工具共享。

## 7. 安装与验证流程

```sh
# 一条龙：build → remove → 清 node_modules → add
bash tools/install-local.sh web
```

⚠️ 两条硬约束（[官方API面](官方API面.md) §9，已复核）：
1. **必须绝对路径**（`file:/绝对路径`），相对路径会被拼到 profile 目录下而失败；
2. **改源码后必须重装**——`file:` 安装是**快照拷贝**不是软链，源文件改动不会生效。

客户端**只在启动时**读取插件清单，**不支持热更新** → 改完必须重启 `dsh web` 或桌面端。
