## 0. 反返工原则

这张表是本文档的主线：每条返工源都在后面有对应的结构，而不是靠“写的时候注意”。

| # | 返工源 | 本设计的对策 |
| --- | --- | --- |
| R1 | 选择器散落在效果里，升级后到处改 | 选择器只存在于 `adapter/targets.ts`；效果层检索 `[data-` 必须零命中 |
| R2 | 每个效果各自建 observer | 全项目只有一个 streaming observer；其余效果消费根属性或纯 CSS |
| R3 | 伪元素被官方或其他效果占用 | `adapter/pseudo.ts` 统一申领 `::before` / `::after`，冲突时降级 |
| R4 | 把光标放错位置（native caret 不可动画） | Phase 0 探测；M3 把光标放到流式输出末尾，输入框只保留品牌色 |
| R5 | 颜色、时长、缓动散落 | L3 变量 + keyframes registry；效果只消费变量 |
| R6 | 运行时读取 SVG 资产（bundle 无 fs） | 构建期生成 `brand/generated.tsx`；运行时不读文件 |
| R7 | 新增配置字段破坏旧存档 | 加法式 schema：新增 `sessionActivity`，旧 payload 由 `parseConfig` 补默认 |
| R8 | 重装/切配置留下重复 `<style>` | `installStyle` 幂等；每次 render 先卸后装 |
| R9 | 先写效果、后补测试 | Phase 0 先落 fixtures 与 probe；每个效果先有失败用例 |
| R10 | `file:` 安装是快照，改了源码看不到 | 每个 Phase 门禁固定 `build → install:local → 重启 → 验收` |

> **一条硬规则：任何效果开始写之前，它依赖的 target 必须已在 L1 登记，并有 fixture 与 probe 通过。**
> 未登记的 target 不允许在效果层出现字符串。

### 1.2 依赖方向

| 模块 | 允许依赖 | 禁止 |
| --- | --- | --- |
| `platform/` | 官方 API（`ctx.slots` / `ctx.locale` / `ctx.effect`） | 任何效果、样式、配置实现 |
| `adapter/` | `platform/`、`core/types` | 效果、面板、配置 store |
| `effects/` | `adapter/`、`style/`、`brand/`、`core/types` | 直接 `document.querySelector`、直接 `ctx.slots`、直接官方包 |
| `style/` | 无（纯字符串与常量） | DOM、配置读取、条件分支 |
| `brand/` | React、`react/jsx-runtime` | 运行时文件读取、网络 |
| `panel/` | `core/config` 类型、诊断快照类型 | `ctx`、DOM 查询 |
| `index.ts` | 全部 | 业务逻辑 |

**效果层拿到的能力**由 `EffectContext` 注入，而不是 import 平台层：

```ts
interface EffectContext {
  config: LuminaConfig
  adapter: Adapter
  styles: StyleSink
  platform: PlatformFacade   // slots / locale / effect
  motion: MotionCapabilities
}
```

这样效果层可测试、可并行，也不会把官方 API 扩散到全库。

## 2. 启动、重配与卸载

### 2.1 apply 时序

```text
loader 执行 client.js
  → factory(require) 返回 module.exports
  → cordis 等待 slots / locale 服务
  → apply(ctx)
      1. createConfigStore()                    L4
      2. createPlatform(ctx)                    L0
      3. createAdapter({ platform })            L1：登记 targets、启动 streaming 观察
      4. createDiagnostics({ adapter })         L1/L4：只读快照
      5. createEffectRegistry(...)              L2
      6. locale.register('settings.lumina')     L0/L4
      7. installStyle('panel', panelCss())      L3/L4
      8. occupySlot('settings.section')         L0/L4
      9. render()                               首次应用
     10. config.subscribe(render)               配置变化重装
     11. ctx.effect(() => teardown, 'ratel-lumina: teardown')
```

### 2.2 render 的边界

`render()` 只做三件事，**不重建 adapter**：

1. 写根属性：`data-lumina` / `data-lumina-brand` / `data-lumina-intensity`；
2. 卸载旧效果（逆序）；
3. 按新配置安装效果。

adapter 的 streaming observer 跨配置存活；只有插件卸载时才销毁。

### 2.3 生命周期矩阵

| 事件 | 必须发生 | 不得发生 |
| --- | --- | --- |
| 首次 apply | 注册 locale、面板、效果；根属性就位 | 重复 `<style>`、重复 slot 注册 |
| 配置保存 | 先卸旧效果，再装新效果；根属性更新 | adapter 重建、面板闪断 |
| 总开关关闭 | 卸全部效果；面板仍可用；根属性 `off` | 留下空壳样式或占位元素 |
| slot 重新声明 | `slots.inject` 回调重新注册；旧 disposer 先释放 | 同一 slot 双注册、品牌双字标 |
| 另一标签页改配置 | `storage` 事件 → `render()` | 覆盖未保存草稿（面板自己处理冲突） |
| 插件卸载 | 逆序 teardown；移除全部 `<style data-plugin>` 与根属性 | 监听器、定时器、observer 残留 |
| 减少动态切换 | CSS 媒体查询即时生效 | 重装效果、闪一下 |

### 2.4 teardown 顺序

> `ctx.effect(callback)` **立即执行 callback**，并收集 callback 返回的 disposer。
> 必须写成 `ctx.effect(() => teardown, reason)`；把 teardown 本身当 callback 传入，
> 会在 apply 阶段立刻卸载插件（slot 注册、样式、根属性全部消失）。


```text
unsubscribe config
→ registry.dispose()        // 效果逆序
→ adapter.dispose()         // observer / 定时器 / 根属性
→ section disposer
→ panel style tag
→ locale disposer
→ removeAllStyles()
→ remove root attributes
```

顺序固定，测试按此断言。

## 3. L0 · 平台契约层

### 3.1 ctx 结构

沿用现有 `LuminaClientContext`，但把可选性写清楚：

```ts
interface LuminaClientContext {
  slots: {
    inject(key: string, callback: () => unknown): () => void
    register(options: unknown, component: unknown): () => void
  }
  locale: {
    register(namespace: string, dictionaries: Record<string, unknown>): () => void
    bind(namespace: string): (key: string) => string
  }
  /**
   * Run the body immediately and collect the disposer it returns.
   * The body must return the teardown; it is not the teardown itself.
   */
  effect(callback: () => unknown, reason?: string): void
}
```

`inject = ['slots', 'locale']`。locale 在已安装客户端存在；不在类型上做 optional，避免调用处到处 `?.`。

### 3.2 occupySlot

所有 slot 注册走同一个 helper，禁止各效果自己写 try/catch：

```ts
function occupySlot(
  slots: SlotRegistryLike,
  key: string,
  options: Record<string, unknown>,
  component: unknown,
): () => void

// 内部：先直接 register；slot 尚未声明时退回 inject 等待声明。
// 两条路径都只注册一次；disposer 统一释放。
```

失败分类：

| 错误文本 | 分类 | 处理 |
| --- | --- | --- |
| `already has a registration` / `already has an entry` | 占用冲突 | warn + 降级 |
| `slot` + `not declared` / `unknown` | 声明缺失 | warn + 诊断标记 |
| 其他 | 编程错误 | warn + 诊断标记（不重试） |

### 3.3 slot 规格（已核对）

| slot | kind | 我方 options | 宿主给组件的 props |
| --- | --- | --- | --- |
| `sidebar.brand.mark` | single | `priority: -20` | `{ size: 24 }` |
| `sidebar.brand.name` | single | `priority: -20` | `{}` |
| `conversation.hero.brand.mark` | single | `priority: -20` | `{ size: 34, className }` |
| `settings.section` | list | `id/order/label/locale/inject` | 壳绑定 `useSettings/save/t` |

> `sidebar.brand.mark` 在折叠与展开两种侧栏状态下都会被渲染；组件不得假设宽度。
> `settings.section` 的 `label` 必须是 thunk；`locale` 用 `settings.lumina`。

### 3.4 能力探测

| 能力 | 探测 | 用途 |
| --- | --- | --- |
| `@property` | `typeof CSS.registerProperty === 'function'` | M2 角度插值 |
| `conic-gradient` | `CSS.supports('background', 'conic-gradient(red, blue)')` | M2 |
| `mask-composite` | `CSS.supports('mask-composite', 'exclude')` | M2 |
| `matchMedia` | `typeof window.matchMedia === 'function'` | 减少动态 |
| `useId` | React 18 固定可用 | 品牌 SVG id 去重 |

探测结果在 adapter 创建时算一次，缓存；不随 DOM 变化重算。

## 4. L1 · 适配层

### 4.1 关键决策：CSS-first，而不是“句柄优先”

架构文档把 L1 描述成“解析成句柄 + 观察重绑”。本设计在 v1 做一个明确收敛：

- **纯 CSS 效果不需要活句柄。** 选择器写进样式表，元素出现/消失由浏览器负责；
  再建一套 handle + observer 只会增加生命周期 bug。
- L1 对 CSS 效果提供 **选择器**，对 JS 效果提供 **查询/校验**，对诊断提供 **probe**。
- 全项目只有一个 observer，且只服务 streaming 状态，不做通用 DOM 重绑框架。

这不是放弃适配层，而是把适配层收成三件可测的东西：
**目标登记表 + 选择器组装 + 一个状态观察者。**

> 与[架构设计](架构设计.md) §5 的差异：v1 不实现结构推断与通用句柄。理由见 §11 D1/D2。
> 架构承诺仍然成立：目标标识改名时，只改 `targets.ts` 一处。

### 4.2 语义目标登记表

| TargetId | kind | 规范选择器 / slot | 用途 | 校验 |
| --- | --- | --- | --- | --- |
| `composerCard` | css | `[data-composer-card]` | M2 / M4 | 可见、有尺寸、含输入或按钮 |
| `composerInput` | css | `[data-composer-input]` | M3（仅 caret-color） | `contenteditable` 或可聚焦 |
| `composerButton` | css | `[data-composer-card] button:not([disabled])` | M4 | 是 button 且未禁用 |
| `lexicalCursor` | css | `[data-lexical-cursor]` | M3（可选块光标呼吸） | 真实元素、有非零尺寸 |
| `streamingTail` | css | 见下方候选选择器 | M3 | 恰好一个可见文本块 |
| `streaming` | state | `[data-streaming]` | M2/M4 | 全局存在性 |
| `sessionRow` | css | `[data-row-key^="session:"]` | M8 | `role=treeitem` |
| `sessionRunning` | css | `[data-row-key^="session:"] svg[data-state="ongoing"]` | M8 | SVG、14×14 |
| `brandMark` | slot | `sidebar.brand.mark` | M1 | 注册成功 |
| `brandName` | slot | `sidebar.brand.name` | M1 | 注册成功 |
| `heroMark` | slot | `conversation.hero.brand.mark` | M5 | 注册成功 |
| `settingsSection` | slot | `settings.section` | M6 | 注册成功 |

**已核对的 DOM 事实**（来自 `app.asar`）：

- `[data-composer-card]` 是 `div`，`position: relative`，内部有 `[data-composer-overlay]`；
  `cardWorkspaceTrigger` 变体已经占用 `::after`（虚线边框），所以 M2/M4 必须申领伪元素。
- `[data-lexical-cursor]` 是 Lexical 的 **block cursor**：`div[contenteditable=false]`，
  由 Lexical 在块级光标场景插入；**不是 native caret**。
- native caret 由 `.yhfFVG_input` 的 `caret-color` 控制，不能呼吸；M3 因此把呼吸光标放到
  流式输出末尾，输入框只留品牌色。
- `[data-streaming]` 挂在 AssistantMarkdown 根和 ReasoningRow summary 上，
  **不在输入框里**；因此 `[data-streaming] [data-lexical-cursor]` 永远不会匹配。
- AssistantMarkdown 的结构是 `[data-streaming] > div.body > 最后一个块`；流式文本通常是
  `<p>`，也可能是 `<li>`。M3 的 `streamingTail` 候选：
  - `[data-streaming] > div > :is(p, h1, h2, h3, h4, h5, h6):last-child`
  - `[data-streaming] > div > :is(ul, ol):last-child > li:last-child`
  - `<pre>` 不挂（光标不在行内，视觉落点错误）
- `[data-row-key="session:<id>"]` 是会话行；运行中指示是 `svg[data-state="ongoing"]`。

### 4.3 选择器策略（v1）

```ts
interface Target {
  id: TargetId
  kind: 'css' | 'slot' | 'state'
  selectors: string[]       // 第 1 条为规范，其余为已证实的历史标识
  validate?: (el: Element) => boolean
}
```

- CSS 效果把 `selectors` 用逗号合并，一次注入；不做运行时“猜哪个命中”。
- **v1 只收规范 + 已证实的历史标识**，不写结构推断。
  没有真实失配案例时写结构推断只能靠猜；猜错比找不到更糟。
- 结构推断的类型预留（`Strategy`），等第一次真实升级失配时再加，并补 fixture。
- 每条选择器必须能在 `tools/verify-hooks.mjs` 里被计数。

### 4.4 选择器组装

```ts
function scope(selector: string): string {
  return `[data-lumina="on"] ${selector}`
}

function cssSelector(id: TargetId): string {
  const target = TARGETS[id]
  return target.selectors.map(scope).join(',\n')
}
```

- 效果层只拿 `cssSelector('composerCard')`，不拼字符串。
- 根属性 `data-lumina="on"` 是唯一总作用域；`off` 时所有效果样式不匹配。
- 变量发布也用同一作用域；见 §6。

### 4.5 JS 查询与校验

只给需要真实元素的场景：

```ts
function query(id: TargetId): Element | null        // 第一个通过 validate 的
function queryAll(id: TargetId): Element[]
```

使用场景只有：

- M4 发送闪光：拿到 `composerCard`，设置 `data-lumina-sent`；
- 诊断：统计每个 target 的命中数；
- Phase 0 探测脚本（不进生产代码）。

纯 CSS 效果禁止调用 `query`。

### 4.6 伪元素申领

```ts
function claimPseudo(id: TargetId, preferred: 'before' | 'after'): 'before' | 'after' | null
function releasePseudo(id: TargetId, slot: 'before' | 'after'): void
```

判定：

- `getComputedStyle(el, '::before').content` 为 `none` / 空，且没有其他效果申领 → 可用；
- 否则尝试另一个；
- 两个都不可用 → 返回 `null`，效果降级并在诊断里记录 `pseudo-occupied`。

分配：

| 效果 | 首选 | 备用 | 说明 |
| --- | --- | --- | --- |
| M2 边框流光 | `::before` | `::after` | 1.5px 光带，挖空中心 |
| M4 发送闪光 | `::after` | `::before` | 一次性扩散环 |

两者同时安装时，按安装顺序申领；先到先得。`cardWorkspaceTrigger` 的 `::after` 已被官方占用，
所以该变体下 M4 闪光可能降级，M2 仍可用。

### 4.7 唯一 observer：streaming 状态

```text
MutationObserver(document.body, {
  subtree: true,
  attributes: true,
  attributeFilter: ['data-streaming'],
})
→ debounce 120ms
→ next = document.querySelector('[data-streaming]') !== null
→ 若变化：写 root data-lumina-streaming="on" / 移除
→ 通知订阅者（M2 用根属性；M4 用一次性事件）
```

规则：

- **只有这一个 observer**；效果层不得 new MutationObserver。
- 只观察一个属性，不观察 childList；元素出现/消失最终都会带来 `data-streaming` 属性变化。
- 初始同步一次，避免首屏已经流式时漏状态。
- 卸载时 `disconnect`、清 timer、移除根属性。
- 订阅接口：`onStreamingChange(cb): () => void`；回调参数 `{ streaming: boolean, started: boolean, ended: boolean }`。

### 4.8 诊断 probe

```ts
interface TargetProbe {
  id: TargetId
  kind: 'css' | 'slot' | 'state'
  matched: number
  status: 'ok' | 'missing' | 'degraded'
  reason?: string
}

function probeAll(): {
  targets: TargetProbe[]
  slots: Record<string, boolean>
  reducedMotion: boolean
  capabilities: Record<string, boolean>
  generatedAt: number
}
```

- 面板打开或点“重新检查”时调用；不做常驻轮询。
- `missing` 只表示当前页面没命中，不一定代表升级失败（例如不在会话页）。
- 诊断只读，不修改 DOM、不触发效果安装。

### 4.9 失败语义

- 空结果是合法值，不抛错；效果降级。
- 选择器缺失、伪元素占用、slot 冲突、能力不支持都写入诊断。
- 异常只用于编程错误（例如 target 未登记），并在开发期测试里暴露。

## 5. L2 · 效果层

### 5.1 效果契约

```ts
interface Effect {
  id: EffectId
  requires: TargetId[]
  install(ctx: EffectContext): () => void
}

type EffectState =
  | { state: 'installed' }
  | { state: 'skipped'; reason: 'disabled' | 'master-off' }
  | { state: 'failed'; reason: string }
```

`registry.apply(config)`：

1. 卸旧效果（逆序）；
2. 对每个 id：总开关/逐效果开关 → 执行 `install`；
3. `try/catch` 包住 install 与 dispose；
4. 记录状态，更新诊断；
5. 返回 disposer。

失败隔离不依赖 React error boundary；效果初始化失败只影响自己。

### 5.2 M1 · 品牌动效

| 项 | 实现 |
| --- | --- |

### 5.4 M3 · 打字机光标（流式末尾 + 输入框）

Phase 0 探测已确认：

- `[data-lexical-cursor]` 是 Lexical 的 **block cursor**（`div[contenteditable=false]`），
  只在块级光标场景出现；
- 正常输入时的 native caret 由 `caret-color` 控制，**没有可用于动画的元素或伪元素**；
- `[data-streaming]` 在 AssistantMarkdown 根上，与输入框不在同一子树。

因此做两段，共用一个 `caret` 开关：

1. **流式末尾**：伪元素光标，视觉主效果；
2. **输入框**：M9 自定义 overlay，跟随折叠选区；native caret 只在 overlay 可见时隐藏。

M3 主表（流式末尾）：

| 项 | 实现 |
| --- | --- |
| target | `streamingTail`（Phase 0 固定选择器） |
| 候选选择器 | `[data-streaming] > div > :is(p,h1,h2,h3,h4,h5,h6):last-child`；`[data-streaming] > div > :is(ul,ol):last-child > li:last-child` |
| 视觉 | 2px 官方蓝渐变竖线 + 柔光；`display:inline-block`，`height:1.05em`，`margin-left:2px`，圆角 1px |
| 动画 | `lumina-caret-breathe`，周期 `--lumina-caret-stream`（流式时） |
| 布局 | 伪元素挂在最后一个文本块末尾；验收必须确认不换行、不遮字、不改变行高 |
| 减少动态 | `animation:none; opacity:1` |
| 输入框 | M9 自定义 overlay（§5.4.1）；native caret 在 overlay 可见时透明，其余时间恢复 |
| 伪元素冲突 | Phase 0 检查最后文本块的 `::after` content；非空则改用 `::before` 或放弃 |
| 失败 | 选择器不命中 → 无光标；诊断标记；不影响输入、选区、复制 |
| 不做 | 不改输入框尺寸/位置；不在选区非折叠或 IME 时显示 overlay |

CSS 形态（选择器由 L1 组装）：

```css

  display: inline-block;
  width: 2px;
  height: 1.1em;
  margin-left: 2px;
  margin-right: -2px;
  vertical-align: -0.15em;
  border-radius: 1px;
```

### 5.4.1 M9 · 输入框自定义光标（同一 `caret` 开关）

原生 caret 无法做透明度动画，所以用 overlay：

| 项 | 实现 |
| --- | --- |
| 元素 | `span.lumina-caret-overlay`，**fixed 定位在 `document.body`**（不依赖卡片 padding/overflow）；2px 官方蓝渐变 + 柔光，`pointer-events:none`，`aria-hidden` |

### 6.2 强度映射：逐效果时长 token

`MVP §2.1` 的数值是唯一真相。这些数值**不是同一个倍率**：

- 品牌：6.0 / 3.6 = 1.667，2.6 / 3.6 = 0.722；
- 边框：9.0 / 6.0 = 1.5，4.2 / 6.0 = 0.7；
- 光标：1.6 / 1.15 = 1.391，0.85 / 1.15 = 0.739。

因此不能用单一 `--lumina-duration-scale`，否则至少两个效果会偏离已定稿参数。
改为**逐效果时长 token**，CSS 与 JS 共用同一张表：

| token | normal | subtle | vivid | 使用方 |
| --- | --- | --- | --- | --- |
| `--lumina-brand-sweep` | 3.6s | 6.0s | 2.6s | M1 |
| `--lumina-composer-breathe` | 3.6s | 4.8s | 2.8s | M2 平时 |
| `--lumina-composer-focus` | 4.0s | 6.0s | 2.8s | M2 聚焦 |
| `--lumina-composer-stream` | 2.4s | 3.6s | 1.68s | M2 发送时 |
| `--lumina-caret-idle` | 1.15s | 1.6s | 0.85s | M3 |
| `--lumina-caret-stream` | 0.72s | 1.0s | 0.55s | M3 |
| `--lumina-press` | 140ms | 180ms | 110ms | M4 |
| `--lumina-flash` | 520ms | 620ms | 420ms | M4 |
| `--lumina-hero` | 320ms | 420ms | 240ms | M5 |
| `--lumina-hero-glow` | 900ms | 1100ms | 700ms | M5 |
| `--lumina-session` | 2.4s | 3.2s | 1.8s | M8 |

发布方式：

```css
html[data-lumina="on"][data-lumina-intensity="normal"] {
  --lumina-brand-sweep: 3.6s;
  --lumina-composer-breathe: 3.6s;
  --lumina-composer-focus: 4s;
  --lumina-composer-stream: 2.4s;
  --lumina-caret-idle: 1.15s;
  --lumina-caret-stream: .72s;
  --lumina-press: 140ms;
  --lumina-flash: 520ms;
  --lumina-hero: 320ms;
  --lumina-hero-glow: 900ms;
  --lumina-session: 2.4s;
}

/* subtle / vivid 同表，各写一份；值由 style/tokens.ts 生成，不手写三份 */
```

- 边框的 focus/stream 与 hero-glow 是派生值（按 idle 比例与视觉节奏推导），
  首次实机验收后可微调；其余数值来自 MVP §2.1 定稿表；
- `style/tokens.ts` 导出 `DURATIONS`（单一数据源），同时生成 CSS 与 JS 查询；
- JS 只读一个值：`durationMs(intensity, 'flash')`，供 M4 timer；
- 删除 `intensityFactor` 的 0.6/1.4 语义，避免两套倍率；
- 测试断言 CSS token 与 `DURATIONS` 一致。

| --- | --- | --- |
| `base` | 变量、keyframes、紧急停止、reduced-motion 兜底 | 每次 render 重建 |
| `brand` / `composer-glow` / `caret` / `press` / `hero` / `session-activity` | 每个效果自己的 CSS | 随效果装卸 |
| `panel` | 设置页 CSS | 插件生命周期 |

`installStyle(effect, css)`：

- 先移除同 `data-effect` 的旧标签，再插入；
- 返回 disposer，重复调用安全；
- 卸载时 `removeAllStyles()` 兜底。

### 6.6 特异性与 `!important`

- 默认不用 `!important`；用 `[data-lumina="on"]` 提高作用域特异性。
- 唯一允许的 `!important`：M8 覆盖官方 `_spinnerMotion` / `_spinnerArc` 的动画属性；
  必须限定在 `[data-row-key^="session:"] svg[data-state="ongoing"]` 内。
- 不覆盖官方 `transition` 简写之外的其他属性；不改 `background` / `border` 的官方状态色。

#### 6.6.1 动效属性例外

“只动 transform / opacity”是默认规则。实现前把例外固定下来，避免实现时反复争论：

| 效果 | 属性 | 类型 | 约束 |
| --- | --- | --- | --- |
| M2 | `--lumina-angle`（驱动 `conic-gradient`） | paint（注册自定义属性） | 只作用于 1.75px 边框；不触发 layout；不支持时保留静态双色环 |
| M5 | `filter: blur()` / `drop-shadow()` | 一次性 composite | 只在挂载时播放一次；不常驻 |

其余效果只用 `transform` / `opacity`。任何效果都不得动画
`width` / `height` / `top` / `left` / `margin` / `padding`。

### 6.7 减少动态

每个效果自带 `@media (prefers-reduced-motion: reduce)` 分支，覆盖 `::before` / `::after`：

```css
@media (prefers-reduced-motion: reduce) {
  [data-lumina="on"] .lumina-shine,
  [data-lumina="on"] [data-composer-card]::before,
  [data-lumina="on"] [data-lexical-cursor],
  [data-lumina="on"] svg[data-state="ongoing"] > g { animation: none !important; }
}
```

另有 base 的全局兜底；两层都保留，防止某个效果漏写。媒体查询只用于动效，不用于主题。

## 7. L4 · 配置与设置页

### 7.1 schema

```jsonc
{
  "version": 1,
  "master": true,
  "brand": "deepseek",          // deepseek | ratel（ratel 待 O1）
  "intensity": "normal",        // subtle | normal | vivid
  "effects": {
    "brand": true,
    "composerGlow": true,
    "caret": true,
    "press": true,
    "hero": true,
    "sessionActivity": true     // 新增；旧 payload 由 parseConfig 补 true
  }
}
```

- 不升 `version`：新增字段是加法，旧 payload 仍合法；
- 非法值一律回默认，不抛错；
- `effects` 缺字段补默认；未来新增字段同理；
- 默认 `brand` 改为 `deepseek`，与 PRD 一致；`ratel` 在面板禁用。

### 7.2 store 与 render

沿用 `createConfigStore`，补：

- `intensity` 变化 → 根属性 `data-lumina-intensity` 更新；
- `brand` 变化 → 根属性 `data-lumina-brand` 更新；
- `effects` 变化 → 只重装受影响的效果（可以全量重装，六个效果成本可接受；
  v1 选全量，逻辑简单，行为可预测）。

### 7.3 面板结构

- 总开关；
- 品牌预设（deepseek 可选；ratel 禁用 + 「待发布」）；
- 强度三档；
- 六个效果开关（master 关闭时置灰）；
- 预览（迷你输入框 + 品牌条 + 会话进行中光点）；
- 诊断折叠区：target 命中表、slot 状态、效果状态、能力探测、版本 / 复制诊断；
- 恢复默认 / 取消 / 保存。

### 7.4 inject face 与 hooks

```ts
inject: () => ({
  hooks: { settings: configStore },              // useSettings
  save: (next: LuminaConfig) => configStore.commit(next),
  probe: () => diagnostics.probeAll()            // 普通 props，不依赖 hooks 命名约定
})
```

- 组件不接触 `ctx`；
- 诊断用普通 `probe` prop，避免“inject.hooks 的 key 是否自动生成 `useDiagnostics`”这个未经验证的假设；
- 诊断在面板挂载时 probe 一次，提供“重新检查”按钮；不常驻轮询。

### 7.5 无障碍

- 每个分段控件用 `role="radiogroup"` + `aria-checked`；
- 总开关/效果开关有 label 与 hint；
- 保存/取消有明确 disabled 状态；
- 诊断表用 `<table>` + caption，或 definition list；
- 减少动态横幅不隐藏开关，只置灰；
- 键盘可达：Tab 顺序、focus ring 用 `--dsw-focus-ring-*`。

### 7.6 迁移路径

保持扁平字段，未来切 `settings.plugin.item` 时：

- Host 半 `installSettingsSection` + schema；
- Client 半 `settings.plugin.item` + `key: 'lumina'`；
- 写入 `scope.set(field, value)`；
- 诊断 / 面板 / 效果代码不动。

## 8. 交叉关注点

### 8.1 失败隔离与日志

统一前缀 `[ratel-lumina]`，固定分类：

| 分类 | 例子 | 行为 |
| --- | --- | --- |
| `slot-conflict` | 同 priority 竞争者 | warn，降级 |
| `slot-missing` | 声明不存在 | warn，诊断 |
| `target-missing` | probe 0 命中 | 不 warn（可能不在对应页面），诊断 |
| `pseudo-occupied` | before/after 都被占 | warn，效果降级 |
| `effect-failed` | install 抛错 | warn，其他效果继续 |
| `capability-missing` | @property 不支持 | info，走降级 |

不得把用户配置值、会话内容、模型输出打进日志。

### 8.2 性能

- 持续型：M1 品牌流光、M2 边框流光（页面常驻）；
- 条件持续型：M3 流式光标（仅 `[data-streaming]` 时）、M8 会话进行中
  （仅运行中的会话，替换官方 spinner）；
- 触发型：M4 按压/闪光、M5 首屏入场；
- 严格页面常驻只有 2 条（品牌 + 边框），与 PRD §8 一致；
  光标只在流式时存在，M8 只在运行中会话存在；
- observer：1 个，单属性，120ms 防抖；
- 不做 rAF 循环、不做布局测量循环；
- M4 闪光只做一次 `offsetWidth` 重排，频率受发送次数限制；
- 默认只改 `transform` / `opacity`；例外见 §6.6.1，且不得引发 layout；
- M4 闪光为 `transform` + `opacity` 的扩散环，不用 `box-shadow`；
- M8 覆盖旋转与透明度，不加持续 `filter`；
- 图片/资产全部内联，无网络请求。

### 8.3 安全与隐私

- 不联网、不上传、不读会话内容、不写业务状态；
- localStorage 只存设置；
- 不创建 `<input type=file>`、不引入外部 URL；
- 诊断只包含选择器命中数、能力布尔值、版本，不含文本内容。

### 8.4 兼容与升级

- 用“标识是否存在”做版本信号，不读版本号；
- target 选择器集中在 `targets.ts`；升级后跑 `tools/verify-hooks.mjs`；
- 新增历史选择器 = 在 `selectors` 数组加一条 + 补 fixture，不改效果；
- 钩子消失 = 静默降级 + 面板诊断，不报错。

### 8.5 可观测性

- 面板诊断区：用户可自查；
- 控制台只输出分类 warn/info；
- 可选 `window.__LUMINA_DIAG__ = () => probeAll()`：只读、冻结、namespaced；
  不挂业务对象，不修改运行时。

### 8.6 构建与安装

- 客户端产物契约不变：`window.__ModuleLoader__.load`、`return module.exports`、
  只 `require` 模块表；
- `generated.tsx` 入库，`npm run gen:brand` 负责再生成；
- `npm run build` → `npm test` → `install:local web` → 重启 → 验收；
- 测试读取 `lib/client.js`，因此测试前必须先 build；CI 顺序固定。

## 11. 关键决策与开放项

### 11.1 已定决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | L1 v1 为 CSS-first，不做通用句柄/重绑 | CSS 效果不需要活句柄；少一套生命周期就少一类 bug |
| D2 | v1 不做结构推断，只收规范 + 历史选择器 | 没有真实失配案例时结构推断只能猜；猜错比找不到更糟 |
| D3 | M3 两段：流式末尾伪元素 + 输入框 overlay；同一 `caret` 开关 | native caret 不可动画；两处都做才能覆盖“打字机”与“输入”两个场景 |
| D4 | M8 作为第六个效果，带独立开关 | 产品原则：每个效果可单独关闭 |
| D5 | 伪元素统一申领 | 官方 `cardWorkspaceTrigger` 已占 `::after`，不申领会静默失败 |
| D6 | 品牌资产构建期生成 TSX | bundle 无 fs；运行时 fetch 会引入网络与 CSP 风险 |
| D7 | 默认品牌 `deepseek`，ratel 禁用 | 与 PRD 一致；ratel 资产未就绪 |
| D8 | 不做侧栏按钮按压 | 只有 hash 类名可用，违反硬约束；输入区按钮已覆盖主要场景 |
| D9 | 严格常驻 2（品牌 + 边框）；流式光标与会话进行中为条件持续；按压/首屏触发 | PRD §8 的 ≤2 成立；数字只写技术详细设计，不写 Skill |
