## 1. 首发

```sh
# 1. 质量门禁
npm run typecheck
npm test
npm run build
npm run check:dsh   # DSH 升级过则必须通过（见 docs/engineering/dsh-compat）
npm pack --dry-run

# 2. 发布到 npmjs（scoped 包必须 public）
npm publish --access public --registry=https://registry.npmjs.org/ --otp=<6位验证码>

# 3. Git 标记
git tag v0.3.0
git push upstream main --tags
```

`npm publish` 会触发 `prepare`，自动重新构建；`files` 只包含构建后的 `lib/`、patch、README
和 hero 图。不要提交 `lib/`（它被 `.gitignore` 忽略），npm 包会自己带。

## 2. 如果 `@ratel-works` scope 不是你的

有两个选择：

1. 在 npm 创建/加入 `ratel` org，然后发布；
2. 改用你拥有的 scope，例如 `@golddream-y/dsh-lumina`。

改 scope 不只改 `package.json.name`：`tsdown.config.ts` 的 `PACKAGE_ID`、`cordis.patch.yml`
的 `name`、profile 安装 spec、README/文档里的包名都要一起改。不要在首发后随意换名——
一个 profile 同名包只能装一个，换名等于迁移。

## 4. 商店如何发现

商店（如 `dsh-plugin-shop`）是**自动抓取**的，不需要单独提交：

- npm 包在 `package.json.keywords` 里带 **`dsh-plugin`** 或 **`deepseek-harness`**；
- 或 GitHub 仓库带同名 **topic**，且根 `package.json` 有 `name` + `dsh.bundle`；
- 每天构建一次，通过自动检查后第二天出现在商店；
- 不发布 npm 的仓库路径要求把构建产物提交进 Git（`lib/` 不能忽略），否则会被 `requires-build` 拒绝。

本包已声明：

- `keywords: ["dsh-plugin", "deepseek-harness", ...]`
- `dsh.bundle.patch`
- `dsh.catalog`（category `ui`、中英文 summary、capabilities）
- `repository`、`homepage`、`bugs`、`license`
- `engines.dsh: ">=0.2.1-rc.2 <0.3.0-0"`

`dsh.catalog` 是可选声明；不写也会从 npm `description` 生成摘要，但分类会是 `other`，
所以这里显式声明 `ui`。

商店卡片会检查：

- `dsh.bundle` 是否存在；
- license / repository 是否可审查；
- 是否 deprecated；
- `engines.dsh` 和 `@deepseek-ai/dsh*` peer 是否覆盖读者版本；
- `dsh.catalog` 字段是否合法。

自动发现不等于人工审核；商店卡片不提供沙箱承诺。

## 5. 以读者身份验证

发布后，用干净的 `DSH_HOME` 安装一次，避免本地 profile 掩盖问题：

```sh
export DSH_HOME="$(mktemp -d)"
dsh plugin --profile web add @ratel-works/dsh-lumina@0.3.0
dsh --profile web --no-open --port 0
```

打开打印的地址，确认：

1. 插件出现在 profile `dsh.profile.bundles`；
2. 品牌、设置页 Lumina 和当前启用的效果可见；
3. 控制台无 `cannot occupy` / `effect failed` / slot crash。

## 6. 常见失败

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ENEEDAUTH` | 未登录 npmjs | `npm login --registry=https://registry.npmjs.org/` |
| `E404` / `E403` scope | `@ratel-works` 不归你 | 创建 org 或换 scope |
| 发布到 npmmirror | 当前 registry 是镜像 | `publishConfig.registry` 已固定 npmjs；命令也显式带 `--registry` |
| 安装后没有插件层 | 包缺 `dsh.bundle` 或 profile 行没加 | 检查 `dsh.profile.bundles`；`dsh plugin add` |
| 商店不收录 | 缺 keyword / license / repository / description | 补齐后等下一轮构建 |
| `requires-build` | GitHub 路径没提交 `lib/` | 用 npm 发布，或提交构建产物 |
| 读者安装被拒 | `engines.dsh` / peer 范围不含其版本 | 调整范围；预发布要显式覆盖 |
| pnpm 11 拒绝 build | 包在安装时跑构建脚本 | 发布预构建 `lib/`，不要让读者构建 |

## 8. awesome-dsh-plugin 收录

[awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md)
是另一个独立列表，和 npm 商店自动抓取不同，需要提交 **一个 YAML 文件**。

文件路径：

```text
data/plugins/golddream-y__ratel-dsh-lumina.yml
```

可直接提交的文件位于 [收录条目](../distribution/golddream-y__ratel-dsh-lumina.yml)，描述与 `package.json` 的中英文 catalog summary 保持一致。将它复制到对方仓库上述路径即可，不需要改对方 README。

内容：

```yaml
url: https://github.com/golddream-y/ratel-dsh-lumina
name: golddream-y/ratel-dsh-lumina
category: ui
description:
  en: 'Let interaction glow. A subtle layer of motion for DeepSeek Harness, with customizable effects and reduced-motion support.'
  zh: '让交互，泛起流光。为 DeepSeek Harness 添一层恰到好处的动效，支持效果调整并跟随系统「减少动态效果」。'
```

注意：

- 中英文描述统一加引号，避免后续含 `: ` 时被 YAML 误解析；
- 仓库已加 `dsh-plugin` / `deepseek-harness` topic；
- 根 `package.json` 已有 `dsh.bundle`；
- 已加 `screenshots.json`（README hero），市场可展示截图；
- 必须等仓库创建满 **1 天**：本仓库创建于 `2026-10-21 16:21 UTC`，
  因此 PR 最早在 **2026-10-22 16:21 UTC / 2026-10-23 00:21 +08** 提交；
- 一个 PR 只加这一条；不要手工改 README。
- npm 已发布，条目优先走 npm；GitHub Release 里的预构建 tarball 仍保留，作为
  读者/镜像无法访问 npm 时的备用安装源。

PR 流程：

1. Fork `awesome-dsh-plugin/awesome-dsh-plugin`；
2. 新建上面的 YAML 文件；
3. 提交 PR，标题例如 `Add Ratel Lumina`；
4. 等 CI 和 maintainer 审核；分类不准确时维护者会直接改，不会打回。

## Changelog 编写规则

- 以“上一个已发布版本 → 本次最终交付版本”为比较基准，不把工作区迭代过程当作发布历史。
- “修复”仅用于上一个已发布版本中确实存在的问题。若问题只发生在本轮未发布的新功能开发期间，合并进新功能的最终行为描述，不单列修复项。
- “优化”须明确基准。新效果内部的调参、重写和性能调整可归入实现说明，不暗示上一版本已经具备此效果。
- 合并反复试验、用户反馈与中间方案，只保留最终能力、兼容性、已知限制和必要验证事实。开发过程另记需求文档或决策记录。
- 发布前逐条对照上一版本标签；不能确认已发布影响面的条目不使用“修复”，也不以内部实现过失充当用户更新价值。
