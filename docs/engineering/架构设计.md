## 1. 设计前提

目标客户端是**持续演进**的第三方产品。它的界面不是我们的，随时会变。
把"将会变"当成常态设计，而不是当成风险来打补丁。

不稳定的形态有三种，**必须两两分开处理**，因为防御手段完全不同：

| 形态 | 具体表现 | 后果 |
| --- | --- | --- |
| **标识漂移** | 语义钩子改名、新增、移除 | 效果静默失效 |
| **结构漂移** | 同一语义的东西换了承载方式（元素变伪元素、层级调整） | 选择器命中但样式无效，或命中错节点 |
| **生命周期漂移** | 目标随会话切换被销毁重建 | 绑定一次后失效，或重复绑定 |

对应的三条设计承诺：

1. 标识漂移 → **改动收敛到一个文件**，不扩散到效果层
2. 结构漂移 → **差异在适配层被吞掉**，效果层只看到统一句柄
3. 生命周期漂移 → **只有一个观察者**，由适配层统一负责重绑

## 2. 分层总表

五层，自下而上。**依赖方向严格向下：同层可并列，上层不得反向依赖，下层不得知道上层。**

```
┌─ L4 配置层 ─────────────────────────────────────┐
│  封闭集合的配置模型 · 设置页（视图）· 诊断汇总      │
│  读效果层健康状态；不接受任意输入                  │
└───────────────────────┬─────────────────────────┘
                        │ 读状态 / 写配置
┌─ L3 表达层 ───────────┴─────────────────────────┐
│  关键帧 · 品牌资产 · --lumina-* 变量              │
│  纯静态，无逻辑、无 DOM                            │
└───────────────────────┬─────────────────────────┘
                        │ 只读素材
┌─ L2 效果层 ───────────┴─────────────────────────┐
│  brand · composerGlow · caret · press · hero     │
│  声明「需要哪些语义目标」，零选择器                 │
└───────────────────────┬─────────────────────────┘
                        │ 「我要输入框卡片」→ 句柄
┌─ L1 适配层 ───────────┴─────────────────────────┐
│  探测 Probe · 解析 Resolve（策略链）· 观察 Observe │
│  唯一允许出现选择器的地方                          │
└───────────────────────┬─────────────────────────┘
                        │ 官方扩展点
┌─ L0 平台契约层 ───────┴─────────────────────────┐
│  slot 注册 · locale · 能力探测                    │
│  唯一允许直接依赖官方 API 的地方                    │
└─────────────────────────────────────────────────┘
```

两个视觉特征值得注意：

- **越往下越稳定，越往上越多变。** L0 随官方版本变，L4 随产品需求变；所以 L1 必须薄——它是唯一同时贴近"会变的东西"和"我们的代码"的层。
- **L1 是唯一的窄腰。** 所有对 DSH 结构的认知都必须穿过这一个窄口；没有第二条路。

| 层 | 名称 | 一句话职责 | 允许依赖 |
| --- | --- | --- | --- |
| **L0** | 平台契约层 | 把官方扩展点翻译成本项目自用的少数几个入口 | 官方 API |
| **L1** | 适配层 | 把"界面上的某处"解析成已校验的句柄，并负责重绑 | L0 |
| **L2** | 效果层 | 决定"动什么、何时动"，不关心动的是谁 | L1 |
| **L3** | 表达层 | 提供视觉素材与动效定义，不含逻辑 | 无（纯静态） |
| **L4** | 配置层 | 封闭集合的配置模型，以及它的人机界面 | L0、L2 |

**为什么配置层在最上面而不是最下面**：配置不是基础设施，而是**人机界面**。它读效果层的状态（哪些生效、哪些降级）并写配置。把它放底层会让效果层反向依赖它。

## 3. 各层的职责与禁区

### L0 · 平台契约层

**职责**：把官方那几个扩展点（slot 注册、locale、能力探测）包装成项目内唯一允许触碰的入口。
**它是整个项目里唯一允许直接调用官方 API 的地方。**

| 允许 | 禁止 |
| --- | --- |
| 调用官方 slot 注册与注入 | 在其它任何层直接调用官方 API |
| 声明 cordis 插件依赖 | 在其它任何层出现官方包名 |
| 读取运行环境能力（媒体查询、CSS 能力） | 在其它任何层做能力判断 |

**这一层的价值是"换供应商只改一处"**：如果 DSH 改了 slot 注册形态，只有这里要动。

### L1 · 适配层

**职责**：把语义目标解析成可用的句柄；管理生命周期；汇总命中情况。

| 允许 | 禁止 |
| --- | --- |
| 出现任何选择器字符串 | 被效果层绕过（效果层不得自己查 DOM） |
| 做几何自校验 | 把启发式结果当成精确结果 |
| 持有唯一的观察者 | 出现多个观察者 |
| 记录解析失败原因 | 静默失败不记录（诊断区需要它） |

**L1 是唯一允许知道"DSH 长什么样"的地方。** 它是本项目最易变的一层，因此也是最薄的一层。

### L2 · 效果层

**职责**：每个效果是一个独立单元，声明它需要哪些语义目标、动什么属性、何时启动、如何降级。

| 允许 | 禁止 |
| --- | --- |
| 声明对语义目标的依赖 | 出现选择器字符串（可审查的零命中） |
| 读写自身作用域的 CSS 变量 | 读写业务状态 |
| 独立失败、独立卸载 | 跨效果共享可变状态 |
| 声明所需能力 | 自行探测能力 |

**可审查的物理约束**：效果层目录内检索选择器特征串，必须零命中。这条把"效果层永远不需要改"从愿望变成事实。

### L3 · 表达层

**职责**：动效定义（关键帧）、品牌资产、本项目自己的 CSS 变量。

**它不含任何逻辑**——没有条件、没有 DOM、没有配置读取。同一份素材在设置页预览与真实界面里完全一致，**预览不可能与实况漂移**，因为它们是同一份东西。

### L4 · 配置层

**职责**：凭封闭集合定义的配置模型，以及它的视图（设置页）与诊断。

| 允许 | 禁止 |
| --- | --- |
| 读效果层的健康状态 | 让配置影响层结构 |
| 提供封闭集合的取值 | 接受任意用户输入 |

## 4. 层间契约（宏观）

契约只约定**信息形态与方向**，不约定实现。

| 调用方 | 被调方 | 契约内容 |
| --- | --- | --- |
| L2 效果层 | L1 适配层 | "我要「输入框卡片」这个东西" → 得到一个**已校验的句柄或空**。效果层不知道它来自哪条策略、也不知道它是不是伪元素 |
| L2 效果层 | L1 适配层 | "这个目标重建时通知我" → 得到一个可释放的订阅 |
| L4 配置层 | L2 效果层 | "你现在是什么状态" → 得到生效/降级/关闭，以及降级原因 |
| L2 效果层 | L3 表达层 | 只读取素材，不做修改 |
| 任意层 | L0 | 只有 L0 对外暴露入口 |

**一条硬规则**：**空句柄是合法返回值，不是异常。** 解析失败不得抛错——它只意味着该效果降级。异常只用于编程错误。

## 5. 适配层的三个抽象

这一层是全文的重点，因为它决定了"DSH 变了我们要改多少"。

### 5.1 语义目标

效果层说的是**意图**，不是元素。例如："输入框的那张卡片""输入框里的光标""流式输出的作用域"
"侧栏的品牌图标""侧栏的会话行"。

语义目标是**封闭枚举**，不随 DSH 版本增加——新版本只增加解析策略，不增加语义。

这是整个适配设计的支点：**语义稳定，实现可变。**

### 5.2 策略链

一个语义目标对应一条**有序策略链**，按"最精确 → 最保守"排列，先命中者胜：

| 顺序 | 策略类型 | 判据 | 失败后的行为 |
| --- | --- | --- | --- |
| 1 | 规范策略 | 使用当前已知的官方标识 | 交给下一条 |
| 2 | 遗留策略 | 使用历史版本曾用过的标识 | 交给下一条 |
| 3 | 结构策略 | 用相邻关系与内容特征推断 | 交给下一条 |
| — | 放弃 | 全部未命中 | 返回空，效果降级 |

**两条不可妥协的规则**：

- **启发式必须自校验。** 结构策略返回的元素必须通过几何与内容校验（可见、有尺寸、包含应有的子结构）。绑到错误节点比找不到更糟——后者是降级，前者是界面错乱。
- **策略数量设上限。** 每个语义目标最多三条。超过三条说明我们在猜，猜得越多越脆弱。

解析过程如下。注意终点有两条出口：**得到句柄**，或**得到空**——空不是异常，是降级。

```
效果层问：「输入框卡片在哪？」

        策略 1 · 规范标识（精确）
              │
      ┌───────┴───────┐
    命中            未命中
      │                │
   几何自校验           ▼
      │          策略 2 · 遗留标识（精确）
   ┌──┴──┐             │
  通过  不通过    ┌─────┴─────┐
   │      │     命中        未命中
   │      └──┐   │            │
   │         │   ▼            ▼
   │         │ 几何自校验   策略 3 · 结构推断（启发）
   │         │   │            │
   │         └───┴──── 未通过 ─┤
   │                          ▼
   ▼                     返回空
 返回句柄                    │
   │                        ▼
   │                  该效果降级
   │                  （不抛错、不占位）
   └──────────► 效果层只看到这两种结果
```

### 5.3 判别式句柄

同一语义在不同版本可能有不同承载方式。适配层对外只暴露**一个句柄概念**，内部把差异吃掉：

句柄有两种形态——**真实元素**，或**寄生在宿主元素上的伪元素**（含伪元素位置与内容特征）。

效果层拿到句柄后按形态分支，而**不需要知道判断逻辑**。这条把"光标可能是伪元素"这个已知风险，从效果层的一次性判断，变成适配层的一个稳定契约。

### 5.4 能力探测与 DOM 解析分离

运行环境能力（属性插值支持、遮罩合成支持、减少动态偏好）与"界面元素在哪"是两件独立的事，**分开探测、分开缓存**。

理由：DOM 会随界面变，能力只随浏览器变。混在一起会让"界面没变但浏览器变了"也触发重新解析。

## 6. 失效半径

分层的实际收益在这里：**一个语义目标失配，只影响依赖它的效果**。

| 失配的语义目标 | 受影响效果 | 不受影响 |
| --- | --- | --- |
| 输入框卡片 | 边框流光、按压 | 品牌、光标、首屏 |
| 输入框正文 | — | 全部 |
| 光标 | 光标 | 品牌、边框流光、按压、首屏 |
| 流式作用域 | 发送闪光、光标加速 | 品牌、边框流光、按压、首屏 |
| 侧栏会话行 | 会话进行中指示 | 品牌、边框流光、光标、按压、首屏 |
| 品牌相关 | 品牌 | 其余全部 |

**这张表同时是设置页诊断区的数据来源**：命中矩阵由适配层产出，效果层不自行上报，避免两处真相。

## 7. 生命周期与观察者

- **全项目只有一个观察者**，位于 L1。
- 观察范围必须收窄：只观察与已注册语义目标相关的属性变化，且防抖。
- 观察者必须在插件卸载时释放；效果层无权创建观察者。
- **能走 L0 就绝不走观察者**：slot 型目标（品牌、首屏）天生有声明与撤销语义，不需要 DOM 观察。

优先级顺序（越靠上越稳）：

1. 官方 slot（有声明周期，最稳）
2. 语义钩子 + 属性选择器
3. 语义钩子 + 结构关系（`:has` 一类，无后代链）
4. 结构推断（最后手段）

**禁止**：后代组合链（越深越脆）、哈希类名、本地化文案、层级索引。

## 8. 依赖方向与禁止清单（可审查）

| 约束 | 审查方式 |
| --- | --- |
| 选择器只出现在适配层 | 在效果层目录检索选择器特征，必须零命中 |
| 官方包名只出现在平台层 | 全库检索官方包名，只允许平台层命中 |
| 只有一个观察者 | 全库检索观察者构造，只允许一处 |
| 表达层无逻辑 | 审查表达层是否出现条件分支与外部读取 |
| 配置层不接受任意输入 | 审查配置来源是否为封闭枚举 |
| 主题只消费不提供 | 检索主题注册与令牌覆盖接口，必须零命中 |

这六条与产品需求里的代码级约束一一对应——**架构是产品边界的实现手段，不是另起一套规矩。**

## 9. 架构承诺

> **DSH 升级导致某个语义标识改名时，改动面 = 适配层一个文件 + 一条策略。
> 效果层、表达层、配置层、设置页全部不动。**

这条不是修辞，是**可测试的属性**：构造一份"改名后"的界面，断言仍能通过遗留或结构策略解析成功。
一个能被测试证伪的承诺，才有资格写进架构。

## 10. 反过度设计

适配层最容易长成一个通用框架。四条护栏：

1. **语义目标是封闭枚举**，不开放运行时注册
2. **每目标策略上限三条**，超限即报警而非继续加
3. **不做版本号门控**——用"标识是否存在"当版本信号，比读版本号可靠，也不会因为版本号读取失败而整体失效
4. **不做运行时选择器配置**——那就是开放集合，直接违反产品需求第 2 条

## 11. 与产品需求的对应

| 产品边界 | 在架构里的落点 |
| --- | --- |
| 只改时间维度 | 效果层只写时间相关的表现；表达层只放关键帧与素材 |
| 封闭集合 | 配置层不接受任意输入；语义目标是枚举 |
| 关掉即回官方 | 表达层的素材与变量全部作用域化，卸载即摘除 |
| 不改布局 | 效果层禁止写布局属性（由审查保证） |
| 不承载信息 | 所有效果在空句柄时降级，不影响语义 |
| 主题只消费 | 平台层不暴露主题注册能力 |

## 12. 演进

| 方向 | 触发条件 | 处理 |
| --- | --- | --- |
| 增加语义目标 | 新效果需要新的界面锚点 | 只加适配层策略，不加层 |
| 官方提供更稳的扩展点 | 例如设置卡片通道可用 | 收缩 L1：相关目标改为走官方通道 |
| 客户端大版本重构 | 标识体系整体变化 | 加"遗留策略"，旧效果零改动 |
| 多客户端形态（桌面/移动） | 出现结构差异 | 在 L1 内做形态分支，不扩散到 L2 |

**不做的演进**：不拆多包、不引入运行时插件系统、不把适配层做成对外 API。
