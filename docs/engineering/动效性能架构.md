# 动效性能架构

日期：2026-10-26。状态：首版已实现，已完成受控页面验证；原生客户端最终观感与占用待重启确认。

本文规定 Lumina 后续效果的调度、资源生命周期、性能档位和性能验收。目标是在保留流光质感的同时，让后台装饰为输入、滚动和面板操作让出资源。性能设置不能代替实现优化，也不能改变宿主业务行为。

## 1. 当前实现与改造边界

星河已经使用一个循环绘制多行，并支持视口判断、页面隐藏暂停和面板动画期间限速；仍在每行每帧读取颜色、生成渐变和计算曲线路径。新会话光带使用 WebGPU，最高 240 万像素、4 倍多重采样，按独立循环持续绘制。发送流光在短暂转场内逐帧改写 SVG 路径。这三种开销需要分别度量，不能把一种优化的收益套到全部效果上。

本方案保留 Canvas、WebGPU、SVG 和 CSS 各自适合的用途，不统一更换绘制技术。不改宿主布局、请求或会话状态，不引入第三方运行时。共享调度、窗口暂停、综合档位及设置页已接入；后续自动降级与进一步绘制算法优化仍按本文边界推进。

## 2. 职责与依赖

| 层 | 职责 | 不负责什么 |
| --- | --- | --- |
| 配置与设置 | 保存用户选择的性能档位，解析多参数预算并校验和迁移配置 | 不直接启动绘制，不根据一次卡顿改写用户配置 |
| 运行条件 | 汇总页面可见、窗口焦点、目标可见、减少动态及面板繁忙状态 | 不读取会话正文，不猜测机器型号或性能等级 |
| 帧调度 | 维护插件脚本动效的单一 rAF 入口，按任务状态与期限派发 | 不统一重写 CSS 动画，不执行宿主业务任务 |
| 效果实例 | 更新自身时间、几何和材质，声明是否还需要下一帧 | 不自行创建常驻循环，不持久化性能偏好 |
| 资源管理 | 按效果缓存绘制资源，处理尺寸变化、卸载和设备丢失 | 不逐帧重建纹理、管线或静态素材 |

`src/client/core/frame-scheduler.ts` 管理帧调度与运行条件，`performance.ts` 保存档位预算，`render-activity.ts` 提供面板繁忙信号。星河、新会话光带、入场粒子和发送转场已通过注册与注销接入。输入批处理和短暂布局检测仍是事件驱动的一次性回调，不纳入绘制限帧。调度器不成为某个效果的内部工具，以免新效果继续各自维护循环。现有 `panel-budget.ts` 的面板繁忙信号接入该机制，避免维护两套优先级。

CSS 合成动画继续由浏览器调度。插件统一传递暂停条件，但不为了统一帧率把 CSS 动画改成逐帧 JS。

## 3. 综合性能档位与设置说明

设置页增加“性能”圆角分区，提供“呈现偏好”：**性能优先 / 均衡 / 画质优先 / 极致画质**，默认“均衡”。四档采用单行分段按钮组，不折行，不另设下拉选择；优先去掉独立说明图标以减少占用，极窄窗口允许按钮组横向滚动。用“性能优先”代替“高性能”，明确它是在减少绘制开销，而非承诺同时得到最高帧率与最好画质。

| 档位 | 目标 | 参数调整方向 |
| --- | --- | --- |
| 性能优先 | 尽量减少持续资源占用 | 较低背景更新频率、像素预算和粒子密度；保留主要光带与必要抗锯齿 |
| 均衡 | 日常使用的默认表现 | 适中的持续绘制预算，兼顾交互流畅、细线和局部光效 |
| 画质优先 | 更完整的材质与细节 | 提高像素预算、粒子密度、曲线细分与光效精度；帧率按收益决定，不要求每档递增 |
| 极致画质 | 在明确资源上限内提供最完整表现 | 允许最高一档绘制清晰度、材质精度与更新频率，资源消耗最高 |

档位是多个参数的组合，不是帧率别名。首轮参数表需要覆盖：背景帧率上限、短暂交互帧率上限、各效果 DPR 与像素总量上限、星河粒子密度、光带网格细分、抗锯齿采样及局部光效精度。只收录实际影响对应渲染器的参数；未接入的参数不出现在界面说明中。首版参数见下表。当前值已进入运行时并完成受控验证，仍需在原生客户端继续确认画质与资源取舍；它们不是适用于所有设备的最优值。原先直接选择 30 / 60 / 90 / 120 fps 的方案由本节替代，不再作为一级设置。

| 参数 | 性能优先 | 均衡 | 画质优先 | 极致画质 |
| --- | --- | --- | --- | --- |
| 背景 / 交互上限（fps） | 30 / 60 | 40 / 60 | 60 / 90 | 90 / 120 |
| 星河 DPR / 粒子 / 光丝 | 1 / 28 / 6 | 1.25 / 44 / 10 | 1.5 / 56 / 12 | 2 / 72 / 14 |
| 光带 DPR / 像素上限（MP） | 1 / 1.0 | 1.5 / 1.6 | 2 / 2.4 | 2 / 3.2 |
| 光带采样 / 网格 | 1× / 128×16 | 4× / 192×16 | 4× / 256×16 | 4× / 320×16 |
| 入场粒子上限 / DPR | 1000 / 1 | 1600 / 1.5 | 2400 / 1.5 | 3000 / 2 |

以上数值以 `RENDER_BUDGETS` 为执行来源，界面提示直接读取该表。各效果不超过设备实际 DPR；背景最高同时绘制 8 行，已有雾光和材质资产复用，不随帧创建。

### 档位说明

不放置独立的说明或感叹号图标。鼠标悬停、键盘聚焦档位按钮时直接显示该档配置提示，点击按钮选择档位并显示提示，以支持触控使用；支持 Escape 关闭。提示内容保持可读，移入提示区域时不立即消失；较长内容使用可点击的说明浮层，不能只依赖原生 title。

每档说明依次包含：一句取舍、按效果分组的具体参数与单位、资源开销提示。例如先列背景与交互的帧率上限，再列星河的粒子密度与像素上限，以及新会话光带的清晰度、采样和网格精度。此处只定义信息结构，实际数值由集中参数表生成，不手写第二套“60 fps”等文案常量。尚未实现的档位不显示可操作的空控件。

说明展示档位预算，不把预算写成实测帧率。浏览器、设备和显示器可能使实际帧率低于上限；CSS 原生合成动画不受脚本帧率上限控制。当前因面板繁忙等原因暂时降低绘制频率时，在“排查与恢复”区展示实际应用限制，不静默修改档位说明或用户选择。

### 配置与兼容

配置 `performance.profile`，取值为 `performance / balanced / quality / ultra`。缺失或非法值回退 `balanced`，只回退该字段，不重置已有品牌、强度及效果开关。`performance.frameRate` 尚未随正式版本发布，不为本次设计草案添加迁移分支；若实施前发现已有实际发布配置，再按发布事实补迁移。

配置解析生成只读的逐效果预算，调度器与渲染器消费同一份解析结果。新增效果必须明确如何响应四档，并登记参数说明；没有差异的参数可以四档相同，不为凑档位削弱质量。后续增加参数时保持档位标识稳定，必要时记录预算调整的用户可见影响。

沿用草稿、取消、保存及保存后热生效流程；恢复默认回到“均衡”。运行中切档先清理受影响的短暂转场，再更新预算；像素尺寸、采样或纹理需重建时只在切档与尺寸失效时执行。不得每帧重建资源。强度控制视觉表达，性能档位控制绘制成本；两者互不覆盖，降低档位不改变动画时长、路径端点和宿主信息。

首期不增加独立的粒子数、DPR 等高级旋钮，也不根据机器型号猜测性能。自动降级若后续加入，需单独设计开关和恢复策略；运行时限制不得写回用户档位。所有档位都必须遵守隐藏、失焦暂停和系统减少动态，极致画质也不豁免。

## 4. 调度与启停契约

每个任务注册类型（背景持续或短暂交互）、可见状态和更新回调。调度器只在存在可运行任务时申请下一帧；没有任务时不得保留空转 rAF。每个任务保留自己的上次更新时间和下一次期限，不能让 30 fps 任务被 120 fps 任务带着重绘。合并入口本身不作为性能收益证明。

分帧处理遵守“先读、再算、后写”：合并必要的布局读取，再更新绘制与样式。颜色和主题相关值在首次挂载、已验证的主题变化或显式失效时刷新；不得把 `getComputedStyle` 或布局测量放进持续绘制回调。尺寸由 ResizeObserver 等事件失效，不逐帧轮询。缓存方案必须覆盖宿主主题变化，不能以缓存为由冻结深浅色。

| 条件 | 持续背景效果 | 发送、入场等短暂效果 |
| --- | --- | --- |
| 窗口失焦或页面隐藏 | 立即停止绘制；恢复时重新判断目标 | 取消装饰并恢复宿主内容，不等待窗口回来再播放旧转场 |
| 面板收起或目标离开视口 | 目标无可见绘制区域时暂停 | 目标失效则取消；不得留下被隐藏的真实文字 |
| 系统减少动态 | 停止装饰运动，保留必要静态状态 | 立即完成清理，直接显示真实内容 |
| 总开关关闭或效果卸载 | 注销任务并释放资源 | 取消并恢复所有归插件所有的临时属性 |
| 面板正在开合 | 背景暂按不超过 30 fps 更新 | 优先保证直接交互；繁忙期结束后恢复当前档位上限 |

失焦与重新聚焦使用窗口事件；`document.hidden` 不能代替窗口焦点。目标可见性不能只看元素是否仍在 DOM 中，应结合视口与实际面板状态。恢复时重置帧时间基点，背景相位续播，避免补算失焦期间的每一帧或突然跳动。

单个任务异常应被隔离并清理，不能中断其他任务。效果结束、目标消失、减少动态和卸载必须走同一套幂等清理。任务状态收敛为运行、暂停、结束；暂停不销毁可复用素材，结束必须释放引用。窗口短暂切换不重新申请 WebGPU 设备和编译管线。

## 5. 绘制预算与缓存

| 效果 | 优先优化 | 保真要求 |
| --- | --- | --- |
| 星河 | 缓存颜色；帧内共享曲线与噪声参数；缓存静态渐变；复用已有雾光、星点素材 | 保留曲线变化、随机性、出现消失过程；不能直接替换成固定扫光 |
| 新会话光带 | 收紧实际绘制区域；减少透明区域计算；按尺寸复用纹理与多重采样资源；逐项比较网格、采样和像素预算 | 先保留细线、柔顺曲面及局部高光；不得同时降分辨率与采样后归因不明 |
| 发送流光 | 减少路径字符串生成和重复属性写入，评估材质或整体变换替代部分路径形变 | 保留真实起点、消息边缘落点及完整文字交接 |

静态素材、管线及采样资源不进入逐帧创建路径。动态渐变只有在确实变化时更新；不能以缓存之名冻结已经确认的流动效果。大尺寸纹理和画布需有集中定义的像素、数量上限，不允许每个新效果自行提高预算；当前数值先作为现状，调整须附对比证据。

首期不设未经测量的“CPU 必须低于 1%”等绝对承诺。先建立固定场景基线，再制定可重复的回归阈值；阈值与机器、视口、DPR、浏览器版本一同记录。

## 6. 验收与持续约束

性能验证至少拆为插件关闭、仅星河（1/3/8 行）、仅新会话光带、单次发送、面板开合与背景同时运行。固定窗口、DPR、性能档位、预热与采样时长，报告多次采样结果；受控页面结果与真实客户端结果分开。比较同一场景的改前改后，不能用宿主总 CPU 直接宣称插件开销。

主线程记录脚本时间、样式重算、布局、长任务及实际绘制次数；GPU 侧另查栅格、合成、绘制面积与提交频率。rAF 间隔只代表回调时机，不等于画面已呈现帧率。JS 计时较低不能作为 GPU 无开销的证明。

必须验证：隐藏与失焦后没有持续绘制提交；恢复不跳帧补算；零任务时没有调度循环；所选上限有效；不同档位下总时长与落点一致；卸载、取消和设备丢失后没有残留遮罩或资源引用。视觉同时覆盖深浅色、不同缩放和两次以上动态采样。

长期测量脚本进入 `tools/`，原始 trace、截图和临时报告进入 Git 忽略的 `.local/diagnostics/<日期-主题>/`。正式文档只保留确定的规则和结论。新增效果提交必须说明触发类型、停止条件、资源上限、配置覆盖和测量证据；缺少接入预算的常驻循环不得合入。

## 7. 实施进度与后续顺序

1. 已接入档位预算、共享调度与失焦暂停，星河移除逐帧样式读取，缓存静态渐变并共享帧内曲线参数；设置页包含综合档位、参数说明和当前绘制状态。
2. 已完成配置兼容、草稿保存、宽窄布局、帧率上限、暂停恢复、资源复用及流光转场回归。受控对比脚本为 `tools/perf-motion.mjs`，设置与 WebGPU 检查为 `tools/verify-performance.mjs`；具体测量值留在本地诊断目录，不能代替真实客户端指标。
3. 后续单独优化 WebGPU 的透明绘制面积与发送 SVG 路径重建，逐项核对视觉与性能；不把这些尚未实施的优化列为已完成功能。
4. 原生客户端基线稳定后加入可重复的发布回归阈值，再决定是否需要自动降级。

新增效果按本文调度与资源要求接入；已发布能力与后续计划在更新记录中分开。
