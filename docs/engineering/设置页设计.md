## 1. 为什么是 `settings.section`，而不是官方菜谱里的 `settings.plugin.item`

官方 `docs/cookbook/adding-a-settings-card.md` 描述的第三方插件配置通道是**双半**路径：

```
Host 半：installSettingsSection(ctx, NS, Config, config, {…})   ← @deepseek-ai/dsh-settings
Client 半：ctx.slots.register({ name: 'settings.plugin.item', key: NS, … }, Card)
写入通道：ctx.settingsScope.bind({ namespace: NS }).set(field, value)
```

**这条路在已安装的客户端 0.2.1-rc.2 上不可用。** 实测（从 `app.asar` 中解出实际安装的包并 grep）：

| 符号 | 安装的包 | 命中 |
| --- | --- | --- |
| `installSettingsSection` / `settingsNamespace` | `@deepseek-ai/dsh-settings@0.2.1-rc.2` | **0** |
| `settingsScope` | `@deepseek-ai/dsh-client-ui-settings@0.2.1-rc.2` | **0** |
| `settings.plugin.item` | `@deepseek-ai/dsh-client-ui-settings-plugins@0.2.1-rc.2` | **0** |
| `settings.plugins.tab` | 同上 | 7 |
| `settings.section` | 同上 | 5 |

这些 API 只存在于**源码 checkout 的更晚版本**（post-0.2.1-rc.2 的 master），尚未进入已发布 npm 包，
因此也不在用户实际运行的客户端里。

**结论**：本客户端上唯一可用、且有生产验证的插件配置通道是 `settings.section`——
正是已安装的 `dsh-brand-studio` 用的那条（其产物中可见
`{ name: "settings.section", id: "dsh-brand-studio", order: 1e3, label: () => ctx.locale.bind(NS)("nav"), locale: NS }`）。

### 迁移路径（客户端升级后）

设置模型**刻意保持扁平**（9 个标量字段，无嵌套对象），因此迁移到 `settings.plugin.item`
只是一次注册方式的改动，不需要动数据模型：

1. Host 半加 `installSettingsSection` + Schemastery schema，命名空间 `lumina`；
2. Client 半把 `settings.section` 换成 `settings.plugin.item`（`key: 'lumina'`）；
3. 写入从 `store.commit()` 换成 `scope.set(field, value)`。

**触发条件**：客户端版本 ≥ 提供 `settings.plugin.item` 与 `settingsScope` 的版本。
升级后用 `grep -c "settings.plugin.item" app.asar` 可判定。

## 3. 关键设计决定

| # | 决定 | 理由 |
| --- | --- | --- |
| 1 | **独立设置页**（`settings.section`）而非插件卡片 | 卡片通道在当前客户端不存在（§1）；独立页是唯一可用路径 |
| 2 | **草稿式表单**：编辑进草稿，保存才落盘 | 用户拖动滑块/切换开关时不应逐次写盘；取消应能无损回退 |
| 3 | **保存为一次整体写入** | 9 个标量字段一次性提交，避免半存状态 |
| 4 | **冲突提示**：外部改动后显示「已更新」 | 另一个标签页改了同一份设置时，不静默覆盖 |
| 5 | **总开关关闭时逐效果开关置灰** | 保留用户的选择，只是暂时不生效；重新打开即恢复 |
| 6 | **「恢复默认」只改草稿** | 误点不该立刻清空配置；仍需点保存 |
| 7 | **样式只用 `--dsw-*` 语义 token** | 深浅色自动跟随，不用 `prefers-color-scheme`（风险 R14 的正解） |
| 8 | **预览复用同一套 keyframes** | 预览与实况共用 `core/keyframes.ts`，不可能漂移 |
| 9 | **面板样式独立于效果开关安装** | 总开关关掉时设置页仍要能用 |
| 10 | **文案走 `ctx.locale` 命名空间 `settings.lumina`** | 跟随客户端语言；`label` 用 thunk，壳不需要订阅 locale 状态 |

## 4. 数据模型

```jsonc
// localStorage["ratel-lumina/settings/v1"]（旧 key dsh-lumina/settings/v1 仍兼容读取）
{
  "version": 1,
  "master": true,
  "brand": "deepseek",       // deepseek | ratel
  "intensity": "normal",     // subtle | normal | vivid
  "effects": {
    "brand": true,
    "composerGlow": true,
    "caret": true,
    "press": true,
    "hero": true,
    "sessionActivity": true  // M8；旧 payload 由 parseConfig 补默认值
  }
}
```

**扁平、可迁移**：将来迁到 `settings.plugin.item` 时，每个字段直接对应一次 `scope.set(field, value)`。

**校验原则**：非法值一律回落到默认，不抛错、不半应用（`core/config.ts` 的 `parseConfig`）。

## 5. 响应式重装

设置页改的是**已提交的快照**；效果读的是同一份快照。链路：

```
面板保存 → store.commit() → 通知订阅者 → render() 卸载旧效果 → 按新配置重装
```

- `store.subscribe` 通知同标签页；
- `storage` 事件通知其它标签页（`core/config.ts` 的 `createConfigStore`）；
- 重装是**先拆后装**，不会留下旧样式的残留。

## 6. 注册契约

```js
ctx.slots.register({
  name: 'settings.section',
  id: 'ratel-lumina',            // 必填：页面身份
  order: 1200,                   // 排在官方页面之后
  label: () => ctx.locale.bind('settings.lumina')('nav'),  // 本地化 thunk
  locale: 'settings.lumina',     // 命名空间
  inject: () => ({
    hooks: { settings: store },              // 渲染器绑定出 useSettings
    save: (config) => store.commit(config),
  }),
}, LuminaPanel)
```

`list` slot 必须给 `id`；`id` 相同且 priority 相同会抛异常（本 slot 不设 priority，默认 0，
但 `id` 唯一所以不冲突）。

## 8. 后续（MVP 收尾）

- 面板的「实时预览」目前是**静态模拟**（迷你输入框 + 品牌条），不是真实组件；
  真正接入真实 composer 需要跨组件注入，不在 MVP 范围。
- 「品牌预设」只有两个固定项；Ratel 资产就绪后只替换包内资产，**不开放上传**
  （产品需求 C4：品牌图形只来自包内 `assets/`）。
- 面板未做键盘导航与屏幕阅读器标注的专项走查（在 MVP 验收统一做）。
