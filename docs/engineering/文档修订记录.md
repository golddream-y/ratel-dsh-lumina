## R-01 · 同优先级的结果：抛异常，不是「后注册者胜」

| | |
| --- | --- |
| 原文 | `docs/design/02` §2.1：「**同优先级 = 后注册者胜**（实测：同样 `-10` 时后注册的插件顶掉了先注册的）」 |
| 事实 | `packages/client/ui-slots/src/index.ts:801-802`：`single` slot 若已有**同 priority** 的占用者 → `throw`；`keyed`/`list` 同理（同 key / 同 id + 同 priority） |
| 处置 | **改**。设计文档的结论（priority 最小者胜、`-20` 压过 `-10`）**仍然正确**，错的只是「同优先级后注册者胜」这一句。观察到的「后注册顶掉先注册」很可能发生在**动态插件路径**（那里 facade 会分配唯一优先级），不是 bundle 路径 |

> 影响面：若两个插件用了同一 priority，**不是谁赢，而是抛异常** → 该 slot 回落官方外观。

## R-02 · 官方 slot 目录的「不要传 priority」只对动态插件成立

| | |
| --- | --- |
| 原文 | `docs/design/02` §2.1 只描述了「priority 最小者胜」，未区分两条注册路径 |
| 事实 | 官方 `slot-catalog.ts` `CLIENT_NOTES[2]`：「Do NOT pass `priority`: the browser-half facade assigns one automatically」。但那是 `cordis-client-runner/src/client/guard.ts:119-126` 的**动态插件代理**行为，会**覆盖**传入值 |
| 处置 | **补**。Bundle 路径（我们）走真实 `SlotRegistry`，`priority` 按传入值生效。**`-20` 必须保留**；误删会与 `dsh-brand-studio` 同为 `0` → 抛异常 → 品牌区回落 |

## R-03 · 04d 的侧栏按压规则违反本项目自己的「禁 hash 类名」

| | |
| --- | --- |
| 原文 | `docs/design/04d` §1.2：`[data-lumina="on"] [class*="sidebar"] button:not([disabled]):active` |
| 事实 | `docs/design/02` §2.3 明令禁止用类名定位（`[class*="…"]` 同样属此类）；CSS Module 类名形如 `_3WPZCG_sidebarRoot`，**会误命中** |
| 处置 | **建议删**。该条被原文自标为「弱选择器·尽力而为」，收益低而违规风险实。保留 `[data-composer-card] button` 一条即可 |

## R-04 · 样式注入：bundle 路径自建 `<style>`，不是 `styles.insert`

| | |
| --- | --- |
| 原文 | `docs/design/02` §2.4 规定手动 `document.createElement("style")` + `dataset.plugin` |
| 事实 | 官方 `styles.insert(css)` 由 `DynamicCordisStyles` 提供（`cordis-client-runner/src/client/evaluator.ts:78-112`），**只存在于动态插件的求值闭包**；`app.asar` 中确有 `styles.insert` 与 `data-dyn`，但那是动态路径。生产插件 `dsh-brand-studio` 同样自建标签 |
| 处置 | **保持原文**，补一句「`styles.insert` 属动态插件座位，bundle 路径自建标签」以免后人误用 |

## R-05 · `dsh.client.inject` 的语义

| | |
| --- | --- |
| 原文 | `docs/design/02` §2.8④：「`inject` 只能列真实存在的包名」，示例取自官方品牌包 |
| 事实 | `inject` 是**信息性**的包名依赖边（预检展示 / HMR diff），**不决定激活顺序**；决定顺序的是 cordis fiber 等待**服务**。真正约束「哪些 specifier 保持 external」的是 `dsh.client.external`（`packages/client/tsdown.client.ts:401-425`） |
| 处置 | **补**。`external` 概念此前完全缺失，导致「客户端构建预设」被低估。已写进 `docs/engineering/官方API面.md` §2 |

## R-06 · 设置面板的注册契约缺 `locale` 与本地化 `label`

| | |
| --- | --- |
| 原文 | `docs/design/03` §3.10：「占据 `settings.section`（list slot），`id: "dsh-lumina"`，`order` 取较大值排在后面」 |
| 事实 | 官方 slot 目录 `settings.section` 要求 `id`（必填）+ `order` + `label`（**注册方本地化文本，可用 thunk**）+ `locale`（命名空间）。生产实现：`ctx.locale.register('dsh.brand-studio', {en, zh})` + `label: () => ctx.locale.bind(NS)('nav')` + `locale: NS` |
| 处置 | **补**。面板实现时必须注册 locale 命名空间（建议 `dsh.lumina`），否则 `label` 无从取值 |
