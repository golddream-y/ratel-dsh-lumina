## R-01 · 同优先级的结果：抛异常，不是「后注册者胜」

| | |
| --- | --- |
| 原文 | `docs/原始材料/02` §2.1：「**同优先级 = 后注册者胜**（实测：同样 `-10` 时后注册的插件顶掉了先注册的）」 |
| 事实 | `packages/client/ui-slots/src/index.ts:801-802`：`single` slot 若已有**同 priority** 的占用者 → `throw`；`keyed`/`list` 同理（同 key / 同 id + 同 priority） |
| 处置 | **改**。设计文档的结论（priority 最小者胜、`-20` 压过 `-10`）**仍然正确**，错的只是「同优先级后注册者胜」这一句。观察到的「后注册顶掉先注册」很可能发生在**动态插件路径**（那里 facade 会分配唯一优先级），不是 bundle 路径 |

> 影响面：若两个插件用了同一 priority，**不是谁赢，而是抛异常** → 该 slot 回落官方外观。

## R-13 · patch 行的 `id`、包名、插件 `name` 导出是三个独立值

| | |
| --- | --- |
| 原文 | 原 `01` §5.3 与 `03` §3.6（**均已删除**）：「`id` 必须与 `lib/index.js` 的 `name` 导出完全一致」；`02` §2.8② 同样表述 |
| 事实 | 官方 `docs/user/develop/basic/publish.md:58-62` 的最小插件：patch 行 `id: hello`、`name: dsh-hello-plugin`，而 `index.js` 导出 `name = 'hello-plugin'`——**三个值互不相同**。`id` 是 loader 的 **entry key**（供后续层按 `id` 覆盖用），`name` 是**包名**（供 Node 解析已安装代码），插件自身的 `name` 导出是 **cordis 插件身份**（须在 context 内唯一） |

## R-15 · 设置页落点：官方第三方路径在当前客户端不可用

| | |
| --- | --- |
| 原文 | 原 `03` §3.10（**已删除**）：「占据 `settings.section`（list slot）」 |
| 事实 | 官方菜谱（`docs/cookbook/adding-a-settings-card.md`）的第三方路径是 **Host 半 `installSettingsSection` + Client 半 keyed 卡片进 `settings.plugin.item`**。但**已安装的客户端 0.2.1-rc.2 完全没有这套符号**：从 `app.asar` 解出的 `@deepseek-ai/dsh-settings@0.2.1-rc.2`、`dsh-client-ui-settings@0.2.1-rc.2`、`dsh-client-ui-settings-plugins@0.2.1-rc.2` 以及 npm 上的同名发布包中，`installSettingsSection` / `settingsNamespace` / `settingsScope` / `settings.plugin.item` 命中数**均为 0**（`settings.plugins.tab` 为 7） |
| 处置 | **保留 `settings.section`，并记录迁移路径**。理由：走官方路线时 `ctx.slots.inject('settings.plugin.item', …)` 会等待一个**永不出现的声明**——卡片静默不渲染，正是风险 R9 那一类失败。`settings.section` 是当前客户端唯一可用、且有生产验证（`dsh-brand-studio`）的通道。设置模型已刻意保持**扁平 8 字段**，将来迁移只需改注册方式 |

详见 [设置页设计](设置页设计.md) §1。

## R-16 · 样式路线：官方规则面向仓库内功能包，第三方插件有固有偏离

| | |
| --- | --- |
| 原文 | `docs/原始材料/02` §2.4（自建 `<style>` 全局注入）、`03` §3.9 / `04` §4.5（在 `:root` 定义 `--lumina-*`） |
| 事实 | 官方 `docs/web-styling.md` 要求：全局样式表归 `ui-theme/src/styles/`、功能包用 CSS Modules + `clsx`、**不要另建一套全局主题**、**功能包 CSS 里不放主题选择器** |
| 处置 | **明确偏离，附理由与补偿**。这三条规则的对象是**仓库内的功能包**：它们能改 `ui-theme` 的全局表、能用构建期 CSS Modules。第三方插件两者都做不到——① 不在仓库内，无法向官方全局表加样式；② 本项目的效果**要样式的是别人拥有的 DOM**（`[data-composer-card]`、`[data-lexical-cursor]`），CSS Modules 只能作用于自己渲染的元素，对第三方 DOM 无效。因此「作用域化的属性选择器 + 自建 `<style>`」是唯一可行机制 |

补偿措施（已落地）：

| 官方关切 | 本项目的补偿 |
| --- | --- |
| 不要另建全局主题 | 品牌色**只**以 `--lumina-*` 变量发布，且**只消费** `--dsw-alias-*` 语义 token；面板样式无字面量颜色 |
| 功能包 CSS 不放主题选择器 | 全部样式**不含** `prefers-color-scheme` / `[data-ds-dark-theme]`；深浅色由 `--dsw-*` 自动跟随 |
| 全局样式表归官方所有 | 注入的 `<style>` 带 `data-plugin="dsh-lumina" data-effect="<id>"`，卸载即摘除；每个效果独立标签，互不影响 |
| 用 CSS Modules | 我们**不**使用 hash 类名（那正是 02 §2.3 禁止的），自有类名一律 `lumina-` 前缀 |

> 唯一保留的媒体查询是 `prefers-reduced-motion`——那是**动效**查询而非主题选择器，且是无障碍底线，不在官方规则的射程内。
